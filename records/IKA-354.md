# IKA-354 深化の途中で候補集合を広げる —— 木を残したまま根に行と列を足す口（`deepen.Grow`）。検討モードは幅を広げても読み直さない。打ち手は「狭く読んでから広げる」を既定 off の設定で足した（対戦評価は IKA-333 の道具を待つ）

2026-09-27。担当 IKA-354（worker）。ブランチ `ika-354-widen-midway`（master 2a16ac7 から。途中で 58d385b（IKA-342）と 3d9e499（IKA-350・IKA-344）を取り込んだ）。

## 0. 課題（Notion IKA-354、High）

* 検討モード（IKA-349）の歯車で幅を変えると、読みを止めて最初から読み直していた。深化で掘った子のゲームは捨てられる。
* 根の最善応答オラクル（`sall`、IKA-293・IKA-307）は候補集合の外の手を足すが、幅そのものを後から広げる口は無かった。
* 形: (1) 深化の木を残したまま、根（と裏の決定化ごとの行列）に行と列を足し、足した分の行列の評価をして均衡を解き直す。(2) 検討モードは幅の変更を止めずに「広げる」として扱う（画面の変更は小さく）。(3) 打ち手は「まず狭い幅で読み、余ったら広げる」が今の「まず幅、残りを深化」より強いかを、IKA-333 の持ち時間の対戦評価で比べる。
* 判定: 広げた読みが、最初から広い幅で同じ量を読んだ答えに近いか（IKA-342 の読み比べの形）。数えの時計で、スレッド数に依らずビット一致。データ生成の局は変えない（既定 off）。

## 1. 入れたもの

### 1.1 `deepen.Grow`（深化の途中で根を広げる口）

* `deepen_root`・`deepen_belief` に `grow` を足した（`search`・`belief_solve` の deepen の辞書・`humanplay.solve_move` から渡る）。深化のステップの頭で、計算予算の読み（`_Meter.spent`）を渡して呼ぶ。各側の足す手（側 0 の、側 1 の）を返せば広げ、None なら何もしない。
* 根の候補集合に無い手だけを、行は行の末尾に、列は列の末尾に足す。精緻化済みのセルは添字も部分木もそのまま（子は `(行, 列)` の添字で持つので、末尾に足せば崩れない）。
* 足したセルだけを深さ 1 で行列の評価をする。全公開の根は 1 回の呼び出し（最善応答オラクルが既に問うたセルはその値を使う）、裏の残る根（`_BeliefRoot`）は「新しい行 × 全部の列」と「前の行 × 新しい列」の 2 つの長方形を、裏の決定化ごとに。計算予算には普通の行列の評価として数える。そのあと均衡を解き直す。LP が解けなければ広げずに前の根のまま。
* 広げたステップは 1 ステップ（`Step.kind == "grow"`、画面の電文の種類の末尾に足した）。記録（`Deepened`）には広げたときだけ `grown`（足した手の数）と `grownCells`（そのセル）を書く。
* 最善応答オラクルがあれば、足した手はその候補にも入る（入れ替えで押し出されても、また問われて戻れる）。
* 呼ぶのは深化のループのスレッドで、先読みのヘルパーのロックの中（候補集合を評価モデルで順位付けすることがあるため）。
* `grow` が無い・何も返さないときは、今までと一字も変わらない（`if grower is not None` の外は触っていない）。データ生成と対戦評価は `grow` を渡さない。

### 1.2 検討モード（`analysis.Widen`・`Service`）

* 読んでいる最中に、同じ局面・同じ読む側・同じ深さの上限で、今より広い幅を頼まれたら、読みを止めずに `Widen` に渡す。次の深化のステップの頭で、新しい幅の候補集合を読みの順位付けのまま作り、根に足す。
* 幅を狭める・同じ幅で「読み直す」・局面や読む側や深さの上限を変える、は今まで通り最初から読み直す。
* 読みが終わる瞬間に来た要求（最後のステップの後）は、終わった後に新しい幅で最初から読み直す（取りこぼさない）。
* 画面: 歯車の「この設定で読み直す」ボタンの文言が、広げられる条件のときだけ「幅を広げる（読みは続ける）」になる。広げたらログに「幅を W に広げた（候補集合 a×b）。読んだ木はそのまま読み続ける」。前後の比較は出さない（ユーザーの決まり）。
* 答えの記録（`--out`）に、終わったときの幅（`width`）と広げた幅の列（`widenedTo`）を足した。

### 1.3 打ち手（`humanplay.Agent.widen`、既定 None）

* `widen=(share, at)`: 最初の幅は幅の規則を `share`（既定の `WIDTH_SHARE` 0.5 より小さい）で選び、深化が計算予算の `at` を使ったところで、規則が 0.5 で選ぶ幅まで広げる（同じ順位付けの候補集合。`_menus` の `wide` で、順位付けは 1 回）。
* 時計の記録（`<out>.clock.jsonl`）の手の行に `widenTo` と `widened`、局の記録の `plan` に `widenTo`。
* 既定 None では `plan_move` の結果も `_menus` の呼び方も今と同じ。`play_human` の旗と `time_match` の条件のキーは、IKA-333 が master に入ってから足す（`C:/tmp/ika354/timematch_widen.py` に用意し、IKA-333 のブランチの `timematch.py` に当たることを確かめた）。

### 3.1 形

  * **W**: 幅 64 を最初から。IKA-342 の `g16` の読みをそのまま使った。この枝の木で p00 を読み直すと、IKA-342 の `p00-g16` と全ステップの数え・値・混合・根の価格までビット一致した（使い回してよいことの確かめ）。
