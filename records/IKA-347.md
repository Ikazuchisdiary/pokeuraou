## 2. 何を変えたか

* `rust/src/encode_games.rs`（新規）と `main.rs` の `encode-games` 副命令:
  `pokeuraou-damage encode-games <regulation.json> [--jobs N] [--limit N] [--kind K ...] -- <file.jsonl> ...`
  * 記録は型付きの構造体で読む（名前の無い欄は読み飛ばす）。`Value` にするのは局面だけ（`Position::from_json` がそれを取る）
  * 浮動小数は元の文字列から `str::parse::<f64>` で読む（serde_json の既定の読みは正しく丸めない。`searchValue` は f64 → f32 なので 1 ulp の差が配列に出うる）。
    そのため `serde_json` に `raw_value` の機能を足した（読み方を変える機能ではなく、既存の経路の挙動は変わらない。依存の追加なし）
  * 無い欄と null を区別する: `record.get("information", "open")` は欄が無ければ "open"、null なら "None"。meta に数える欄（provenance・searchLimit・searchObjective・
    selectionSource・information・engine）と `foeArchetype` は、生の JSON の文字列（か「無い」）ごとの数を初出の順で返し、Python が同じ `.get`・`or {}`・`str()` を当てる
  * ファイルごとに別のスレッドで読み（`--jobs`）、ファイルの並び順に繋ぐ。局の番号・相手の番号・meta の数・未知の volatile は、逐次のループが出会った順になる
  * 未知の volatile は `encode_mon` と同じ順に局面を歩いて並べ、数は encoder 自身の数と局ごとに照合する（食い違えば止まる）
  * 読めない行は、そのファイルの最後の行（書きかけ）だけ飛ばす。途中の行が読めなければ止まる（Python が読める `NaN` を serde が拒むような差を、黙って別のデータにしない）
  * 出力は標準出力に、JSON のヘッダ 1 行（数・幅・meta の小さな表）と、生のリトルエンディアンの配列 16 本。添字は Python の encoder と同じ int64 で送る
  * `ika347-control` 機能: 陽性対照。field の turn の特徴を 1 つずらして書く
* `tools/encode_dataset.py`: 旗と出力はそのまま。局ごとのループを `_read_rust`（既定）に替え、今までのループは `_read_python`（`--engine python`）として残した（比べる基準）。
  配列はパイプから `readinto` で numpy の配列に直接読む。`--jobs N`（既定 1）。キャッシュ・meta・npz の書き出しは Python のまま
  * exe が無い・古いときは `rustnode.require_current_binary()` で止まる
* `tests/test_encode_games_port.py`（新規）: 小さな記録（3 局を実際に打ち、未完了の局・空行・書きかけの最後の行・別の provenance・欄の欠落と null・`foeSearchValue` の欠落・2 ファイル）で
  両経路の shard をメンバーごとにバイトで比べる。`--kinds`・`--limit`（ファイルをまたぐ場合も）・`--jobs 2` も同じく。途中の読めない行で止まることも見る
* `tests/test_final_position.py`: `encode_dir` に渡す Namespace に `engine`・`jobs` を足した
* `.github/workflows/ci.yml`: suite ジョブの torch の skip の予算 17 → 18（新しいテストのファイルが torch を要る）

Q の教材（`tools/q_teach.py`）は `encode_dataset.py` を通らない。1 局面ずつ `encoder.encode_positions([pos])` を呼び、その横で行列の評価をするので、符号化の分は小さい。対象外にした。

## 5. 局ごとに多コアで並べる案との比べ

Python のループをファイルごとに N 本のプロセスで回す案（安い案）の見込み: 1 節の 1 コアの内訳のうち並べられるのは読み・復元・符号化（専有で約 120 秒）。8 本で約 15 秒、
それに配列（1.73 GB）をプロセスから親に戻す手間と npz の書き出しが乗って、20〜30 秒ほど。コアは 8 本使い続ける。
port の経路は 1 コアで 41 秒、8 本で 19.5 秒なので、同じコア数では port が速く、1 コアで回しても安い案の 8 コアに近い。加えて安い案は、ファイルの数より細かくは並べられない
（1 世代 24 ファイル）。port の経路は `--jobs` で同じ並べ方もできる。
