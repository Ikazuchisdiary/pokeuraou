# IKA-419 1構築の診断の道具を作る（段1: 値と勝率の照合）

段1の問いは次のとおり。選出ゲーム（順序付き 90×90）の均衡の値を value-mc4（value-mc4.pt と value-mc4-s1.pt の平均）で出す。その値は、実際に打った局の勝率とどれだけ合うか。

## 結論

段1は通る。値は構築の強さの順位をよく写し、勝率との目盛りもほぼ 1 対 1 に合う。組ごとの値には、標本の少なさでは説明できない誤差が残る。

| 照合 | 構築ごと（65 構築）の Spearman | 組ごと（2,080 組）の Spearman | 勝率の回帰の傾き（構築ごと） |
|---|---|---|---|
| value-mc4 が学んだ局（selfplay-mc4、39.9 万局） | +0.964（構築の bootstrap 95% [+0.926, +0.977]） | +0.874 | 0.93 |
| 学んでいない局（対戦評価の盤、2.2 万局） | +0.907（同 [+0.846, +0.946]） | +0.537（1 組 10 局ほどで標本が少ない） | 0.97 |

- 前者は value-mc4 の学習に入っている局なので、合い方が良く出る。後者を学習外の確認として並べた。
- 照合に使った局を打った評価モデルは前者が value-mc3、後者が value-mc4 ほか世代の混じりである。値は value-mc4 で出している。

## 道具

`tools/selection_diag.py`（3 つの小コマンド。新しく葉は学ばない）。

| コマンド | 内容 |
|---|---|
| winrates | 局の jsonl（一つの局は数十 KB）から `pool.teams` と `outcome` だけを正規表現で読み、組ごとの局数と勝ちを数える。各ファイルの先頭 20 行は JSON の読み取りと突き合わせ、ずれたら止める |

| report | 順位相関・較正・組ごとの区間。`--team-file` を付けると 1 構築の対プールの表になる |

テストは `tests/test_selection_diag.py`（正規表現が局の 2 通りのキー順を読む。正規表現と JSON の読みがずれたら止まる負の対照。統計の小さな検算）。

## 確かめていないこと

- 実対戦の局は、プールの構築どうしの局だけを使った。プール外の構築の値が勝率と合うかは測っていない。
- 学んだ局の照合は、学習に入っている局なので、合い方が良く出る。学んでいない盤の局は組ごとには標本が足りない（1 組平均 10 局）。組ごとの較正の確かな照合には、盤を回して局を足す必要がある。回していない。
- 盤の局は、アームと世代が混じる（qmc 系・x2 と x3・x4 の比較）。勝率はアームの強さの差を含む。
- 選出ゲームは「選出は相手の 4 匹が見えない、対戦中の評価は裏が見えている」という前提を含み（`selection.py` の注記）、実際の対戦評価は裏を隠して打つ。照合の合い方は、この差を含んだ結果として出ている。
- 構築の型（努力値・性格）の置き方が結果にどれだけ効くかは測っていない。
- 値の標本の少なさの区間は、組ごとの勝率には出した。値の側（評価モデルの種ごとのばらつき）は測っていない。

## 確認: ユーザーの構築の連携を port とソルバは扱えるか（2026-10-02）

ユーザーの構築は連携で勝つ構築である。メガXライチュウ（メガ進化でエレキメイカー）がエレキフィールドを張る。クエスパトラはエレキシード・めいそう・かそくで能力を上げ、バトンタッチでエースに渡す。ニョロトノの雨とリザードンYの晴れも絡む。エレキシードで上がるのはぼうぎょである（Showdown の items.ts は `boosts: { def: 1 }`。とくぼうではない）。

問いは2つである。問1は、port がこの連携を Showdown と同じに解決するか。問2は、ソルバがこの連携を打てるか、評価モデルがこの連携を評価できるか。

### 結論

- port は3つの規則で Showdown とずれていた。3つとも直した。バトンタッチは能力ランクと状態を引き継がなかった（注記つき）。ライジングボルトは接地していない相手にも威力が2倍になった（注記なし）。同じ天候の中の天候わざは、天候の残りターンを5に戻した（注記なし）。
- 直した port では、ソルバはバトンタッチを候補に残し、ときどき選ぶ。能力も渡る。
- 評価モデルはこの構築を評価できていない。学習データにクエスパトラ・バトンタッチ・エレキフィールドは1回も出てこない。60局の対局で、ユーザーの構築の勝率は 0.314 だった。選出の値の平均は 0.505 である。相手ごとの順位も合わない（6相手で Spearman −0.12）。プール外の構築の較正の最初の点は、値が勝率を大きく上回る結果になった。

問いは、ユーザーの席の選出とライチュウのメガ進化を筋1の形に固定すれば、勝率が上がるかである。筋1は、ライチュウXをメガ進化させてエレキフィールドを張り、クエスパトラが能力を上げてバトンタッチで渡す流れである。

### 結論

- 筋1をユーザーの言う形で打っても、勝率は上がらなかった。この 6 相手と 300 対では、下がった。
- バトンタッチの保留は効いた。腕 B のバトンタッチ 215 回のうち 206 回は、とくこう・とくぼうが両方 +1 以上でない状態からだった。腕 C は 53 回のうち 0 回である。
- 能力を渡せた局は 47 局（15.7%）しかなかった。その 47 局の勝率は 9/47 = 0.191 で、B の 35/177 = 0.198 と同じ水準である。渡せなかった 253 局の勝率は 20/253 = 0.079 で、B の 30/123 = 0.244 より低い。

- エルフーンに渡せた局は 2 局だけだった。渡した先は 49 回のうち 47 回がブリジュラスで、「エルフーンに渡す形」はほとんど打たれていない。ソルバは、裏の 2 体のうち渡す先をブリジュラスに選んだ。

### 方法

- 打ち手・対局・相手は 419f と同じである（value-mc4 と value-mc4-s1 の平均、幅 12、rank-leaf、q-nocover は q-mc4、裏は非公開、CPU、seed 419、`pool7.json`、`--pairs-with espathra --pairs-no-mirror`、局の番号 300 × 2 席）。port は自分の source から作った exe（`rust/target/release`）である。
- 腕 C は、ユーザーの席だけを変える。相手の席は本番のままである。
- 費用は 5 コアで 13.1 分（`heavy.py`、`--cores 12 --cores-min 5`、見積り 20 分）。

腕 C の中身は次のとおり。

| 項目 | 内容 |
|---|---|
| 先発 | ライチュウとクエスパトラ（ライチュウが 1 番目） |
| 裏の2体 | エルフーンとブリジュラスに固定（この順）。均衡からは引かない |
| ライチュウのメガ進化 | 腕 B と同じ。1 ターン目に、本番の均衡をメガ進化の手に条件付けた確率で引く。確率が全部 0 なら、メニュー順の最初の手 |
| バトンタッチ | クエスパトラが場にいて、とくこうかとくぼうが +1 未満のあいだ、クエスパトラのバトンタッチを含む行を、ユーザーの席の候補（`side_actions` の出力）から外す。外した後の候補で順位付け・幅 12 の絞り込み・均衡を解く。両方が +1 以上になれば外さない |
| それ以外 | 本番の探索のまま（めいそう・まもる・渡す先・エルフーンの技など） |
| 相手の席 | 本番のまま。相手の探索は、ユーザーの席がバトンタッチを外していることを知らない（相手が思うユーザーの候補にはバトンタッチが残る） |

- 候補から外す位置は `actions.side_actions` である。ユーザーの席の探索を読む間だけ、保留（`actions.hold_baton`）を有効にする。順位付け（leaf・Q）、幅 12 の絞り込み、均衡の行列は、すべてこの出力の上で作る。外した後に幅を詰め直すので、バトンタッチの行が幅 12 の枠を使わない。
- 外す条件の片方でも未達なら外す。とくこう +1・とくぼう 0 や、とくこう +3・とくぼう 0 や、とくこう +1・とくぼう −1 は外す。両方が +1 以上なら外さない。クエスパトラが戦闘不能のときと、別の種のときは何もしない。外すとメニューが空になるときは、外す前のメニューを残す（コードの安全策。保留が閉じているノードで漏れた数が 0 なので、この対局では働いていない）。
- 保留があるときは、探索が相手と同じメニューを使い回さない（`same_menu` を外す）。ユーザーの席と相手の席は、それぞれ自分のメニューと解を作る。
- 先発・裏・メガ進化の旗は 419f のもの（`--line1`、`--line-only-with espathra`）で、裏の固定だけ `--line1-back whimsicott archaludon` を足した。保留は `--hold-baton`（`--baseline-hold-baton` で相手の腕）。どれも既定は旗なしである。
- コード: `src/pokeuraou/actions.py`（`BATON_HOLD`、`hold_baton`、`baton_gate_open`、`baton_slots`、`uses_baton`、`side_actions` の出口の `_without_held_baton`）、`src/pokeuraou/selfplay.py`（`play_game` の `hold_baton`、記録の `holdBaton`・`batonHold`）、`src/pokeuraou/poolplay.py`（`PoolArm.line1_back`・`hold_baton`、`draw_line1` の `fixed_back`、`check_hold_baton`）、`tools/pool_match.py`（`--hold-baton`・`--baseline-hold-baton`・`--line1-back`）、`tests/test_hold_baton.py`。
