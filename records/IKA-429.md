## 1. 縛りの定義（段 1）

縛りは port のダメージ計算から作る（`rust/src/bind.rs`）。場の 2 体と相手の 2 体の、向きのある 8 組を技ごとに判定する。控えは含めない。

| 項目 | 決めたこと |
|---|---|
| 1 撃 | 急所なしの 16 乱数のうち、相手の今の HP を削り切る乱数の割合。必中急所の技（willCrit）は急所で計算する。命中は読まない |
| 範囲技 | 当たる相手が 2 体以上なら 0.75 倍で、両方の相手に当てる。味方にも当たる技（allAdjacent）は、味方が生きていれば 0.75 倍 |
| 耐える効果 | きあいのタスキ・がんじょう（HP 満タン）と、ばけのかわは計算器の扱いのまま |
| 連続技 | 最小回数（スキルリンクは最大回数）で、同じ乱数が毎回出るとみなす。タスキとがんじょうは効かない |
| 先手 | 技の優先度（いたずらごころ・はやてのつばさ・グラススライダーを含む）、次に実効の素早さ（おいかぜ・まひ・スカーフ・天気の特性）。トリックルームでは逆にする。同速は 0.5 |
| 相手の技 | 分からないので優先度 0 とみなす |
| 止まる先制技 | サイコフィールドで地面にいる相手と、ビビッドボディ・じょおうのいげん・テイルアーマーの側への先制技は、倒せないものとして数える |
| 使える技 | PP が残り、かなしばりでない技。こだわり・アンコール・あばれる・溜め技で固定された体は、その技だけ |

組 (X, Y) の値は、技 m ごとに「先手（1・0.5・0）× 1 撃の割合」を出し、その最大を bind(X, Y) とする。先手を問わない最大を ko(X, Y) とする。

符号化の列（revision 4）は次のとおり。どれも 1/2048 の倍数で、float32 で正確に表せる。

| 列 | ブロック | 値 |
|---|---|---|
| `bind_out` | 1 体 | この体が縛っている相手の bind の和 / 2 |
| `bind_in` | 1 体 | この体を縛っている相手の bind の和 / 2 |
| `ko_out` | 1 体 | この体が倒せる相手の ko の和 / 2 |
| `ko_in` | 1 体 | この体を倒せる相手の ko の和 / 2 |
| `foes_bound` | 側 | 相手の各体について、自分の体の bind の最大をとった和 / 2 |
| `double_bind` | 側 | 相手が 2 体いるときの、その最大の小さいほう（両縛り） |
| `secure_bound` | 側 | `foes_bound` のうち、縛り手が相手に縛り返されていない分 |
| `spread_double` | 側 | 1 体の範囲技 1 発で相手 2 体をともに縛る強さ |
| `spread_ally_ko` | 側 | その範囲技が味方を倒す乱数の割合 |
| `spread_wide_guard` | 側 | 範囲技の両縛りに対し、相手がワイドガードを持つ |
| `spread_fake_out` | 側 | 範囲技の両縛りに対し、相手のねこだましがその体を止められる |

* 控えの行の 4 列は 0 にした。こうすると 1 体の行は場の体と場の状態だけで決まる。`beliefnode._patched` が控えの行を別の局面の符号化から写しても、値は正しいまま残る。
* 両縛りは、縛られた相手の数が 2 のときに数える。縛る側は 1 体でも 2 体でもよい。1 体の範囲技による両縛りは、まもるで 1 体を守っても、もう 1 体が倒れる。そこで `spread_double` を別に持つ。
* ねこだましの判定: その体が場に出て最初の行動で、範囲技より先に動ける（優先度が高い、または同じ優先度で速い）。相手がゴースト・せいしんりょく・りんぷん・おんみつマントのときは止められない。
* 縛りを解く技は `bind.rs` の `RELEASE_*` に 1 か所でまとめた。ワイドガード、ねこだまし、このゆびとまれ・いかりのこな、まもる系（まもる・みきり・ニードルガード・キングシールド・トーチカ・スレッドトラップ・かえんのまもり・ブロッキング）。列として読むのはワイドガードとねこだましだけで、ほかは技の埋め込みで網が読む。

## 2. 両方の符号化の一致の扱い

* 1 ターンの解決とダメージ計算は port だけが持つ。縛りの列も port だけが計算する。
* 学習の配列は port の `encode-games` が作る。探索の葉も port が符号化する。
* Python の `Encoder.encode_positions` は計算器を持たないので、port に `bind` 要求で局面を送り、答えの列を自分の配列に書く。選出の 8,100 局面は 900 の先発 4 体の組でできているので、場の体・場の状態・気絶数のオブジェクトが同じ局面は 1 回だけ問う。
* `beliefnode._patched` は控えの行だけを読むので、`bind=False` で問わない。
* port の側は、葉ごとに全部を計算すると重い。そこで、体（HP は計算器が読む旗だけ）・場・組ごとのダメージ乱数を正確なキーで覚える（`BindCache`）。倒せる乱数の割合は、葉ごとの HP で数え直す。
