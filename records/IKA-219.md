## 3. 局面・符号化の判断

* **sim-bridge の局面**は種族（`species` = 写した種族、`baseSpecies` = ditto）・タイプ・特性・技（PP 5）・ランク・`statsOverride`（storedStats）・`transformed` を元から運んでいた。**運べなかったのは戻り先**（`baseAbility` と `baseMoveSlots`）。交代や瀕死で戻すにはこれが要るので、`transformed` のときだけ `baseAbility`・`baseMoves` を書き出すようにした（`packages/sim-bridge/src/position.ts`、dist は worktree で tsc。変えない側の出力は元の dist とバイト一致を確かめた）
* **port の局面**（`rust/src/position.rs`）：`Pokemon.transform_base: Option<Box<TransformBase>>`（特性と技）。変身中だけ Some で、JSON は変身中だけ `baseAbility`・`baseMoves` を出す。変身していない局面の JSON は前と同じ
* **Python の局面**（`src/pokeuraou/position.py`）：生成では局面が port と Python を往復する（`Position.from_json`/`to_json`）ので、`base_ability`・`base_moves` を足して素通しにした（読む所は無い）。変身していなければ出力は前と同じ
* **符号化（encode.py・encode.rs）は変えていない**。変身した状態は既存の欄に乗る：種族 id（写した種族）・特性 id・技 id と PP の割合（5/5）・タイプ・ランク。新しい入力は足していない。値関数の入力の形は同じ
  * 近似になる所：符号化の能力 6 つは `stats_from_sp(種族, 性格, SP)` で作るので、変身したメタモンは「写した種族の種族値 × メタモン自身の性格と SP」になり、Showdown の storedStats（相手の実数値）とは違う。`transformed` の旗そのものも符号化されない（メタモンと本物は最大 HP と PP で見分けるしかない）
  * メタモンは生成の記録に 1 度も出ていない（§1）ので、学習済みの値関数はこの局面を見たことがない。符号化を変えるかは、プールにメタモンが入るときに調整役と決める（§9）

## 4. 入れたもの（rust/src、既存行の書き換えを小さく）

* `transform.rs`（新規）：`transform_into`・`imposter`・`revert`・`switch_names`
* `moves.rs`：`apply_status_move` に 3 行（`mv.id == "transform"` で `transform_move`）と小さな関数 `transform_move`
* `resolve.rs`：`restore_types` の先頭で `revert`、`switch_in_ability` を `pub(crate)` にして先頭で `imposter`、`check_position_supported` の `transformed` の拒否を外した、`ability_handled` に `imposter`・`illusion`
* **交代の相手を種族で探す 4 か所**（`resolve.rs` 3・`commands.rs` 1）を `transform::switch_names` に替えた。変身したメタモンは写した種族を名乗るので、自分の側に同じ種族がいると「その種族に交代」がメタモン（場にいる）を見つけて何もしなかった。§6 のメタモン差し込み標本で見つけた（直す前 species の乖離 27 → 8、その 8 は §6 の別の穴）。交代で出てくるのは控えで、控えは変身していないので、変身中のものを種族では探さない
* `hidden.py`：`shown_species` は変身中のポケモンの種族（写したもの）を「見せた」に入れない。入れると、写した種族を持つ相手の控えが見えない枠の候補から消え、候補が足りなければ `completions` が ValueError を投げる。生成で変身した局面が出るようになったことで初めて通る道なので、ここで直した（正の対照：直す前の行でテストが落ちる）
* `tools/port_coverage.py` の engine に `transform.rs` を足し、`inert.rs`・`modelled.rs` を作り直した：`imposter`・`illusion` が inert から modelled へ、`transform` が `status_move_is_fully_modelled` に入った（注記 `status move: transform`・`defender.ability:imposter` が出なくなる）。illusion を modelled にしたのは、ターンに見える作用が「へんしんの失敗」だけで、そこで注記を出すから

構造の変更（取り込みで見るもの）：`Pokemon` に `transform_base`（8 バイト）、`TransformBase`、`switch_in_ability` が `pub(crate)`、交代の探し方 4 行、`mod transform`。
