## 3. 局面・符号化の判断

* **sim-bridge の局面**は種族（`species` = 写した種族、`baseSpecies` = ditto）・タイプ・特性・技（PP 5）・ランク・`statsOverride`（storedStats）・`transformed` を元から運んでいた。**運べなかったのは戻り先**（`baseAbility` と `baseMoveSlots`）。交代や瀕死で戻すにはこれが要るので、`transformed` のときだけ `baseAbility`・`baseMoves` を書き出すようにした（`packages/sim-bridge/src/position.ts`、dist は worktree で tsc。変えない側の出力は元の dist とバイト一致を確かめた）
* **port の局面**（`rust/src/position.rs`）：`Pokemon.transform_base: Option<Box<TransformBase>>`（特性と技）。変身中だけ Some で、JSON は変身中だけ `baseAbility`・`baseMoves` を出す。変身していない局面の JSON は前と同じ
* **Python の局面**（`src/pokeuraou/position.py`）：生成では局面が port と Python を往復する（`Position.from_json`/`to_json`）ので、`base_ability`・`base_moves` を足して素通しにした（読む所は無い）。変身していなければ出力は前と同じ
* **符号化（encode.py・encode.rs）は変えていない**。変身した状態は既存の欄に乗る：種族 id（写した種族）・特性 id・技 id と PP の割合（5/5）・タイプ・ランク。新しい入力は足していない。値関数の入力の形は同じ
  * 近似になる所：符号化の能力 6 つは `stats_from_sp(種族, 性格, SP)` で作るので、変身したメタモンは「写した種族の種族値 × メタモン自身の性格と SP」になり、Showdown の storedStats（相手の実数値）とは違う。`transformed` の旗そのものも符号化されない（メタモンと本物は最大 HP と PP で見分けるしかない）
  * メタモンは生成の記録に 1 度も出ていない（§1）ので、学習済みの値関数はこの局面を見たことがない。符号化を変えるかは、プールにメタモンが入るときに調整役と決める（§9）

## 9. 別課題の候補

* **同速の順番（diff_turn の約束）**：Showdown の `speedSort` は選択の入れ替えのあと同速の組を shuffle する（`keep` はその並びのまま）。port の決定的な予算は安定ソートで p1 を先にする。変身は写した相手と同じ素早さを作るので、メタモンの局面ではこの形の乖離が増える（差し込み標本で 20 ターン）。diff_turn の比べ方を「同速は分けて、どれかの枝が一致」にするか、port の決定的な順を Showdown の並べ方に合わせるか
* **Inner Focus でひるみが止まらない**（port、`innerfocus` はいかくにしか出てこない）
* **半減の実が、倒れる当たりでは食べられずに残る**（`moves.rs` の `Some(mon) if mon.fainted => false`。Showdown は当てる前に食べる）
* **ノーてんき・エアロックの下でソーラービームを溜めない**、**アンコールで替わった技の優先度でファストガードを判定していない**、**メガエレザードの特性 Eelevate**（diff_turn の差し込み標本で見た。どれも変身とは無関係）
* **port は `timesAttacked` を数えない**（当たっても 0 のまま。ふんどのこぶし の威力が変わらない）。テストでは変身中のものだけ比べている
* **生成の先発の PP が Showdown と違う**（`selfplay._opening` は dex の PP：まもる 5・ねこだまし 10、Showdown の champions は 8・12）。長い試合で PP 切れの時期が変わる
* **変身中に効かない特性（notransform）**：ばけのかわ・マイティチェンジ・はらぺこスイッチ・うのミサイル・アイスフェイス・おもかげやどしを写した場合、Showdown は `ignoringAbility` で効かなくする。port は写した特性をそのまま使う（ミミッキュ・パルデア以外は規則表に持ち主が少ない）
* **変身したメタモンがメガストーンを持つとき**：Showdown はメタモンの `canMegaEvo` を試合の始めに決める（null）。Python の手の一覧と port の `do_mega` は今の種族と持ち物で決めるので、写した種族のストーンを持っていればメガを許す（差し込み標本のような構築でだけ起きる）
* **イリュージョン**：port は状態を持たないので、ゾロアークへのへんしん・ゾロアークのかわりもの相手は「出ていない」とみなして注記する
* **トレースを写したかわりもの**：`switch_may_trace` は登場するポケモン自身のトレースしか見ないので、かわりものが写したトレースの引きは分けずに先頭（注記は出る）
* **符号化**（§3）：変身中の能力が「写した種族 × メタモンの SP」になる。プールにメタモンを入れるなら、statsOverride を読むか `transformed` を入力に足すかを決める
* **Python の局面の往復 +1 µs**（§7）：気になるなら `base_ability`・`base_moves` を 1 欄にまとめる
