## 1. IKA-324: `speed.action_overriding_effects`

### 1.1 原因

名前（Showdown の ID）を、行を小文字にした文字列の中から `move: {name}` か `|{name}|` で探していた。ID に空白は無いが
表示名にはあるので、`|-activate|p2b: Toxapex|move: After You` の `afteryou` は一度も当たらない。

### 1.2 洗った効果（Showdown の data と sim を読み、M-C の dump にあるものを確かめた）

途中で行動の順を動かすもの（`queue.prioritizeAction`・`action.order` の書き換え・行動の差し込み）と、そのログの形:

```
効果              M-C に   ログ                                          直す前   直した後   port
おさきにどうぞ      ある    |-activate|X|move: After You                   ×        ○          注記（unmodelled）
さきおくり          ある    |-activate|X|move: Quash                       ○        ○          注記
さいはい            ある    |-singleturn|X|move: Instruct|[of] Y           ○        ○          注記
おどりこ（特性）     ある    |-activate|X|ability: Dancer                   ×        ○          注記
アンコール          ある    |-start|X|Encore（"move:" なし）               △ ※1     ○          模している（除かない）
りんしょう          ある    ログなし（2 人目を 1 人目の直後へ）              ×        ○ ※2       威力だけ（順は無い）
ちかいのわざ 3 種    無い    |-waiting|X|Y                                  -        -
トラップシェル      無い    |-singleturn|X|move: Shell Trap（前）           -        -
```

* ※1 アンコールの技の行（`|move|X|Encore|Y`）には当たっていたが、効果が始まる行には当たっていなかった。終わる行
  （`|-end|X|Encore`）は並べ替えないので、直した後も数えない
* ※2 りんしょうは 1 人目の onTry が 2 人目の行動を黙って前へ出す。ログに印が無いので、ターンにりんしょうが 2 回出たとき
  だけ `round` とする。port は順を模していないので、`only_unmodelled` の側（diff_turn・diverge_report が飛ばす）にも入る
* 並べ替えでないもの: コマンダー（`cancelAction`、行動が消えるだけ）、トリックルームの途中の開始（速さの側。
  `speed_changing_effects` で `-fieldstart` として "terrain" の名で数えられている。名前は違うが除外はされる）、
  せんせいのツメ等（小数の優先度として `build_queue` が扱う）
* 1,600 局 ×4 種（§1.4）で当たったのは afteryou・quash・instruct・encore。りんしょう 2 回・おどりこは 0

### 1.3 直し

行を `|` で割り、4 つ目以降の欄を 1 つずつ、`[from]`・`move: `・`ability: ` を外して `to_id` し、名前と比べる。
`-end` の行は見ない。りんしょうは技の行を数えて 2 以上で足す。`ACTION_OVERRIDING_EFFECTS` に `round` を足した。

### 1.4 前後（PYTHONHASHSEED=0、1,600 局）

前 = master の tools と master の `action_overriding_effects`、後 = この枝。src の残り・exe・sim-bridge は同じ。
diff_order は種 1〜4 × 400 局、diverge_report は種 1〜16 × 100 局。

```
                         前                     後
diff_order 比べた        12,876                 12,874
           乖離          3（0.023%）            1（0.008%）
           並べ替えで除いた 339                  341
           afteryou に当たった   0              3（種 2・3・4）
diverge_report 比べた    11,377                 11,373
           乖離          646                    646
           "action overridden mid-turn"  13     17
           afteryou に当たった（unmodelled）  0   4
```

* **陽性対照**: 直す前は afteryou が 0 回、直した後は diff_order で 3 回・diverge_report で 4 回当たる
* diff_order の乖離 3 → 1。消えた 2 件（種 2・4）が並べ替えに移った（339 → 341）。種 3 の 1 件は同じターンにほかの原因
  もあったので、除く数は変わらない
* 残る 1 件（種 1、turn 6）は前後とも同じもの（p2a がてだすけのターン、p2b サイコキネシス 素早さ 189 より p1b の kowtowcleave 素早さ 85 が先に動く）。読んでいない
* diverge_report で飛ばすターンが 4 増え、比べるターンが 4 減った。乖離は 646 のままなので、その 4 ターンは一致していた
* 種 1 の 1 局は前後とも "You can't choose a target for Uproar" で止まる（battle 104 turn 4）。別の課題の候補（§5）

## 2. IKA-327: diff_replacement の "Draco Meteor needs a target"

### 2.1 再現

IKA-316 の 1 件は、そのときの PYTHONHASHSEED でしか出ない。M-C の道具のうち diff_order・diff_speed・
diff_replacement・diff_damage は IKA-218 の `hash_free_prior` を通っておらず、チームの特性の引きが hash の種で変わる
（PYTHONHASHSEED 0 と 1 で種 4 の局は battle 0 の特性から違う。100 局で行が一致するのは 69 局）。
hash の種 0〜3・10〜25（20 通り × 種 1〜4 × 400 局 = 32,000 局）を回すと、**hash 18・種 4・battle 291・turn 8** で同じ
拒否がちょうど 1 回出た。

### 2.2 原因（Showdown の request を読んだ）

交代待ちではなかった（そのステップの request は両側とも技の要求で、forceSwitch も wait も無い。
"not a pure replacement phase" は 32,000 局で一度も数えられていない）。

* p1b のドラミドロ（隣は p1a ドヒドイデ）が、前のターンにマフォクシーのアンコールでまもるに縛られ、シャンデラのふういんで
  まもる自体も使えない。使える技が無いのでわるあがきになる
* ふういんの禁止は Showdown では `'hidden'` で、その側の最後の 1 体への request では隠す
  （`getMoves(lockedMove, isLastActive)`）。request は 4 つの技を並べ、まもるだけ使える（`disabled: false`）と見せ、
  `maybeDisabled`・`maybeLocked` を付ける。わるあがきは載らない
* 列挙（`actions.slot_actions`）は正しくわるあがき（`move_index=1`、対象なし）を出す。`diff_turn.showdown_choice` は
  request に無い技の番号をそのまま残すので `move 1` になり、Showdown は 1 番目のりゅうせいぐんとして読んで、
  わるあがきに置き換える（`!moves.length`）前に対象の検査で断る

### 2.3 直し

`showdown_choice`: request に無いわるあがき（対象なし）は、request が使えると見せる技のうち、対象を選ばない
（`targetTypeChoices` の外の）最初の技の番号にする。Showdown のプレイヤーが押すのと同じ手で、Showdown はそれを
わるあがきにする。request がわるあがきを載せているときは今まで通り（`move 1`）。
この関数は 5 本の道具（diff_order・diff_speed・diff_replacement・diverge_report・diff_damage）と diff_turn が共有する。

### 2.4 陽性対照と前後

```
hash 18・種 4・400 局              前                           後
拒否                                1（battle 291 turn 8）        0
battle 291                          turn 8 で止まる               turn 12 で決着
比べた交代の局面                    1,212                         1,209（止まらなかった分 py_rng がずれる）
```

* 後のそのステップの選択は `move 3 2, move 2` で、Showdown のログは `|-activate|p1b: Dragalge|move: Struggle` →
  `|move|p1b: Dragalge|Struggle|p2a: Delphox`。Showdown が受け取ってわるあがきにしたことを確かめた
* PYTHONHASHSEED=0 の 1,600 局（種 1〜4 × 400）は前後で同じ（比べた 4,927・乖離 2・拒否 0）。この形の局面は出ない
