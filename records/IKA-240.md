## 3. 入れたもの（新しいファイル 1 つ、既存の関数への挿入 5 か所、既存行の書き換え 0）

新しい `rust/src/move_hooks.rs`（6 関数）:

* `fails_on_try(turn, move_id, targets)`: ポルターガイストの `onTry`（最初の対象が道具を持たない）
* `field_past_screens(field, move_id, target)`: 壁破りのダメージを計算する場。対象の側の壁を除く
* `break_screens(turn, move_id, target)`: 壁破りの `onTryHit`。対象の側からリフレクター・ひかりのかべ・オーロラベールを除く
* `set_berry_aside(turn, move_id, target)` / `steal_berry(...)`: むしくい・ついばむ。`deal_damage` が半分以下で対象にオボンを食べさせないよう、
  ダメージの間だけきのみを外し、後で戻して取る。取らない場合（使い手が倒れている・この当たりの半減の実・ねんちゃく）は対象の
  `check_berry` をその場で呼ぶ（`deal_damage` がしたはずのこと）
* `eat(turn, at, berry)`: 食べた効果。オボン・オレン・ラム・キー・半減の実。それ以外のきのみ（状態異常のきのみ・ヒメリ）は
  `berry eaten by another: <id>` と注記する

呼び出し（moves.rs）:

* `use_move`: `damage_callback::fails_on_try` の直後にポルターガイストの失敗（`move_failed` を立てる）
* `hit_target`: `let field = field_for_hit(&turn);` の直後に `field_past_screens`。乱数の枝ごとの `break_protection` の直後に `break_screens`
  （免疫と外れの枝には入らない）。`deal_damage` の前に `set_berry_aside`、後に `steal_berry`（`damage_callback::record` と `after_hit`
  より前）
* main.rs に `mod move_hooks;`、`tools/port_coverage.py` の `PORT_ENGINE_FILES` に `move_hooks.rs`
* `tools/port_coverage.py --rust-modelled` で modelled.rs を書き直した。変わったのは `damaging_move_is_unmodelled` から 5 技が外れたことだけ

**名前の出し方の注意**: 最初の版は、食べた効果に状態異常のきのみ（クラボ・カゴ・モモン・チーゴ・ナナシ）と、使い手の特性
（ほおぶくろ・はんすう・じゅくせい）を文字列で書いた。port_coverage は「エンジンが名前を出す id は扱っている」と読むので、modelled.rs の
`item_is_modelled` に 5 きのみ、`ability_is_modelled` に 3 特性が増えた（持っているだけで出ていた注記が消える）。どれも port は自分の
`onUpdate` や `EatItem` を扱っていないので誤り。名前を出さない形（上の `eat` の既定の枝で注記）に書き直し、modelled.rs の差分が
5 技の削除だけになるのを確かめた。
