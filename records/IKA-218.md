# IKA-218: diff_turn が PYTHONHASHSEED で打つターンを変えていたのは、使用率の事前分布の特性の表が set の順だったため —— Python の列とは無関係で、port の列だけでも再現した。道具の側で順を決め、diff_turn・diverge_report とも PYTHONHASHSEED 0/1/2/未設定でバイト一致。生成は M-B の `--opponents metagame` だけが同じ依存を持つ（別課題の候補）

9/24。ブランチ `ika-218-227-compare-tools`（master f025265 から）。IKA-227 と同じ枝。

## 1. 再現した（今の diff_turn、port の列だけ）

master の `tools/diff_turn.py`、seed 1 × 400 局（roll 8、max-turns 10、exe 27243d69adb57955）を PYTHONHASHSEED だけ変えて回した。

```
PYTHONHASHSEED        0              1              2
比べたターン         2,722          2,724          2,725
一致                 2,572          2,573          2,574
乖離率（silent）  5.511% (2.976%) 5.543% (3.010%) 5.541% (2.972%)
replacement turn       890            892            893
出力の sha256       3ddf99f5…      e6d3ad06…      4e71647e…
```

IKA-207 の「2,726 と 2,727」と同じ形の揺れが、Python の列が無くても出る。

## 2. どこにあったか

最初に食い違うのは **seed 1 battle 0 の 1 体目**（ターンより前、チームを引く所）。`sample_team` が引いた 4,800 体（400 局 × 2 チーム × 6）のうち、PYTHONHASHSEED 0 と 1 で特性だけが違うものが 159 体、それを含む局が 400 局中 142 局（0 と 2 では 44 局）。違ったのは Delphox 116・Mawile 42・Banette 7・Meganium 4・Pyroar 2・Aggron 1（両側の合計）。特性以外の項目（種族・持ち物・技・性格・努力値）と Showdown の種はすべて同じ。

原因は `src/pokeuraou/priors.py` の `load_chaos`（241 行目付近）:

```python
legal_ability_ids = {to_id(a) for a in target.abilities}
...
observed_abilities = {a: 1.0 / len(legal_ability_ids) for a in legal_ability_ids}
```

メガシンカの姿でしか使用率に出ない種族（`abilities_unobserved`、今の使用率ファイルで 19 種、特性が 2 つ以上あるのは 18 種）は、特性の表を **set を回して** 一様に作る。確率は同じだが表の並びが hash の種で変わり、`weighted_choice` は同じ乱数から並びの違う表を引くので、別の特性になる。以後の局の進み（選択・ダメージ）が変わり、打つターンの数も変わる。

**なぜ「Python の列」と見えたか:** IKA-207 が数えたのが Python の列の数（2,726 / 2,727）だっただけで、揺れはチームを引く所にあり、どの列にも共通。IKA-212 で Python の列が消えても残っていた。

diverge_report には set の順がもう 1 か所あった（`_tally` の `effects_in_play` と変化した項目の種類が set。数は変わらないが、Counter の最初に見た順が順位の同点と例の選び方を決める）。

## 3. 直したもの（道具の側だけ）

* `tools/diff_turn.py` に `hash_free_prior(reg, prior)` を足した。`abilities_unobserved` の種族の表だけを図鑑の特性の順に並べ直す（確率はそのまま、ほかの表は使用率ファイルの順のまま＝もとから hash に依らない）。`run()` は `load_chaos` の後にこれを通す。並べ直す表は 1 回の実行で 11〜12 個（残りは偶々図鑑の順だった）。
* `tools/diverge_report.py` も同じ関数を通し、`_tally` の 2 つの set を `sorted` にした。
* `load_chaos` そのものは直していない。生成（selfplay の `--opponents metagame`・`mix`）も同じ関数を読むので、直すと本番の局が変わる（§5）。
* diff_turn の「PYTHONHASHSEED is unset」の stderr の一言は、もう当たらないので消した（stdout の形は同じ）。

## 4. 直した後（PYTHONHASHSEED を変えてバイト一致）

```
diff_turn seed 1 × 400 局             0 / 1 / 2              → 3 本とも 01b9346b72de76df
  比べたターン 2,722、一致 2,575、乖離率 5.400%（silent 2.902%、flagged 68）、止まった 136・続けて比べた 133・うち乖離 9
diff_turn seed 2 × 400 局 ss 0.8      0 / 1 / 2 / 未設定     → 4 本とも 458e3dbfa006acb4
  比べたターン 2,747、一致 2,560、乖離率 6.807%（silent 3.640%、flagged 87）、止まった 367・続けて比べた 348・うち乖離 26
diverge_report 20 種 × 20 局          0 / 1 / 2 / 未設定     → 4 本とも a0ffd313702a3bcc（--jobs 1）
```

* **正の対照（直す前は揺れる）:** §1 の 3 本（master の diff_turn）。diverge_report も直す前は hash 0 と 1 で数が違った（2,662 / 2,659 ターン）。特性の表を直した後も、set を sorted にするまでは順位の同点の並びと例が違った（0/1/2 で 3 通りの sha）。
* **null 対照（直したのはこの 1 点だけ）:** この枝の diff_turn で `hash_free_prior` を恒等関数に差し替えて回すと、master の diff_turn の出力とバイト一致した（seed 1 × 400・PYTHONHASHSEED 0、seed 2 × 400 ss 0.8・PYTHONHASHSEED 0 の 2 通り）。IKA-227 で足した部分も diff_turn の出力を 1 文字も変えていない。
* テスト `tests/test_diff_turn_hashseed.py`（新、1 件、約 2 s）: PYTHONHASHSEED 0 と 1 の 2 つの子 process で表を出し、生の表は違う（正の対照）・直した表は同じ・並べ直しただけで中身は同じ、を断言。

**調整役へ（大事）:** 同じ PYTHONHASHSEED=0 でも、diff_turn の数は master と変わる（seed 1 × 400: 2,722 ターン 5.511% → 2,722 ターン 5.400%、seed 2 × 400 ss 0.8 は上のとおり）。引くチームの特性が一部変わるため。出力の形と旗は同じ。master の数と比べている担当（IKA-213・219・205・231）は、前後とも同じ diff_turn で回せば影響はない。記録された数（IKA-207・217・222 の表）とこの枝の後の数は、そのままは並べられない。

## 5. 生成（selfplay・poolplay）

同じ種・同じ exe で PYTHONHASHSEED 0 と 1 を回し、record を丸ごと比べた（`searchSeconds`・`engine` を除く、diff_generation と同じ比べ方）。

```
M-B 隠蔽 worlds（本番の既定）   --hide-bench --seed 5       8 局  8/8 同一、40 局 40/40 同一
M-C プール 一様選出             --pool regmc-matchupweb --uniform-selection --seed 7   20 局 20/20 同一
M-C プール 解いた選出           同上に --value value-gen11L --device cpu（一様選出なし） 4 局  4/4 同一
M-B 隠蔽 metagame の相手        --hide-bench --opponents metagame --seed 5   20 局 14/20 同一
```

**依存はある: `--opponents metagame`（と、それを含む `mix`）。** 違った 6 局はどれも相手のチームの特性だけ（Delphox 3・Mawile・Pyroar・Scolipede）で、§2 と同じ `load_chaos` の表。M-C のプール（gen-0 の経路）と M-B の worlds（既定）は一致した。worlds でも、チームの記録に特性が無い 1 体（「ability recorded as the mega forme's, so drawn from usage」の Charizard）は同じ表から引くが、Charizard は観測された種族なので表の順は hash に依らない。直していない（本番の経路。別課題の候補へ）。

## 6. 別課題の候補

* **`load_chaos` の特性の表を図鑑の順で作る**（`src/pokeuraou/priors.py`、`legal_ability_ids` を set で回している 1 行）。`--opponents metagame`・`mix` の生成と、`load_chaos` の表を引くほかの道具が PYTHONHASHSEED に依らなくなる。直すと同じ種の局が変わる（metagame の 20 局で 6 局くらい）ので、本番に入れる時期は調整役の判断。直したら diff_turn・diverge_report の `hash_free_prior` は何もしなくなる（消してよい）。
* 生成の既定の起動（generate_queue など）が PYTHONHASHSEED を固定しているかは見ていない。M-C プールと worlds の経路は今回の標本では hash に依らなかった。
