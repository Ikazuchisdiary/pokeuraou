# IKA-411 メガシンカ後に裏の決定化が増える不具合の疑い

Notion: https://app.notion.com/p/3ec4b8acaa6c81ddac53e35dfaa0820a

## 問い

IKA-410 の打ち直しで、相手のフラエッテ（えいえんのはな）が T1 にメガシンカした後、裏の決定化が 6 → 10 に増えた例が 3 つあった。
見えた体の持ち越しで、メガシンカ後の種族を元の体と同じと見ていないのではないか。

## 答え

不具合だった。ただし「見えた体」の持ち越し（IKA-117 の同一性）は正しく、落ちていたのは**見えた体を 6 体の表（sheet）に当てる所**。

- `selfplay._make_pokemon` が `base_species` に図鑑の `baseSpecies`（表示名 "Floette"・"Meowstic"）を入れていた。
- Showdown の正規形（`position.ts` の `baseSpecies: dex.species.get(set.species).id`）は set の種族 id で、メガシンカの後もそのまま（オラクルで確認、下）。
- `hidden.shown_species` は「盤の種族」と「base_species」で表の体を裏の候補から外す。メガシンカの後は `floettemega` と `floette` のどちらも表の `floetteeternal` に当たらず、えいえんのはなが裏の候補に戻る。
  - 裏が 2 枠: 決定化 6 → 10（うち 4 つはフラエッテが 2 体いる、Species Clause で起きない世界）。裏が 1 枠: 3 → 4。
  - さらに、選出の均衡から作る裏の重み（`bench_weights`）は、見えた体に `floetteeternal` が無いので、どの決定化にも重みを付けられない（キーが 3 体組になる）。`completions` は重みが全部 0 なので**黙って一様**に落ちる。「explains nothing」の注記も出ない。
  - 候補集合の順位付けは一番重い決定化から作るが、一様なので列挙の先頭（存在しない世界のことがある）から作っていた。
- M-C のメガ 82 組（石ごと）を port で実際にメガシンカさせて調べ、壊れるのは **Floette-Eternal（フラエッテ（えいえんのはな））と Meowstic-F（ニャオニクス♀）の 2 つだけ**。ほかの 80 組は図鑑の baseSpecies が set の種族と同じなので壊れない。メガ以外の戦闘中のフォルム変化（ギルガルド・ミミッキュ・イルカマン・モルペコ・ポワルン）は、どれも図鑑の baseSpecies が元の種族と同じで、壊れない。
- 直し: `_make_pokemon` の `base_species` を set の種族 id にする（1 行。`position.ts` と同じ形）。

## 6. 対戦評価の口（旧規則を片側に戻す）

局面は両席で共有なので、直す前と後を対戦評価で比べるために、片側の信念だけ旧規則で作る口を足した（IKA-141 の形、調整役の承認 10/1）。

- `play_game(dex_base_belief=(a, b))`・`PoolArm.dex_base_belief`・`tools/pool_match.py --dex-base-belief / --baseline-dex-base-belief`。
- 旧規則の側は、相手の裏の信念（行動の手番・交代・自分交代の 3 か所）を、相手のメガの base_species を図鑑の baseSpecies に戻した局面（`selfplay._belief_view`）で作る。メガでない体は、どちらの規則でも species で表に当たるので書き換えない。何も隠れていなければ局面そのもの。
- 記録に `dexBaseBelief`・`dexBaseRewrites`（旧規則が信念を変えた数）を書き、ワーカーは席ごとに出す（旧規則が届いた陽性対照）。
- `--pairs-with SPECIES...`: どちらかの構築にその種族がいる組だけを引く（記録の組番号は pool.pairs のまま）。

## 別課題の候補

- ランクマの画面（IKA-407）の 2 か所が、えいえんのはなを図鑑の baseSpecies で読む:
  - `rankedposition.mega_stone("floetteeternal")` が None を返す（`floettite.megaStone` の鍵は "Floette-Eternal" で、図鑑の baseSpecies "Floette" と合わない）。メガシンカを見た相手のえいえんのはなに石を付けられない（確かめたのは関数の戻り値だけ）。
  - `rankedboard.make_game` が相手の先発を `to_id(reg.species[s].base_species)` で作る。えいえんのはなが先発だと `floette` になり、`bench_weights` の先発の条件（表と 2 体が当たること）に当たらない（読んだだけで、走らせてはいない）。
- 直す前の記録（gen-0〜4）を読む道具（qhead・q_teach・analysis）は、記録の局面の base_species（"Floette"）で決定化を作り直すので、記録と同じ（壊れたままの）決定化を再現する。直したコードで `qhead.decision_views` を局 140281 の行動の手番 9 つに当てて、9 つとも記録の rankViews と合った（T2・T3 は存在しない世界 raichu・floetteeternal のまま。`C:/tmp/ika411/qhead_check.py`）。つまり gen-3・gen-4 の記録から作る Q の教材は、その手番では存在しない世界の局面を含む。直した後の記録とは綴りが違う（shownIdentities が `floette` か `floetteeternal` か）。
