## 1. 何を変えたか

### 1.1 ライブラリ

* `play_game`・`_menus`・`generate_pool`・`PoolArm`・`analysis.Settings` の `rank_fill` の既定を `None` にした。`play_game` と `_menus` は席ごとに
  `resolve_rank_fill(fill, 葉の順位付けか)` で決め、`PoolArm` は作るときに決める（`__post_init__`）。「葉の順位付けか」は `rank_by_leaf` で、方策（policy）があれば偽
  （方策は葉の順位付けに優先するので fill を読まない）
* 名指しが無い葉の順位付けは q-nocover。ライブラリは Q を自分で読まないので、Q が入っていなければ最初の候補集合で `qrank.installed` の文言で止まる。refs2 に黙って落ちる所は、ライブラリから無くなった
* 損傷の見積もりで並べる条件（と方策の条件）は、名指しが無ければ今の印 `DEFAULT_RANK_FILL`（refs2）のまま。記録に `rankFill` が付かず、バイトは前と同じ（問い 5）
* `search.ROSTER_RANK_FILL = "refs2"` を足した。M-B のロスタの経路の fill で、M-B には Q が無い
* `search.py` の説明に、refs の仕組みを「名指しでだけ打つ研究用」として残す理由を書いた（M-B、Q の無い人の局、HP 比の評価モデルと torch の無いテスト、refs2 で打った記録の作り直し）

### 1.3 人と打つ道具・検討の落とし先（問い 2、3.3 の疑い）

`tools/play_human.py` に `install_menus` を置き、`tools/analyze.py` も同じ関数を使う。名指しが無いとき:

* Q のファイルがある・評価モデルの encoder がある → q-nocover（前と同じ）
* どちらかが無い → 注記して refs2（前と同じ。定数の名前を `NO_Q_FILL` にした）
* **Q が評価モデルの語彙と違う → 注記して refs2**（新しい）。前は `LocalQ` の `ValueError`（推論サーバなら `RuntimeError`）で止まっていた。どちらも
  `qrank.QVocabularyError`（`ValueError` と `RuntimeError` の両方の子）にしたので、前の型を捕まえていた呼び出し元はそのまま捕まえる

名指し（`--rank-fill q-nocover`）なら、語彙が違えば今までどおり止まる。

**疑いの確かめ**: 計画の 3.3 では「M-B の評価モデルで起動すると止まる」と読んだが、動かすと止まらなかった。master c7aecfa の `play_human.py` を
`--value value-gen11L.pt`（M-B）で `--q-model q-mc0.pt` を置いて回すと、局は q-nocover で打たれた（記録の `rankFill` q-nocover・`qModel` q-mc0.pt）。
encoder は評価モデルからではなく構築プールのレギュレーション（M-C）から作るので、語彙は Q と合う。語彙が違うのは、構築プールが Q と別のレギュレーションのときだけ。
それを実物で確かめた: 本物の `q-mc0.pt` を M-B のロスタのレギュレーションの encoder で `install_menus` に通すと、名指し無しは
`('refs2', [])` と注記「q-mc0.pt reads another vocabulary than this encoder's」、名指しの q-nocover は `QVocabularyError` で止まる（`C:/tmp/ika341/probe_vocab.py`）。

## 6. 限定

* ライブラリを直に呼ぶ新しい道具は、葉の順位付けなら Q を入れる（`qrank.install`）か fill を名指しする必要がある。名指しも Q も無ければ、最初の候補集合で止まる（黙って refs2 にはならない）
* `tools/rank_fill_menus.py` は `--played` の既定が refs2 のまま。Q を読まないので q の fill を打つ局は作れない（研究用、前と同じ）
* 記録の印（`rankFill` を書かない = refs2）は残した（問い 5）。損傷の条件と M-B の記録は、`rankFill` が無いことで refs2 を表す
* M-B の局の一致は一様選出（`--uniform-selection`）で取った。選出 book を使う M-B の生成は回していないが、book は fill の経路に関わらない

## 7. 別課題の候補

* q-nocover の順位付け（Q の行列の解に対する候補の値）も `--record-rank-scores` で書く。今は止まるだけ（IKA-278 の記録は refs の順位付けのもの）
* `tools/generation_match.py --help` が argparse の書式で落ちる（`ValueError: unsupported format character ' ' (0x20) at index 233`、help の中の `%`）。前からある
* 生成の記録に Q のファイル（`qModel`）を書く（IKA-338 §7 の候補のまま）
* ロスタの道具の KNOWN_DRIFT（bench_prior・sheets が足りない 8 つ）は今回触っていない
