# IKA-465: CI を速くする

始点は origin/master の 522e0ca（2026-11-27）。ユーザーの依頼は「ci遅すぎるのであとで改善したいね」（2026-11-27）。

## 要点

* master の CI の 1 回は変更前に 1,105〜1,252 秒かかった（緑の 4 回）。取り込む commit は、キャッシュが当たった 2 回で 464 秒と 822 秒だった。差はランナーごとの pytest の速さの違いから来ている。
* 変更後は build の約 5 分と learn の職の長さが実行の全体から消えた。残りはほぼ suite の pytest である。
* 文章だけの push は、親の commit の CI が緑なら suite と learn を飛ばす。親の実行が終わっていれば、その push の実行は 17 秒で終わった。
* master では commit ごとに別の concurrency の group にし、どの実行も取り消さないようにした。11/26 からの master の 60 回のうち 25 回が取り消されていた。
* 名指しした検査が走ったという約束は保った。省いた検査と、その理由は ci.yml の冒頭と下の 3 節に書いた。

## 2. 変えたこと

| 変更 | 中身 |
|---|---|
| learn の範囲 | `tools/ci_torch_tests.py` が挙げるファイルだけを回す。torch という語を含む `tests/test_*.py` で、今は 42 ファイル |
| learn の範囲の確かめ | suite が、torch で飛んだテストがすべて learn のファイルにあるかを確かめる（`ci_torch_tests.py --check`）。無ければ suite が赤になる |
| 文章だけの push | 新しい職 `changes` が push の差分を見る。`*.md` と `records/` だけなら、親の commit の CI を待つ。親が緑なら suite と learn を飛ばす。赤・取り消し・見つからない・40 分で終わらないなら全部回す |
| lint | `tests/test_line_endings.py` を足した。文章を読むテストはこれだけで、文章だけの push でも走らせるため |
| build のキャッシュ | Showdown・sim-bridge・port の build の結果を、入力のハッシュをキーにして保存し、当たれば build を飛ばす |
| port のキャッシュ | キーは `rust/**`・`configs/regulations/**`・`configs/vocab/**` のハッシュ、HiGHS の commit、`rustc -vV` と `g++ --version`、OS。configs の 2 つは `cargo test` が実行時に読む（`moves_unit_tests.rs` が規則の dump を読み、`Reg::load` が vocab の順を読む）。保存は suite の `cargo test` が通った後だけ。当たれば build と `cargo test` を飛ばし、exe を `touch` する（`rustnode` は exe が `rust/src` より古いと止まる）|
| 取り消し | master では group に commit の SHA を入れ、commit ごとに独立に走らせる。ほかのブランチはブランチごとの group で、今までどおり取り消す。GitHub の group は走る 1 本と待つ 1 本しか持てず、3 本目が来ると待つ 1 本が取り消される。そのため `cancel-in-progress: false` だけでは取り込みが取り消され、次の実行も前の実行の終わりを待つ |

ci.yml の冒頭の learn の説明には、torch で飛ぶ検査の数を書かないことにした。数は suite の `--absent torch` の 1 か所だけに置く。IKA-464 が torch の数を 30 から 29 に変えても、冒頭の説明は直さずに済む。

`changes` が親の CI の緑で判断してよい理由は次のとおり。文章だけの push では、テストが読むコードは親の commit と同じバイト列になる。親の実行が緑なら、同じコードで suite と learn が通っている。親の実行も文章だけで飛ばしていた場合は、その親の判断を順にたどる。

## 3. 省いた検査と理由

* learn は、torch を含まないファイルのテスト（2,837 件の大半）を torch のある環境で回さなくなった。これらは suite で torch なしに通っている。torch があると動きが変わる src の箇所を探した。`importlib.util.find_spec("torch")` を使うのは `rustnet.py` の 1 か所だけで、Windows の DLL の場所を探すためのものだった。torch を含むファイルは、docstring で「torch なし」と書いたファイルも含めて learn に入る。
* port のキャッシュが当たった実行は `cargo test` を回さない。同じキーで保存した実行は、同じ Rust のソース・HiGHS・コンパイラ・`cargo test` が読む configs で `cargo test` を通している。キーに入れたのは grep で見つけた入力だけで、`cargo test` が読むほかのファイルや環境変数を漏れなく調べたとは言えない。`rust/src` の中で `std::fs` で読むのは、規則の dump と vocab の順のほかに、引数で渡すファイル（main.rs・residual.rs）とテストが自分で書く一時ファイル（rnet.rs）だけだった。
* 文章だけの push は suite と learn を回さない。同じコードの親の実行が緑であることを `changes` が確かめる。

## 6. 選ばなかった案

| 案 | 理由 |
|---|---|
| pytest の worker を 4 にする（`-n logical`）| suite の pytest は 2 worker の 524 秒に対し 365〜428 秒だった。ただし 4 回のうち 1 回（45970087506）で `tests/test_timing.py::test_a_part_is_charged_its_child_s_cpu` が落ちた。子のプロセスが壁時計で 0.4 秒回る間の CPU を 0.4 秒と見込むテストで、0.24 秒と読んだ。物理 2 コアに 4 worker を載せると、時計のテストの CPU が壁時計より少なくなる。同じ形のテストは `test_timing.py` にほかにもあるので、2 worker のままにした |
| pytest を matrix で複数の職に分ける | 変更後の実行の全体は suite の pytest（433〜794 秒）で決まるので、次に効く案である。2 つに分ければ 3〜6 分縮む見込みで、試していない。skip の監査が分けた junit を合わせて数える形に変わり、監査を別の職に移すことになる。IKA-464 が同じ時期に `--absent` の数を変えるので、ci.yml の変更を小さく保つために今回は見送った |
| `paths-ignore` で文章だけの push を回さない | 実行そのものが起きないので、親が赤のときも緑に見える。lint も回らない |
| learn をやめて suite に torch を入れる | suite は「torch なしで解析の道が動く」ことも確かめている。torch を入れると、解析の道が torch に頼り始めても気づけない |
| 遅いテストを軽くする | 上位の梯子のテストは IKA-464 が Rust に移す途中なので触らなかった |
| Rust の release の設定（lto・codegen-units）を CI で軽くする | テストする exe が製品の exe と違う設定になる。port のキャッシュで足りた |

## 7. 確かめていないこと

* master のキャッシュは試験用のブランチと分かれている。取り込んだ後の master の最初の実行は、Showdown・sim-bridge・port をすべて build する。
* master の group を commit ごとにする設定は、master で試していない。試験用のブランチでは、ブランチごとの group で取り消しが働くことだけを見た。
* port のキーに configs を足し、group を変えた後の ci.yml は、試験用のブランチで 1 回だけ走らせた（45976819646、緑、996 秒）。キーが変わったので port は外れて build した。configs だけを変えた commit でキーが外れることは試していない。
* 文章だけの push が親を待つ経路は、別のブランチの同じ commit の実行を待つ形で確かめた（45968796700）。master の上の同じ順の push では試していない。
* 一度に 300 ファイル以上を変えた push の扱い（全部回す）は試していない。
