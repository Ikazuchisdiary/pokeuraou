## 1. 入れたもの（既定は変えない）

### 1.1 ラベル（`deepen.deepen_spec`）

`h` の後に 2 つの接尾辞を足した（順は `…h` → `c<k>` → `g<L>`。例 `m1200sallhc6g16`）。今までのラベルは同じ意味（`child_q`・`levels` は None）。`b<N>…` は精緻化しないので、どちらも取らない（止まる）。

* **`g<L>`（深化の柵）**: `deepen.MAX_LEVELS`（8、根を入れて深さ 9）を L にする。与えたときだけ、決定の記録の `deepened[side]` に次を書く
  （無ければ一字も変わらない。数えはいつも取り、計器 `deepen.lines.*`・`deepen.stop.*`・`deepen.guarded` に出る）:
  * `stop`: 深化が止まった理由。`budget`（予算を使い切った）/ `exhausted`（得をする歩が柵の内に無い）
  * `lines`: 深化した筋（木の終わる枝）ごとの止まり方。`ended`（局の終わり）/ `decided`（歩に値するセルが無い、または親のセルが決着して届かない）/
    `guard`（柵の深さで、まだ歩に値するセルがある）/ `budget`（柵の内で、歩に値するセルが残ったまま予算で止まった）
  * `guarded`: 柵の外のセルが、実際に取った歩のセルより優先度が高かった歩の数（= 柵が選びを変えた歩）。`_best` は境界の上のノードを全部開くので、この数は正確
* **`c<k>`（子のメニューを Q で）**: 精緻化した 1 セルの子（上位 3 枝の局面）のメニューを、`narrow` のダメージ順の 8 本の代わりに、
  各側の合法手全部（`qhead.legal_pool`）を Q で解いた q-full の順（根の `q-nocover` と同じ読み）の上位 k 本（覆いなし）にする。
  **1 歩の子の Q はまとめて 1 回の順伝播**（`qrank.LocalQ.batched`・`RemoteQ.batched`）。記録に `childQ`（順伝播の回数）・`childRanked`（並べた子の数）
* 配管: `search(levels=, child_q=)`、`belief_solve` の `deepen` の辞書、`selfplay` の `how`、`humanplay.Agent(max_levels=, child_q=)`・`tools/play_human.py --max-levels --child-q`、
  `tools/pool_match.py`・`tools/selfplay.py` は `c<k>` のラベルにも Q を入れる。pool_match の echo に `children's Q N passes (M children)` と `lines {...}`

### 1.2 複数局面の Q の口（データの形の決まりどおり、JSON でない）

* `qhead.q_matrices(net, requests, device)`: 局面を積み、各側のプールを最長にゼロで詰めて **1 回の順伝播**。行・列は自分の手と自分の局面しか読まないので、
  詰め物は本物のセルを変えない（最後の桁は束の形で動きうる）。同じ束なら同じ答え（テストで確認）
* 推論サーバの op `q_batch`（`inference._serve_q`）: 配列は `q_many` と同じ共有メモリの配置、答えも共有メモリ。要求の行は小さな制御行だけ。
  サーバの Q の腕（`qrank.served_q`）に `batch` を足した（eager。グラフには乗らない）

### 1.3 テスト（`tests/test_deepen_guard.py`、新規 11 本）

ラベルの読み／柵が木を抑え（柵 1・2 で深さ ≤ 柵 + 1）、筋の数が木の終わりの数と一致し、柵で止まった筋と柵が変えた歩が出ること（陽性対照）／

## 5. 結論: 固定の配分（IKA-330 の `plan_move` と IKA-333 に渡すもの）

* **打ち手の時間は、まず幅に使う**（今の `plan_move` の「まず幅、残りを深化」の向きは合っている）。Q のメニュー（q-nocover）でも、同じ CPU で深化だけは幅に 16〜32 Elo 負ける
* **深化を使うなら、入れ替えのオラクル（`s24`）を付ける**: 同じ CPU で深化だけより +14〜+23。`plan_move` の「残りを `h` の深化」は「残りを `s24h` の深化（オラクル付き）」にする
  （人と打つ形では幅が 64 まで開くので、候補は `sall` か「幅 W の残り」。`s24` は幅 12 の根での形。広い根でのオラクルは測っていない）
* **子のメニューを Q で（`c<k>`）は入れない**（今の値段では得が見えない）。一括の順伝播をグラフに乗せて安くしたら測り直す
* **柵（`MAX_LEVELS`）は上げない**（上げると細い筋を深さ 30 台まで追い、同じ時間でセルが 1/3 になる、§2）。45 秒で柵が効いているのは事実なので、
  大きい予算の深化の配分は「柵を上げる」ではなく「優先度に深さの割引を入れる」か「広い根で幅に回す」で直す（別課題）
* 予算点ごとの配分（今の値段・この盤の形。人と打つ持ち時間の秒には IKA-330 の `NODE_TIME` で換算する）:
  * 小（1 局 ≈1.05 CPU 秒、d1@12 の 1.5 倍）: **d1@18**（深化 + オラクルの 12+m50s24h とは並ぶ見込み、目安 −1）
  * 中（≈1.7、2.4 倍）: **d1@26**（深化 + オラクルは目安 −19）
  * 大（≈2.65、3.7 倍）: **d1@36**（深化 + オラクルは目安 −5）
  * どれも「幅だけ」が最善か同等。幅が合法手で頭打ちになった後（人と打つ 5 秒以上ではほぼ全部の手）の残りを、オラクル付きの深化に回す
* 生成（教える側）の配分は別の問い（IKA-73 の形）で、ここでは測っていない

## 9. 別課題の候補

* **深化の優先度に深さの割引**: 柵を上げると `bern/gap` × 枝の重みの継承が細い筋を深さ 30 台まで追う（§2）。子の行列の大きさ（セルの安さ）を値段に入れるか、深さで割り引く。
  45 秒で柵 8 が歩の 69〜86% を変えているので、人と打つ道具（IKA-330・IKA-333）の大きい予算に効く
* **子の Q の一括の順伝播を CUDA グラフに**（`c<k>` の値段、1 回 約 18 ms CPU）。安くなれば §4 の (d) を測り直す
* **広い根（幅 36〜64）でのオラクル**: 人と打つ形は幅が合法手で頭打ちになる。そこで残りを `sall` のオラクル付き深化に回す形を、同じ時間の対戦評価で
* **中の予算の三角形を直接**: 12+m375s24hg32 対 d1@26（目安 −19、腕の違う本の和）。上限 1,000 対で SPRT が決まらなかった S2・M2（+14 前後）を固定の局数で
* **両側の幅 40 以上の対戦評価はホスト RAM の床に当たる**: 大きい予算の値段・対戦評価を片側だけにするか、worker の数を減らす形を決める
