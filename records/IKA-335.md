# IKA-335 pool_match は --baseline を省くと黙って hp-share を相手にする

Notion: https://app.notion.com/p/3e74b8acaa6c81eda984fd59ab6bf4e4 ・ 関連: IKA-296

## 何が起きたか

IKA-296 の対戦評価の駆動は、同じ腕どうしの帰無を回すときに `--baseline` を渡していなかった。
`tools/pool_match.py` は相手の葉が無いと黙って hp-share を相手にするので、帰無のつもりの本が
「B10x2 対 hp-share」になった。担当が気づいて数には使わず、渡す形で回し直した。
測る道具が意図と違う打ち手を作るのは、agent_drift（measurement-lags-generation）と同じ類の穴。

## 直した形: 相手の葉を省けなくした

hp-share を相手にするのは「その旗を書いたときだけ」にした。`--selection-book` を省くと止まる
（`--uniform-selection` で本気だと言う）のと同じ形。

- `tools/pool_match.py`（M-C の対戦評価の打ち手）
  - `--baseline-hp-share` を足した。相手に葉を持たせないことを明示する旗。
  - `--baseline`（ここで読む）・`--baseline-inference-arm`（サーバ）・`--baseline-hp-share` のどれも無ければ、
    引数の検査で止まる（argparse の error、終了コード 2）。エラーは 3 つの旗を名指しする。
  - `--baseline-hp-share` と葉を同時に渡しても止まる（どちらかが意図と違う）。
- `tools/match_queue.py`（対戦評価の駆動。M-C は `--pool`、M-B は generation_match）
  - 同じ `--baseline-hp-share` を足した。`--baseline` も `--baseline-hp-share` も無ければ、出力のディレクトリを作る前に止まる。
    ただし `--` の後ろ（ワーカーに渡す尾）に `--baseline` か `--baseline-inference-arm` があれば、名指ししたものとみなす。
    IKA-307 の対戦評価は `-- --baseline-inference-arm value` で帰無を組んでいるので、その形はそのまま動く。
  - `--pool` のときは、`--baseline-hp-share` を各ワーカーに渡す。
  - M-B（`--pool` なし）のときは、generation_match の相手は尾の `--objective`（既定 hp-share）になる。
    `--baseline-hp-share` と `--objective faints` が並んだら止める。

明示した呼び出し（`--baseline` / `--baseline-inference-arm` を渡すもの）は、ワーカーに渡る引数も
打つ局も変わらない（下の検査で、渡る引数を確かめた）。

### echo と記録について

相手の腕の中身は、もともと echo の先頭に腕ごとに 1 行ずつ出ていた（`tested arm: leaf ... / width /
ranking (fill) / bench drop / deepen / ends / depth / selection / belief`。Q は `Q: ...` の行）。
局の記録にも、provenance の `leaves` に両席の葉（hp-share を含む）が入っている。
つまり情報は出ていたが、省略が既定として通ってしまっていた。今回は echo を増やさず、省略そのものを拒否した。

## 入口の洗い出し（対戦評価の腕を組む道具）

| 道具 | 省くと黙って決まるもの | 扱い |
|---|---|---|
| `tools/pool_match.py` | 相手の葉 → hp-share | **拒否にした**（`--baseline-hp-share` で明示） |
| `tools/match_queue.py` | `--baseline` → M-C は hp-share、M-B は `--objective` | **拒否にした**（同上。尾で名指ししても可） |
| `tools/generation_match.py`（M-B のワーカー） | `--baseline` → `--objective`（既定 hp-share） | 変えていない。M-B の対戦評価はこの道具の `--objective` が「相手の評価軸」という明示の旗で、committed の呼び手（`genmatch_parallel.sh`）は `--baseline` を渡している。駆動の match_queue 側は今回ふさいだ |
| `tools/profile_stages.py match` | `--baseline` → `value-gen10.pt` | 変えていない。計時の道具で、match_queue に必ず `--baseline` を渡している |
| `tools/oneshot/served_matches_direct.py` | `--baseline` → `value-gen8.pt` | 変えていない（oneshot は当時の道具） |
| `pool_match` の `--rank-leaf` / `--baseline-rank-leaf` | 省くと両腕とも damage の順位付け（M-C の生成は葉で順位付けする） | 変えていない。echo の先頭に `damage ranking` と出て、片側だけなら腕の名に `@leafrank` が付く。**別課題の候補**（下） |
| `pool_match` の rank-fill・deepen・bench-drop・depth・limit | `DEFAULT_RANK_FILL` / `DEFAULT_DEEPEN` / `DEFAULT_BENCH_DROP` / 1 / 12 | 生成と同じ既定を共有しているので、黙って違う打ち手にはならない。`--baseline-limit` は `--limit` を引き継ぐ |
| `pool_match` の Q | q の fill・q<k> の deepen は Q の旗が無いと `qrank.install_from_args` が止める | 既にふさがっている |
| width_match・cycle_match など M-B の古い道具 | `--objective` と narrow の既定 | agent_drift が DRIFTED と一覧している既知の状態で、今回の対象外 |

## 検査

- 新しいテスト `tests/test_explicit_baseline.py`（9 本。torch・CUDA・data は要らない。port の exe は要る。CI の skip の予算は変わらない）
  - ワーカー: 葉を省くと終了コード 2 で止まり、3 つの旗を名指しし、局を 1 つも書かない。
    `--baseline-hp-share` と葉（`--baseline` / `--baseline-inference-arm`）の同時指定も止まる。
    `--baseline-hp-share` なら相手席の葉が hp-share になり、echo の先頭に両腕が出る。
  - 駆動: `--pool` でも M-B でも、`--baseline` が無ければワーカーを 1 つも組まずに止まる。
    `--baseline-hp-share` は M-C のワーカーにだけ渡る。`--baseline b.pt` は前と同じく渡り、
    尾の `--baseline-inference-arm value`（IKA-307 の形）も通る。矛盾する 2 つの形は止まる。
- 陽性対照: 新しいテストを master の `tools/pool_match.py`・`tools/match_queue.py` に対して回すと、
  9 本のうち 8 本が落ちる（C:/tmp/ika335/positive_control.txt）。落ち方も確かめた。ワーカーは
  `DID NOT RAISE SystemExit`（hp-share を相手に局を打ち切った）で、駆動は「名指しの無い対戦評価にワーカーが組まれた」。
  通る 1 本は、明示した呼び出しが前と同じに動くことを見るテスト（`--baseline b.pt` と尾での名指し）。
- 既存のテストのうち、省略に頼っていた 2 本に `--baseline-hp-share` を足した。
  `test_pool_match.py::test_the_worker_writes_records_that_pair_up`（hp-share が相手なのを確かめるテスト）と、
  `test_sprt.py::test_match_queue_registers_its_test_before_the_first_game`。
  関係するテスト（test_explicit_baseline・test_pool_match・test_sprt・test_bench_default・test_aivat）はローカルで通った。
- 手元の CLI 確認: `pool_match.py --pool x --value a.pt --hide-bench` は argparse のエラーで止まる。
  `match_queue.py --pool <regmc-matchupweb> --value a.pt --hide-bench --served` はサーバを立てる前に止まり、`--out` も作らない。
- ruff、agent_drift --check（rc 0。DRIFTED の一覧は master と同じ）、port_gate_audit --check、port_coverage --check は通った。

## 機械時間

cargo build --release（heavy.py、8 コア、38 秒）と、上のテスト（1 コア、数十秒）だけ。専有の仕事は無い（見込み 0 分、実際 0 分）。

## 別課題の候補

- `pool_match` / `match_queue --pool` では `--rank-leaf` を省くと、両腕とも damage で順位付けする。M-C の生成は葉で順位付けする。
  今の対戦評価の駆動はどれも渡しているが、省けば「生成が打たない打ち手」どうしの対戦評価が黙って走る。
  agent_drift の poolplay の行は play_game の呼び出しを見ていて、この CLI の既定は見ていない。
  既定を生成に合わせるか、省略を拒否する。
