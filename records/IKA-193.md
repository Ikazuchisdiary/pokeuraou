答えた問い: **対戦評価の対の得点から、乱数（と混合から引いた手）の運を AIVAT の形で引くと、平均を動かさずに

## 0. 止め方の登録（計算の前に書いた）

この節は、補正後の得点を 1 局も計算する前に書いてコミットした。

* **対象**: IKA-292 の対戦評価 5 本（`C:/tmp/ika292/board/` の d2w5-vs-w31・d2-vs-w42・d2w5-vs-w24・m100-vs-w14・
  d2-vs-d1-w12）。書かれている完全な対を全部使う（SPRT で止めた後に書かれた対も含む。`tools/paired_result.py` と同じ対）
* **評価器**: value-mc0x2（value-mc0.pt と value-mc0-s1.pt の平均。M-C の出荷の葉）。CPU の torch で固定
* **補正**: 各 move 決定の、打った組の `Budget.exact()` の分岐で c_t = V(着いた枝) − Σ_k p_k V(枝 k)。
  途中交代で止まった枝は中立（止まらない枝の加重平均）に置き、再開した残りのターンを別の段として補正する
* **検定（補正後）**: 正規近似の GSPRT（fishtest の `LLR_alt2` を連続値の対の得点にそのまま使う形）
  LLR_n = n (s1 − s0)(2 x̄_n − s0 − s1) / (2 σ̂²_n)、x̄・σ̂² は n 対目までの平均と母分散（分散が 0 の間は LLR 0）。
  H0: Elo 0、H1: Elo +10、α = β = 0.05、Wald の境界 ±2.944。対は game index の順（`sprt.StopWhenDecided` と同じ順）。
  最初に境界を出た対で止める。出なければ「決着せず」
* **比べる相手**: 同じ対の生の得点に、(a) 今の三項の GSPRT（`sprt.llr`）と (b) 同じ正規近似の GSPRT を当てる
* **止まる対の数の分布**: 1 本の道は運で大きく動くので、各対戦の対の分布から復元抽出した 2,000 本の道（上限 3,000 対、
  種 193）で、生と補正後の止まる対の数の平均・中央値と判定の割合も出す（`sprt_replay.py --bootstrap` の形）
* **null 対照**: 恒等な腕の対戦（`null-d1w31`・`null-d2w5`・`null-m100`、IKA-292 §1.2 の `p12`・`p24`）で、
  補正後の対の得点が全対で 1/2（|x − 1/2| < 1e-9）であること
* **偏りの検査と除外の規則**: 補正の段を「列挙が厳密（exact）」「max_branches で打ち切り（inexact）」「途中交代の後の段」に分け、
  5 本を合わせた c の平均の 95% 区間を出す。区間が 0 を含まない種類は、補正しない（その段の c を 0 に置いて数え直す）。
  あわせて対ごとの（生 − 補正後）の平均の区間が 0 を含むことを確かめる

### 0.2 段 1 の最初の計算の後、段 2 の計算の前に足した登録

段 1 を上の登録どおりに 1 度計算した（数は §2）。その復元抽出で、登録した正規近似の GSPRT に欠陥が見つかった:
**補正後の得点では、2 対目で止まる道がある**（分散の推定が 2 対で極端に小さくなり、|LLR| が境界を越える）。
効果が −21 Elo の対戦で、1,000 本の道のうち 25〜79 本が 2 対目に逆向き（H1）で止まった（§3.3）。
生の得点（3 値）では起きない。登録した規則の数はそのまま §3 に出し、あわせて次の変更を**段 2 の数を計算する前に**登録する。

* **燃やし込み 30 対**: 正規近似の GSPRT は 30 対目までは止めない（LLR を 0 に置く）。生の正規近似にも同じものを当てる。
  30 は段 1 の復元抽出を見て選んだ（0・30・100 で、30 と 100 は逆向きの停止 0、停止の対の数も同じ）ので、事後の選択である
* **復元抽出の対照**: 補正後の得点の平均は、対戦ごとに生の平均から運で数 % ずれる（§2）。止まる対の数の比が分散だけの効きを
  表すよう、補正後の得点を生の平均に平行移動した系列（recentred）でも同じ復元抽出をする
* **段 2（手番の項）**: 各 move 決定で、両側の記録した混合（`ownPolicy`・`foePolicy`）の台の組 (a, b) すべてを
  `Budget.exact()` で解き、Q(a, b) = 同じ評価器の中立な期待値（段 1 の E と同じ関数。全ての枝が途中交代の組は、止まった局面の
  V の加重平均）。手番の補正 = Q(a*, b*) − Σ π(a) σ(b) Q(a, b)。純粋な決定は 0。replacement は、このデータでは全て純粋なので
  足さない。補正後の得点 = 生 − (乱数の項 + 手番の項)。判定・分散比・復元抽出は段 1 と同じ形で、燃やし込み 30
* **偏りの検査（段 2）**: 手番の項の平均の 95% 区間を 5 本合わせて出す。0 を含まなければ、手番の項は使わない
* 段 1 の計算で見つかった途中交代の照合漏れ（同じ局面の pause が 2 つあり、続きが違う。§1.1）は直してから段 1 も計算し直す
  （乱数の項の数は、段 2 と同じ計算の中で出し直したものを本とする）

## 1. 段 0: 記録した局の各ターンは、exact の分岐に着いているか

## 2. 段 1 と段 2: 分散

評価器は value-mc0x2（CPU の torch、1 スレッド）。どちらの腕の葉とも同じ重みだが、補正の不偏性は評価器によらない。

* **乱数の項**: 各 move 決定の各段で c = V(着いた枝) − E、E = 止まらない枝の加重平均（pause は中立に E と置く）
* **手番の項（段 2）**: 各 move 決定で、記録した両側の混合の台の組を全て exact で解き、Q(a, b) = 同じ中立な期待値
  （全ての枝が pause になる組、たとえば先に動く U-turn は、止まった局面の V の加重平均）。項 = Q(a*, b*) − Σ π σ Q。
  台が 1 組の決定（純粋）は 0。move 決定の 29〜34% が純粋。replacement 決定は 20,120 のうち 40（0.2%）だけが混合で、
  足していない（補正しない項は常に不偏）。self-switch の選択は argmax なので運が無い
* 補正後の対の得点 = 生 − (項の和)（試す腕が side 1 なら符号を逆に。`aivat.arm_score`）

* **予想は外れた**: 対の SD を 30〜60% 削る予想に対し、乱数の項だけで 9〜13%、手番の項も足して **19〜25%**。必要な対は

```
  手番の項（混合の決定）                 39,031   −0.00028    ±0.00089      −0.62
  対ごとの 生 − 補正後（乱数の項）          3,498   −0.00016    ±0.00477      −0.07

```

* **どの種類も区間が 0 を含むので、除外はしない**。打ち切り（近似の列挙）の決定も偏らない。理由は作りにある: ゲームは打ち切った
  分布から引いているので、その分布での期待値はゲームに対しては厳密（AV-AIVAT の「期待値が近似なら偏る」は、ゲームが引いた分布と
  補正が引く分布が違うときの話で、ここでは同じもの）。手番の項も、記録した混合がそのまま抽選の分布（`_sample_index`）
* **null 対照**: 恒等な腕の 5 本（null-d1w31・null-d2w5・null-m100・p12・p24、計 600 対）で、両方の補正後の対の得点が全対で
  1/2（最大の |x − 1/2| は 5.6e-17、浮動小数の 1 ulp）。同じ局を席を入れ替えて打つので、席ごとの補正が符号だけ逆になって消える。
  null の手番の項の平均は null-d1w31 で z −2.02 だが、null の 200 局は 100 局の複製なので z は √2 倍に出る（−1.43 相当）

## 5. 裏非公開と評価器が見る局面

* 評価器は**真の局面**（裏も含む）を見る。補正の不偏性は評価器によらない（どんな V でも、ゲームが引いた分布での期待値を引く限り
  平均 0）ので、真の局面で問題ない。事後の採点で、どちらの腕の探索にも渡らないので、情報の漏れにもならない
* 分岐の一致に裏の扱いは効かない: 局面を進めるのは真の局面の port（裏の決定化は各腕の探索の中だけ）。裏非公開で効くのは
  途中交代の選択（各腕が自分の信念で選ぶ）だけで、記録した選択で再開するので一致は 100%（§1.1）
* 公開情報だけの評価器（裏の決定化で平均した V）も不偏だが、分散の減りは小さくなる見込み（測っていない）。対局中に腕が
  自分で補正を計算するなら公開情報に限る必要があるが、対戦評価の採点はその必要がない

## 6. 費用と、対戦評価の道具への組み込みの提案

今の `tools/aivat.py` は事後の計算で、1 局あたりの CPU（CPU の torch、1 スレッド、8 本並列の壁時計 × 8 ÷ 局数）:

```
  対戦                 乱数の項だけ   両方     局そのものの CPU（IKA-292 §1.2 の対戦評価の形、2 腕の平均）
  d2w5@12 対 d1@31     0.56 s        3.61 s   2.34 s
  m100@12 対 d1@14     0.57 s        4.06 s   1.03 s
  d2@12 対 d1@42       0.57 s        3.91 s   約 4.07 s（d1@42 は d1@40・44 の間）
  d2w5@12 対 d1@24     0.58 s        3.45 s   2.05 s
  d2@12 対 d1@12       0.55 s        2.83 s   2.70 s
```

同じ答えを出す CPU の比 = 分散比 ×（1 + 補正 ÷ 局）: 乱数の項だけで 0.92〜1.24 倍、両方で 1.27〜3.27 倍。
**今の形では、減る対の数で補正の費用を払えない**（計時は ABBA でなく、局の CPU は別の日の別の測り方なので目安）。
費用の大半は Python 側（枝 1 段あたり平均 70 の局面の JSON の読み込みと符号化、手番の項は台の組ごとに exact のターン）。

**提案（この課題では既定を変えていない）**:

1. **補正をワーカーの中で、すでにある数から作る**:
   * 乱数の項: `_advance_turn` は打った組の exact の重みをすでに持っている。同じ組を符号化の道（`port.batched_payoff` の exact 版、
     葉は推論サーバ）で 1 セル評価すれば E が出て、着いた枝はその場で分かる（照合が要らない）。追加は 1 ターン 1 セル
   * 手番の項: 探索の行列 M[a, b]（matrix の予算、その腕の葉）はすでに全メニューの組にある。Q に使えば追加の費用は 0。
     どんな固定の Q でも不偏なので正しさは保たれるが、分散の減りは exact の Q より小さいはず（測る）
   * 局の記録に `aivat: {C, A}` を書く
2. **`match_queue.py --sprt` に補正後の得点の検定を足す**: 正規近似の GSPRT に**燃やし込み 30 対**（§3.3。燃やし込みの無い形は
   誤り率が 6〜28% で使えない）。既定は三項のままにして、`--sprt-aivat` のような旗で並べて走らせ、数本で判定が三項と一致し、
   対の数が 0.6 倍前後になることを確かめてから既定を考える
3. それまでは、`aivat.py report` で終わった対戦評価の区間を狭める（点推定の本、IKA-89 §2 の「大きさを測る対戦」）用途に使える。
   ただし費用は局と同じくらいかかる
