# IKA-292: 裏非公開の制限深さ 2 と deepen（m100）を、同じ費用の深さ 1 と対戦評価で比べた —— 深さ 2 は同じ設定（幅 12）なら深さ 1 に勝つ（SPRT H1、Elo +24.8 [+10.8, +38.9]）が、同じ CPU なら 3 本とも幅を広げた深さ 1 に負ける（深さ 2・w5 対 幅 31: H0、−26.9 [−44.9, −9.0]。深さ 2・none 対 幅 42: H0、−17.6 [−33.3, −2.0]。m100 対 幅 14: H0、−15.7 [−29.3, −2.2]）

2026-09-25。担当 IKA-292（worker）。master 3c0b72a（IKA-107・IKA-289・IKA-295 の取り込み後）から切った `ika-292-equal-cost-depth-board`。
コードは変えていない（記録と GENERATIONS.md だけ）。

答えた問い: **裏非公開（今の生成と対戦評価の条件）で、制限深さ 2（IKA-111、`--depth 2 --solve-restricted`）は、
同じ費用の深さ 1 より強いか。あわせて、IKA-33 の deepen（m100）も同じ費用で並べる。**
答え: どちらも強くない。同じ 1 局の CPU を幅に使った深さ 1 に、どの組でも SPRT(0, 10) の H0 で負けた（区間の上端も 0 未満）。
深さ 2 そのものは効いている（同じ幅 12 なら +24.8 で H1）。公開情報の IKA-12（深さ 2@24 が同じ設定で −11.9）とは違い、
裏非公開では同じ設定で深さが勝つが、その値段（CPU 3〜4.8 倍）なら幅の方が多く買える。

用語: 「裏」＝選出した 4 体のうち場に出ていない 2 体。「対戦評価」＝盤。「裏の決定化」＝完成形（completion）。
腕の書き方: `d2w5@12` = 深さ 2・制限つき・`--bench-drop w5`・幅 12、`d2@12` = 同じで drop なし、`d1@W` = 出荷の深さ 1・幅 W、
`m100@12` = 深さ 1・幅 12・`--deepen m100`。

加えて §1.2 の 13 本（同じ腕どうし、150 局/席）も同じ帰無の形で、`pair_divergence` はどれも動いた対 0（150/150、d1@48 は止まるまでの 62/62）。

## 4. IKA-31（「軽くして深く読む」）への含意

* 今の費用では、**打ち手の時間は深さではなく幅に使う**。深さ 2（none・w5）も best-first の深化（m100）も、同じ CPU の幅に負けた。
  CLAUDE.md の「速さと強さの引き換え」の判定（同じ時間の対戦評価）で、どちらも打ち手の既定にしない
* ただし深さ 2 は同じ設定で +25 なので、**深さ 2 の費用が下がれば答えは変わりうる**。目安: d2w5@12 は、CPU で自分の
  0.67〜0.73 倍しか使わない d1@24（深さ 1@12 の 1.9〜2.0 倍）にも −17.0 で負けた。同じ打ち筋のまま互角にするには、深さ 2 の費用を
  **深さ 1 の 2 倍より下**まで下げる必要がある見込み（今は w5 で 3.0 倍（生成）/ 2.6 倍（対戦評価））。
  幅と Elo の関係を直線と見た粗い見積もりで、測ってはいない
* 「軽くして深く読む」の「軽くする」側は、幅を狭めて深さを買う形では、この対戦評価の範囲では割に合わない。IKA-12 の
  「同じ時間なら幅」は公開情報だけでなく裏非公開でも成り立った
* 生成（教える側）は別の問い（IKA-73 の形: 同じ壁時計で作ったプールから学んだ葉の強さ）で、この課題は答えていない。
  同じ CPU なら幅の広い深さ 1 の方が打ち手として強いので、生成で深さ 2 を使う理由は打ち手の強さからは出てこない

## 6. 別課題の候補

* **葉 対 葉の対戦評価で、サーバの 2 つの腕のグラフのキャプチャが重なって worker が落ちる**（§2.1）。IKA-33 の形（`--baseline` に
  同じ重み）でも起きる。今は局がキューに戻るので結果は書かれるが、run の rc が 1 になり、腕の一方のグラフが止まれば腕ごとの
  サーバの費用も非対称になりうる。直し方の候補: `_Graphs` のキャプチャのロックをサーバ全体で 1 つにする（腕ごとでなく）。
  陽性対照は「2 腕で `--baseline` を付けた 100 局/席の対戦評価で worker が落ちる」（この課題の 3 本で 3/3 起きた）
* **幅の広い深さ 1 の要求（512 行超）が GPU で詰まる**（対戦評価の形で busy 8〜9）: 512 行を超える要求を 512 行のグラフの
  連なりに切る（行数で答えが変わるので、局が変わる。IKA-291 §1）か、アンサンブルの 2 本を 1 回の起動にまとめる。
  打ち手の幅を広げるなら効く
* **d1@31 対 d1@12**（三角形を閉じる。幅の値の大きさ）と、**M-C の裏非公開で幅をどこまで広げるか**（IKA-12 の「幅 48 で止まる」の
  M-C 版、同じ時間の対戦評価で）
* 深さ 2 の費用を深さ 1 の 2 倍以下へ（§4 の損益分岐）: IKA-295 §7 の JSON をやめる・部分ゲームの narrow を port で・LP など
* 深さ 2 の knob（refine 4・passes 2・sub_limit 8・sub_branches 3）を裏非公開・幅 12 で振る（IKA-111 §6 の残り）。
  refine を減らして費用を下げた深さ 2 が、同じ費用の幅に並ぶか
