# IKA-338: データ生成・対戦評価の既定を q-nocover に切り替えた —— 葉の順位付けの候補集合で `--rank-fill` を名指ししなければ q-nocover、Q は `data/models/q-mc0.pt`。Q が無ければ止まる（refs2 に黙って戻らない）。新しい既定の局は、前の master に `--rank-fill q-nocover --q-model q-mc0.pt` を明示した局とバイト一致（データ生成 600/600、スモークテスト 48/48、対戦評価のスモークテスト 48/48）。refs2 は名指しすれば前の既定の局を再現する（48/48）

2026-09-27。担当 IKA-338（worker）。master c72020a から切った `ika-338-qnocover-default`、コードは 8b2e4c4。
きっかけ: IKA-331 の判定（同じ壁時計の構築プールから学んだ評価モデルで q-nocover は refs2 に Elo +3.8 [−6.3, +14.0]、非劣性の SPRT(−10, 0) H1、局は 1.18 倍）と、
9/26 のユーザーの判断（対戦評価と人と打つときは q-nocover）。対戦評価の道具は `agent_drift.py` の決まりで生成と同じ打ち手を作るので、生成と一緒に切り替えた。
出力（実行・比べるスクリプト）は `C:/tmp/ika338/`（コミットしない）。$M/data は読んだだけ。

## 1. 何を変えたか

### 1.1 既定の決まり方

* `search.SHIPPED_RANK_FILL = "q-nocover"` と `search.resolve_rank_fill(given, rank_leaf)`: 名指しした fill はそのまま。名指しが無ければ、葉の順位付けの条件は q-nocover、
  損傷の見積もりで並べる条件は refs2（fill を読まないので、記録に `rankFill` が付かず Q も要らない。前と同じ）
* `qrank.DEFAULT_Q = "data/models/q-mc0.pt"`（リポジトリの根から）と `qrank.default_q()`。`qrank.install_from_args` は、既定の名前の q の fill に Q が名指しされていなければ
  `default_q()` をワーカーで読む（`LocalQ`）。ファイルが無ければ `qrank.missing_q` の文言で止まる（ファイルの場所と、`--q-model FILE` か `--rank-fill refs2` を名指しする道を示す）
* `qrank.tail_wants_default_q(tail)`: 起動の道具（`generate_queue.py`・`match_queue.py`）は `--` の後をワーカーにそのまま渡すので、その尾から各条件の `--rank-leaf`・`--rank-fill`
  （対戦評価の相手は `--baseline-*`）と Q で探る `--deepen` を読み、ワーカーと同じ決まりで「既定の Q が要るか」を出す。尾が自分で Q を名指し（`--q-arm`・`--q-model`）していれば要らない
* **ライブラリの既定は refs2 のまま**: `play_game`・`generate_pool`・`PoolArm` の既定、M-B のロスタの経路（fill を受けない）。これらは Q を持たないので、既定を q-nocover にすると
  Q を渡さない呼び出し（テストの多く）が最初の順位付けで止まる。refs2 の廃止（9/27 ユーザー: 廃止の見込み）は別の段

### 1.2 道具ごと

```
  道具                          名指しが無いとき                                  Q が無いとき
  tools/selfplay.py --pool      --rank-leaf なら q-nocover（ワーカーで Q を読む）   止まる（最初の局の前）
  tools/generate_queue.py --pool  尾が既定の Q を要るなら推論サーバに Q の条件 q を載せ、  止まる（ワーカーを起動する前）
                                ワーカーに --q-arm q（推論サーバなしなら --q-model）
  tools/pool_match.py           各条件: --rank-leaf なら q-nocover                   止まる（最初の局の前）
  tools/match_queue.py --pool   generate_queue.py と同じ                             止まる（ワーカーを起動する前）
  tools/profile_stages.py       --q-model は与えたときだけ渡す（生成の道具の既定が走る） 生成の道具が止まる
  tools/play_human.py・analyze.py  Q があれば q-nocover、無ければ refs2 で注記          注記して refs2（下）
  M-B（ロスタの経路・generation_match.py）  refs2 のまま（fill を受けない）            —
```

* `generate_queue.py` の始めの表示に `Q q-mc0.pt` を足した（局には関わらない）
* **人と打つ道具（play_human・analyze）は注記で落とすまま**にした。理由: 評価モデルが無いときも同じく注記して HP 比の打ち手に落とす道具で、始めに注記を出し、記録（`rank_fill`）に
  実際の fill が残る。人が読む場で止めるより、何で打ったかを見せるほうが使える。データ生成と対戦評価は、黙って別の打ち手になると数字が別の打ち手のものになる（`agent_drift.py` の
  存在理由）ので止める。定数は同じもの（`qrank.DEFAULT_Q`・`search.SHIPPED_RANK_FILL`）を読む
* refs2 は `--rank-fill refs2`（対戦評価の相手は `--baseline-rank-fill refs2`）で今までどおり打てる。Q は読まない

### 1.3 `agent_drift.py`

`play_game` の引数を読むだけでは、fill の既定のずれは見えない（M-C の生成も対戦評価も `poolplay` を通して fill を渡し、どの値かは道具の旗の既定で決まる）。そこで旗の段で見る検査
`resolution_drift` を足した:

* `--rank-fill`・`--baseline-rank-fill` を宣言する道具は、既定が None で、`resolve_rank_fill` で決めること
* `--q-model` を宣言する起動の道具は、既定が None で、`tail_wants_default_q` を読むこと
* 自分の決まりで決める道具は `OWN_RESOLUTION` に理由つきで載せる: play_human（人の局、注記で落とす）、analyze（play_human の打ち手）、profile_stages（生成の道具に任せる）
* 生成のワーカー（`tools/selfplay.py`）が `resolve_rank_fill` を使っていなければ落ちる
* `--check` はこれも見る。前の `pool_match.py`（`default=DEFAULT_RANK_FILL`）に戻すと `DEFAULT pool_match.py` で落ちる（§3 の陽性対照 2）

## 3. テスト（`tests/test_shipped_rank_fill.py`、12 本、torch・CUDA・data は要らない）

* 既定の決まり（`resolve_rank_fill`、`DEFAULT_Q`）と、起動の道具が尾から Q の要否を読むこと
* 生成のワーカー: `--rank-leaf` だけで `generate_pool` に q-nocover が渡り、既定の Q を読む（代役の `LocalQ`）。`--rank-leaf` なしなら refs2 で Q を読まない。
  Q が無ければ止まる（ファイルの場所と `--rank-fill refs2` を示す）。refs2 の名指しは Q なしで refs2
* `generate_queue.py`: 既定の Q をワーカーに渡す（refs2 の名指しなら渡さない）。Q が無ければワーカーを作る前に止まる
* 対戦評価のワーカー: 両条件が q-nocover で打ち、既定の Q を読む。Q が無ければ局を書く前に止まる。`match_queue.py`: 既定の Q を渡す、無ければ止まる
* `agent_drift.resolution_drift`: `default=DEFAULT_RANK_FILL` の道具を見つけ、今の 4 つの道具は通す
* 既存の 2 本（`test_explicit_baseline` の尾、`test_rank_scores` の CLI）は fill が主題ではないので `--rank-fill refs2` を名指しした
* **陽性対照**（前の既定で落ちること、この枝のコピーを壊して回した）:
  1. `SHIPPED_RANK_FILL` を refs2 に戻す: 12 本中 10 本が落ちる（残る 2 本は refs2 の名指しと agent_drift）
  2. `pool_match.py` の既定を前の `DEFAULT_RANK_FILL` に戻す: 対戦評価のワーカーの 2 本と agent_drift の 1 本が落ち、`agent_drift.py --check` が rc 1
* CI の skip の予算は変えていない（新しいテストは torch・CUDA・data を使わない。data の Q は代役）

## 5. 限定

* 生成の記録には Q のファイル名が入らない（前の master の明示でも同じ。`rankFill` だけ）。どの Q で打ったかはワーカーのログ（`Q: q-mc0.pt …`）と推論サーバのログにある。
  対戦評価の記録には `qModel` が入る
* 既定の Q は評価モデル value-mc0 から作った教材で学んだもの（IKA-274 段 3）。世代が進んで評価モデルを替えるとき、Q を作り直すかは決まっていない（IKA-331 §8）
* worktree には data/ が無いので、worktree で既定の生成・対戦評価を回すと Q が無くて止まる（`--q-model` を名指しするか、`data/models/q-mc0.pt` を置く）
