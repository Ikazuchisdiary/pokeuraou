## 1. 足したもの

* `ValueConfig.move_properties`（既定 False）と `move_property_dim`（32）。
  on のとき、`ValueNet` は `qhead.move_table`（IKA-274 の表。import だけで、qhead.py は変えていない）を buffer `move_props` に持つ。
  表の中身は、タイプ・分類・威力・命中（必中の旗）・優先度・変動威力・対象の種類・フラグ 12 種・追加効果の要約 14 列の計 65 列
* 形: 技ごとに 性質 → Linear(65→32)→GELU → 4 技で平均（ID の埋め込みと同じ mask）→ `mon_mlp` の 1 段目に列として足す。
  書き方は `mon_mlp[0](特徴) + move_prop_in(性質の平均)` で、1 段目の入力を連結するのと同じ写像になる。
  **`move_prop_in` は 0 で初期化する。** なので、ID だけのモデルから温間始動すると、1 歩目の前は元のモデルと同じ答えを返す（ビット一致。§2）
* 反対称は作りのまま保たれる（個体ごと・側ごとの層だけに足したので、鏡像の入れ替えと可換）
* 語彙とレギュレーションの固定: 語彙の指紋の検査は今のまま。それに加えて、保存した表の行が今の dex の表の同じ行とビット一致しないと、読み込みを拒否する
  （`_checked_move_props`）。語彙が末尾に伸びた分の行は、今の dex から埋める（ID だけなら 0 行で始まる技にも、性質は最初から入る）。
  M-B と M-C の表は 516 行とも一致した。なので、M-B の性質つきモデルは M-C に読める
* 既定 off のときは、パラメタも state_dict の鍵も前と同じで、`side_vectors` は前と同じ `self.mon_mlp(features)` の 1 行を通る
* `tools/train_value.py`:
  * `--move-properties` を足した。`--init-from` が ID だけのモデルなら、性質の枝を足した網に載せ替える。足りない鍵は枝のものだけであることを検査し、枝の初期化は `--seed` で決める
  * `--drop-train-moves a,b,c` を足した。その技を持つ局面を学習から抜き、検証の局はそのままにする
* `tools/value_move_rarity.py`（新規）: 学習で使った分割の検証の決定を、「局面にある技のうち、学習での出現数が最も少ないもの」の数で分けて、腕ごとの log loss（各シードの値・平均・標本 sd・logit 平均のアンサンブル）を出す。`--moves` を付けると、その技を含む決定とそれ以外にも分ける
* テスト（`tests/test_value.py`、torch が要る。モジュールごと importorskip なので、CI の skip の数は変わらない）:
  * 既定 off で、性質の鍵が無いこと
  * 0 初期化の網が ID だけの網とビット一致すること。陽性対照として、枝の重みを動かすと答えが動き、そのときも反対称であること
  * 保存して読み直すと答えが一致すること。表の 1 行を書き換えると読み込みを拒否すること
    （陽性対照: `_checked_move_props` を素通しにすると、このテストは落ちる。`C:/tmp/ika318/control_refusal.py`）

## 5. 読み（問いへの答え）

問い: 葉の符号化に技の性質を足すと、葉は良くなるか。

* **今の M-C の教材では良くならない。** 理由は、プール（65 構築）で使われる技が 153 個しかなく、どれも数千行以上出ているから。
  ID の埋め込みで十分に学べていて、性質が足す情報が無い
* **性質が効くのは、教わっていない技に出会うとき**（ゼロからで −0.015、抜いたことによる損の 6 割）。この場面は、次の 3 つで起きる:
  1. レギュレーションが変わって、新しい技が入るとき（M-B → M-C では技の語彙が同じだったので、起きなかった）
  2. プールが広がって、学習に少ししか出ない技が増えるとき
  3. 対戦評価で、プールの外の構築と当たるとき
* 温間始動では、性質の枝が育たない。持ち越しのために使うなら、性質つきでゼロから学ぶ（S の形）か、枝の学習率を上げるなどの形を別に決める必要がある
* IKA-274 §5.2 で「性質 + ID」が「ID だけ」よりセル誤差を 2〜3 割下げた結果とは、同じ比較ではない。そこの「性質」には port の候補ごとの特徴量（ダメージ・倒せる確率など）も入っていた。
  Q は手（技そのもの）を読むモデルで、教材も 10 万局面と小さい

## 6. 次の段の提案

* **出荷の葉としての対戦評価は、今は勧めない。** W2 の検証損失の差 −0.0001 は、IKA-82 の W2 x2 対 WA x2 の差（0.0006）より小さく、盤で差を出せる大きさではない。
  打つなら、SPRT(0, 10) の null に近い本になり、上限まで走る。IKA-82 §4 の形（x2 対 x2、1 局の CPU 秒で揃えた盤）で上限 4,000 対 = 8,000 局。
  IKA-82 §4 の盤は 1 本 8,212 局で約 10 分だったので、上限まで走る本と null（100 対）、選出の解の作り直しを合わせて、**専有の見込みは 15〜25 分**。
  その本は「性質つき x2 が負けないこと」の確認にしかならない
* **生成の葉として使う場合の判定**（CLAUDE.md の「速さと強さの引き換え」とは別の軸だが、同じ形）:
  次の世代（gen-1）の教材で、性質つきと ID だけを同じ W2 の形で学び、検証損失と盤で比べる。今回の結果からは、差が出ないと見込む
* **効く場面を先に作るほうが、情報が多い**:
  * 次のレギュレーション、またはプールの外の構築（大会の standings の構築など）で出てくる技の局面で、ID だけと性質つきを比べる
  * 持ち越しの形: 性質つきのゼロから（S）と温間（W2）のどちらを出荷の形にするかは、その比較の後で決める
  * 温間で性質の枝を育てる形（枝だけ lr を上げる、枝だけ先に数エポック学ぶ）も、そのときの候補
* 特性・持ち物の性質: 同じ理由で、今のプールでは効かないと見込む。新しいレギュレーションの試験と一緒に足す
