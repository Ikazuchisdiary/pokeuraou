# IKA-406 てっていこうせんの反動を port で扱う

課題: https://app.notion.com/p/3eb4b8acaa6c812894a3fb0a702aa176

## 背景

IKA-404 段 1c（records/IKA-404.md §8）で、大会の構築を 400 戦回すと、てっていこうせん（steelbeam）の
`mindBlownRecoil` で port が `PortRefused`（`move field mindBlownRecoil: steelbeam`）を 1 回出した。

## Showdown の規則（vendor a5df827、champions mod は技も `applyRecoilDamage` も上書きしない）

- `data/moves.ts` steelbeam: `mindBlownRecoil: true`、`onMoveFail`（`multihit` の技は除く）で
  `this.damage(Math.round(source.maxhp / 2), source, source, this.dex.conditions.get('Steel Beam'))`。
- `sim/battle-actions.ts applyRecoilDamage`: `move.mindBlownRecoil` なら反動 = `Math.round(maxhp / 2)`
  （当たった量に依らない。切り上げ）。`hitStepMoveHitLoop` で `totalDamage` が真のとき、および身代わりが
  ダメージを受けたとき（Substitute の `onTryPrimaryHit`）に呼ばれる。
- `useMoveInner`: `trySpreadMoveHit` が false（外れ・まもる・無効・半無敵の相手）なら `MoveFail` →
  同じ量。対象がいない・`TryMove` で止まる場合は `trySpreadMoveHit` に届かず、反動なし。
- 効果は `dex.conditions.get('Steel Beam')`。`sim/dex-conditions.ts` 650 は Weather・Status・Terrain 以外の
  effectType を `'Condition'` にするので、**`'Move'` ではない**。よって:
  - マジックガードは止める（Showdown のログで反動が出ないことを確認。最初は「技の名前の効果だから通る」と読んで
    いて、オラクルで外れた）。
  - いしあたま（`effect.id === 'recoil'` だけ）は止めない。
  - きあいのタスキ・がんじょう・こらえる（`effectType === 'Move'`）は効かない。port では `deal_damage` の
    `from_move = false`。
- 同じ field を持つ技: dump にあるのは steelbeam だけ（M-B・M-C とも。mindblown は `isNonstandard: "Past"` で
  dump に無い）。port の実装は field で決めているので、mindblown が入っても同じ扱い（反動は対象が 1 体でも
  allAdjacent でも同じ式。ゲートの許可リストには mindblown も書いた。Showdown との突き合わせは steelbeam のみ）。

## port の変更

- `rust/src/steel_beam.rs`（新）: `recoil_after_hit`（当たった量が正のとき）と `recoil_on_fail`（`multihit` は除く）。
  量は `(maxhp + 1) / 2`。
- `moves.rs`: `after_move`（当たり・失敗）、`hit_substitute`（身代わり）、`fail_before_hit_steps`
  （半無敵の相手・サイコフィールドでの失敗。`begin_move_watch` してから反動、ふみこみのとき
  `exits_if_crossed`）から呼ぶ。この field の無い技では何も変えない。
- `resolve.rs`: `move_field_is_ported` に `("mindBlownRecoil", "steelbeam" | "mindblown")`。
- `modelled.rs` を `tools/port_coverage.py --rust-modelled` で作り直した（差分は steelbeam の 1 行が消えるだけ。
  port が名前を出すので、`damaging move: steelbeam` の注記は出なくなる）。inert.rs は変わらない。
- `tests/test_gate_fields_in_dump.py` の `GATED` から steelbeam を外した（port が扱う）。

## テスト

`tests/test_steel_beam_oracle.py`（port 対 Showdown。11 の場面 + 丸めの確認 1）。各場面は Showdown で実際に
遊んでログの行を確かめ、port の結果の局面（HP・倒れ・持ち物・身代わり）と比べる。外れは port では
分岐なので、Showdown の外れが port の分岐のどれかに一致し、かつ分岐が 2 つ以上あること（当たりとの違い）を見る。

| 場面 | 旧 exe | 新 exe |
|---|---|---|
| 当たり（奇数 HP・偶数 HP） | 拒否 | 一致 |
| 当たって相手が倒れる | 拒否 | 一致 |
| 身代わりが受けた | 拒否 | 一致（反動あり） |
| 外れ | 拒否 | 一致 |
| まもる | 拒否 | 一致 |
| 相手がそらをとぶ・あなをほる中（半無敵） | 拒否 | 一致 |
| マジックガード（当たり・外れ） | 拒否 | 一致（反動なし） |
| いしあたま | 拒否 | 一致（反動あり） |
| 対照: 技を使わない | 一致 | 一致 |

旧 exe = 変更前の master の build（C:/tmp/ika406/old.exe）。`POKEURAOU_RUST_NODE_BIN=<exe> pytest` で両方を回した。
旧 exe は 11 場面中 10 で落ち（対照 1 は両方で通る）、新 exe は全部通る。`fail_before_hit_steps` を無効にした
build（変異）では半無敵の場面だけが落ちる（その経路が走っていることの対照）。

## 確かめていないこと

- `Parental Bond`（`inert.rs` にあり port は未対応）との組み合わせ。
  steelbeam は multihit の技ではないが、Parental Bond の持ち主が使うと Showdown は `onMoveFail` を飛ばす。
  port は `mv.raw.multihit` しか見ないので、この組み合わせは合わない（Parental Bond の体は steelbeam を覚えない前提）。
- Emergency Exit の持ち主が反動で半分を割る場合の切り替え（`exits_if_crossed` を通すが、オラクルで試していない）。
- ワンダーガード（Shedinja）の無効での失敗: port が ワンダーガード自体を扱わず拒否するので、試せていない。

## 生成への影響

本番の構築プール（data/pool/regmc-matchupweb/pastes の 65 構築）に Steel Beam を持つ体は無い
（`grep -i "steel beam"` が 0 件）。生成の局は変わらない（この規則は steelbeam を使う体が出る局面でだけ効き、
直す前は拒否になっていた）。大会の構築を扱う道具（IKA-404 の diff_field など）は PortRefused が減る。
