## 2. 全世代の符号化し直し（revision 3）

### 2.1 主記憶を抑える分割（`encode_dataset.py --parts`）

1 世代 40 万局の密な配列は、revision 2 で 13.6 GB（`mon` だけ）あり、revision 3 では列が増えてさらに大きい。学習と並べると主記憶 31 GB を超える（IKA-425 §2b.5）。
そこで `tools/encode_dataset.py` に `--parts N` を足した。ディレクトリのファイルを並び順に N 組に分け、組ごとに port で符号化する。結果は詰めた形（IKA-426 の `PackedFloat` と最小の整数型）にしてから、密な配列を手放す。最後に組を `concat_datasets` で結合し、1 つの shard として書く。
局の番号は前の組から続けて振るので、1 回で読んだ shard と同じ局・番号・値になる。

| 確かめ | 結果 | 対照 |
|---|---|---|
| `tests/test_encode_games_port.py::test_reading_in_parts_writes_the_same_shard`（3 ファイル・7 局、`--parts` 1・2・3、port と Python の両方の道） | 全メンバー（配列の bytes と dtype、meta）が一致 | 組を逆順に読むように変えた版では、2 件とも `foe`・`foe_search_value` ほかの不一致で落ちた |
