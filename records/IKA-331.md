# IKA-331: 生成に q-nocover を入れるかを判定する（IKA-73 の形）

2026-09-26。担当 IKA-331（worker）。master 0a56fc8 から切った `ika-331-qnocover-generation`。
問い: **同じ壁時計で、生成の既定（refs2）と q-nocover でそれぞれ M-C のプールを作り、同じ手順で学んだ葉を対戦評価にかけると、q-nocover のプールの葉は弱くならないか。**
打ち手としての q-nocover は IKA-274 段 2 で同じ CPU の対戦評価 +26.4 [+19.5, +33.3]（対 refs2）。打つ強さは教える質ではない（IKA-66）ので、別に測る。
出力はすべて `C:/tmp/ika331/`（プール・符号化・葉・対戦評価・駆動のスクリプト。コミットしない）。$M/data は読むだけ。

用語: 「裏」＝選出した 4 体のうち場に出ていない 2 体。「対戦評価」＝盤。

## 0. 登録（生成の前にコミットする）

### 0.1 2 つの腕（違うのは rank-fill だけ）

生成の既定の M-C の形（gen-0 = `data/selfplay-mc0` の形に、今の出荷の葉を載せたもの）:

```
tools/generate_queue.py --out <dir> --games <N> --first-game <F> --seed 33101
  --served --servers 2 --workers 24 --limit 12 --value $M/data/models/value-mc0.pt
  --pool regmc-matchupweb --hide-bench
  -- --rank-leaf --selection-store <C:/tmp/ika331/store-gen>
```

* **R 腕（今の既定）**: 上のまま（rank-fill 既定 = refs2）
* **Q 腕**: 上に `--q-model $M/data/models/q-mc0.pt` と、`--` の後に `--rank-fill q-nocover`
* 葉は value-mc0（x1）。`generate_queue.py` の `--value` は 1 ファイル（gen-0 も value-gen11L の x1）。Q は出荷の q-mc0.pt（x1、サーバの Q の腕 `q`、CUDA グラフ）
* 深さ 1・bench drop・deepen は既定（none）。ε・温度も既定。`--max-worker-failures` は既定（24 の 4 分の 1 = 6）
* run seed は両腕で同じ 33101、局の添字も両腕で 0 から。局 i は両腕で同じ 2 構築の対・同じ種になる（IKA-73 と同じ）
* **選出の解は先に全部解いておく**: value-mc0（x1）で全 2,145 対を解いた store（`presolve.py`、tag `<pool sha>|value:value-mc0`）を両腕で読む。
  選出は葉だけで解き rank-fill に依らないので、両腕で同じ答え。先に解かないと、最初に走る本だけが解く費用を払い、壁時計の比較が順番で傾く。
  そのぶん、本番の生成（その場で解く）より 1 局あたりの固定費が少し軽い。両腕に同じだけ効く

### 0.2 同じ壁時計（どう揃えるか）

* **大きさ**: 各腕 40,000 局を頼む（M-C gen-0 と同じ局数。IKA-73 の等時間の腕は 37,401 局）
* **順（ABBA、2 本ずつ）**: R1（局 0〜19,999）→ Q1（0〜19,999）→ Q2（20,000〜39,999）→ R2（20,000〜39,999）。
  各本は heavy.py `--exclusive`、他の GPU の仕事と重ねない。IKA-66・73 は腕ごとに逐次 1 本だったが、ここは機械のずれを打ち消すため交互にする
* **壁時計** = 各本の `generate_queue.py` の起動から終了まで（サーバの起動を含む。4 本とも同じ形なので固定費は両腕に同じ）。腕の壁時計 W = 2 本の和
* **揃え方（IKA-66・73 と同じ、添字で切る）**: 局は添字から種を取るので、先頭 N 局は「N 局を頼んでいたら得られたプール」そのもの。
  速い腕（W の小さい腕）は 40,000 局をすべて使い、遅い腕は **N = floor(40,000 × W_速 / W_遅)** 局（添字 0〜N−1）に切る。
  max-turns で捨てられた局（`discarded unfinished`）は欠けたまま数える（IKA-73 と同じ）
* 本ごとの監視（`C:/tmp/ika331/gen.py`）: nvidia-smi を 10 秒ごとに記録（使用量が 11 GB を超えたら木ごと止めて "main" に知らせる）。
  始める前に空き 3 GB 以上。CPU は機械全体の busy 秒を本の前後で取り、局あたりの CPU 秒にする（専有なので機械の busy ≈ この本）。
  本ごとに workers.json を残し、失敗の数を記録する。OOM が 1 つでも出たら止めて報告する
* 1 本の見込みを 10 分以上超えたら、その本を止めて "main" に知らせる

* レシピ: 出荷の温間始動（IKA-82 の W2）`tools/train_value.py --init-from $M/data/models/value-gen11L.pt --epochs 2 --lr 5e-4 --keep last --split-seed 0 --holdout 0.15`、

  加えて、両腕の葉を相手の腕の保留の局と gen-0 の保留（IKA-82 と同じ 6,000 局）にも当てる

### 0.4 対戦評価（判定）

* **主**: Q 腕の葉 x2（試す）対 R 腕の葉 x2（`--baseline` に明示）。どちらも等時間のプールから学んだもの
* 形（IKA-82・296 の葉 対 葉、打ち手は両腕で同じ設定で差は葉だけ = 同じ時間）:

```
tools/match_queue.py --pool regmc-matchupweb --served --servers 2 --workers 24 --hide-bench
  --sprt 0 10 --games 2000 --seed 33111 --q-model $M/data/models/q-mc0.pt
  --value <Q 腕 s0 s1> --baseline <R 腕 s0 s1>
  -- --limit 12 --baseline-limit 12 --rank-leaf --baseline-rank-leaf
     --rank-fill q-nocover --baseline-rank-fill q-nocover
     --selection-store <Q 腕の store> --baseline-selection-store <R 腕の store>
```

  打ち手の rank-fill は両腕とも q-nocover（9/26 の決め: 対戦評価と人と打つときの既定は q-nocover）。Q は両腕で同じ q-mc0（葉に依らない）。
  各腕は自分の葉で選出を解く（store は対戦評価の前に全 2,145 対を解いておく）
* **帰無対照（先に）**: R 腕の葉 x2 対 それ自身（`--baseline` に同じファイルを明示、IKA-296 の落とし穴）、100 対・SPRT なし、種 33110。全対が同じ局であること
* **止め方**: `--sprt 0 10`（H1 =「Q 腕の葉が 10 Elo 以上強い」）、上限 2,000 対
* **判定（「弱くならない」の読み）**:
  * H1 → 生成の既定を q-nocover にする
  * H0 か上限 → 同じ対の並びに `tools/sprt_replay.py --bounds -10 0` を当てる（非劣性: H1 =「弱さは 10 Elo 未満」）。
    その H1 → 弱くならない → q-nocover にする。H0 → 弱い → refs2 のまま。決まらない → 判定なし（refs2 のまま）として Elo と区間を書き、
    `--sprt -10 0` での続き（同じ種の続きの対）を "main" に提案する
  * 発火率（`pair_divergence.py`）と両席への届き（echo の葉・Q rankings）を添える
* **副（参考、機械に余裕があれば）**: 等局数（IKA-73 の armDg の形 = 教材の質だけ）。遅い腕を切らずに 40,000 局どうしで学んだ葉の対戦評価。
  主の判定には使わない。遅い腕が 40,000 局を持つので、追加の生成は要らない（学習 3 本と事前の解き 1 本と対戦評価 1 本）

### 0.6 予想

IKA-73 の向き（弱い探索のほうが打ち方がばらけて教材が良い）なら、覆いを外す q-nocover は教材として悪くない方向。打ち手として強いこと自体は教材の質を言わない（IKA-66）。
速さは IKA-274 段 3 で q-nocover が refs2 より遅くない見込み（別の master の比較）なので、局数はほぼ同じと見込む。対戦評価は H0 か判定なしが本命。
