# ratings-q-identity: M-C のレーティング表で本番が mc2 より下に出た件

2026-10-01。`tools/ratings.py --matches data/matches-mc --anchor hp-share/w12/hidden-bench` が
value-mc3e6x2（本番の評価モデル）を 254.7、value-mc2x2 を 261.7 と置いた。直接の比べでは
mc3e4 が mc2 に +59.2、mc3e6 が mc3e4 に +15.4（どちらも SPRT H1）。

## 結論

原因は 2 つあり、表の食い違いを作っていたのは **(2) 当てはめが収束していなかったこと**。

1. 打ち手の名前に Q が入っていなかった。直した（下記）。ただしこれだけでは表はほとんど動かない
   （500 歩のままの当てはめで mc2 が 261.7 から 261.9 / 261.6 に割れただけ）。
2. `fit()` は勾配上昇の固定 500 歩で、収束していなかった。mc3 の族は mc2 と 765 局の 1 本の辺で
   つながるだけで、その方向の曲率が他の千分の 1 のため、500 歩では約 100 Elo 足りなかった
   （歩数 5,000 で 348、50,000 で 356.6、500,000 でも 356.6）。ニュートン法に替え 6 歩で収束する。

## Q の指紋

局の行に `qModel`（`["q-mc0.pt", "new=q-mc1.pt"]`。1 つ目が通常の腕の Q、`new=` が `.new` の腕の Q）が
あり、`qModelSha256` は 9/30 ごろ以降の行だけにある。q-mc0 は sha 3944d4ba、q-mc2 は f0e885f6、
q-mc3 は e4ce9237 の 1 つずつで、同じファイル名に別の sha は無い。それ以前の行（mc1 系）は名前だけ。

`.new` は「その対戦評価の候補の腕」のラベルで、Q の名前ではない。IKA-400 の `.new` は q-mc2、
IKA-402 の通常の腕も q-mc2 で、名前の上では別々、中身は同じだった。逆に IKA-348 の `.new` は
q-mc1 で、通常の腕の q-mc0 と中身が違うのに、名前の差は `.new` だけだった。

新しい名前は `.../rankfill:q-nocover(q-mc2)`（`.new` は外して Q のファイル名）。`qModel` が無い行は
`(q?)` を付けて `.new` を残す（今の data/matches-mc には無い）。`provenance.q_identity` と
`agent_name` の `qModels`、`tools/ratings.py` の読み込み。キャッシュは `NAMES = 2` で読み直す。

## 当てはめ直し（Elo、hp-share/w12/hidden-bench = 0）

|---|---|---|---|---|---|
| mc3e6 / q-mc2（本番の評価モデル） | 254.7 | 253.7 | **371.8** | 32.7 | 3,374 |
| mc3e4 / q-mc3 | （q-mc2 と混在） | 242.3 | 359.8 | 32.3 | 3,443 |
| mc3e4 / q-mc2 | 243.4（.new 含め別名で 2 行） | 242.4 | 356.6 | 30.2 | 21,150 |
| mc3e2 / q-mc2 | 230.3 | 229.3 | 345.7 | 31.6 | 5,168 |
| mc2 / q-mc2 | 261.7（q-mc0 と混在） | 261.6 | 300.0 | 17.6 | 8,764 |
| mc2 / q-mc0 | 同上 | 261.9 | 292.8 | 15.9 | 11,850 |

当てはめと観測の差（別の打ち手どうしの組の最大）: 前 mc3e4 対 mc2 で −12.9 / +9.2 → 後 −2.2 / −1.5。
全組の最大は 2.2（mc2 対 hp-share、1,000 局）。同じ打ち手どうしの組（鏡）は席の有利が 5〜6 ポイント出る
（mc1 の鏡 +5.9、mc3e4 の鏡 +4.9）が、これは当てはめの席項が全体で 0.004 しかないためで、辺の食い違いではない。

## 本番の位置と、測っていないこと

- 本番の評価モデル mc3e6（Q は対戦評価のとき q-mc2）は mc2/q-mc0 より +79、mc3e4/q-mc2 より +15。
  直接の比べ（+59.2、+15.4）と合う（当てはめ値 mc3e4 − mc2/q-mc2 = 56.6）。
- **本番の組 value-mc3e6 と q-mc3 の対戦評価は無い**。q-mc3 は mc3e4 の上でだけ測った
  （q-mc3 − q-mc2 = +3.2 Elo、非劣性の SPRT）。表の mc3e6 / q-mc2 は本番ではない組。
- mc3 系は hp-share と直接つながらず、mc2 との 765 局の辺 1 本で水準が決まる（±30 の理由）。
- 評価モデルのファイルの指紋は局の行に無く、同名で中身が違う可能性は確かめていない。
  エンジンの版は 7 つ混ざる（警告は従来どおり）。
- `.new` の付かない q-mc0 の行のうち sha を持たない行（mc1 系）は、名前が q-mc0 であることだけを根拠にしている。

## 検査

`tests/test_ratings_q_identity.py`。収束の試験は、直す前の fit（origin/master）で
mc3 − mc2 が −0.08（正解 0.32）になって落ちることを確かめた。小さな 2 辺の例では旧 fit も収束し
（0.319）、1 万局級の別の塊を足して初めて落ちる（実際の表と同じ形）。
