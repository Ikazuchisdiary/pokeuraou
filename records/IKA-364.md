## 6. 既定と相談（調整役へ）

* 既定は何も変えていない（ladder は既定 off。play_human・analyze の `--threads` の既定も今のまま）。
* 全コアの形を使うなら、スレッドは 8〜9 で十分（16 と差が無い）。残りの 8 論理コアを検討の読みや推論サーバに空けられる。
* 既定にする前に要るもの:
  1. 深さ 4 まで採点できる基準（IKA-367 §9）。全コアでは 16 s から深さ 3・4 の段に入るので、そこでの損失が今の基準では読めない。
  2. L5 の深さ 4 の最初の段（d4r4b3…）の見直し（§4.3）。
  3. 実時間をそろえた対戦評価（1 過程の今の規則 対 全コアの L5）。

## 7. 別課題の候補

* **深さ 4 まで読む基準**（IKA-367 §9 の再掲）: 全コアでは 16 s から深さ 3・4 の段に入り、今の基準では採点できない。
* **L5 の深さ 4 の段**: d4r4b3k24x（長方形 4×4）が deep で +0.0096・呪い +0.009。d4r8 を先にするか、深さ 3 を広げる段（d3r16…）を挟む。
* **段の終わりの待ち**（ワーカー過程の時間の 19〜24%）: 次の段のセルを先に配る（前の段の答えが出る前に、長方形に入りそうな行と列のセルを読み始める）、または段の中で重いセルから先に配る（深さ 3 は子の数で重さが分かる）。
* **ワーカー過程と port 過程の往復**: ワーカー過程の python と port 過程は交互にしか動かない（14%・23%）。ワーカー過程の中で port を in-process にするか、塊の中の Python の仕事（`_fold_cell`・子の LP・Q の候補集合）を port に移す（IKA-303・IKA-305 と同じ根）。物理コアの壁の下で、1 セルあたりの CPU を減らす方向。
* **予算の使い残し**: 読みは次の段が入らないと見積もると、予算の半分ほどで止まる（5 s の手で 2.0〜2.9 s）。残りを次の段の一部（部分長方形）や、同じ段の oracle の巡に使う形。
* **段の予測**: `_guess_cell_ms` の深さ 3 以上の見積もりは、数えた費用の 100〜200 倍（§1）。値段を段の形ごとに当てはめ直す（`fit` を段の種類別に）。
* **Q を段で 1 回に積む**（IKA-363 §8）: この課題では入れていない。ワーカー過程で塊ごとに Q を頼むので、塊を細かくするほど往復が増える（§2）。並列とは逆向きの効き目がある。
