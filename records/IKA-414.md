# IKA-414 かたやぶりがフレンドガード・オーラブレイクを無視しない

## 結果

port はかたやぶり（テラボルテージ・ターボブレイズも）の使い手の攻撃で、フレンドガードとオーラブレイクを効かせたままだった。Showdown では両方とも `breakable` で、使い手の技の間は無視される。port は直した。

Showdown の規則（`sim/battle.ts` の `suppressingAbility`、`data/abilities.ts`）は次の通り。

- `breakable` の特性の handler は、持ち主が使い手と別で、かつアビリティシールドを持たないときに飛ばされる。
- フレンドガード（`onAnyModifyDamage` の 0.75 倍）の持ち主は、標的の味方。
- オーラブレイク（`onAnyTryPrimaryHit` で `hasAuraBreak`）の持ち主は、場の誰か。
- フェアリーオーラ・ダークオーラ・ルイン系は `flags: {}` で、無視されない。

port の変更は次の 4 点。

- `damage.rs` の `collect` で、使い手がかたやぶり・テラボルテージ・ターボブレイズのとき、アビリティシールドを持たないフレンドガードの 0.75 倍を足さない。
- 同じ条件のオーラブレイクは、オーラを割らない（5448/4096 のまま）。
- `FieldState.shielded_abilities` を足した。アビリティシールドを持つ場の個体の特性を、陣営ごとに持つ。
- `effects::breaks_for_damage` を足した。ふしぎなきのこのちから（Mycelium Might）は状態技にだけ `ignoreAbility` を付けるので、この判定に含めない。

## 確認

`tests/test_breakable_ally_abilities_oracle.py`。かたやぶり・テラボルテージ・シールド持ち・対照（かたやぶりでない使い手）を、フレンドガードとオーラブレイクで 7 ケース、Showdown と port の 1 ターン後の状態で比べる。

| 実行 | 結果 |
|---|---|
| 直す前の exe | 3 ケースが落ちる（フレンドガード 2、オーラブレイク 1。標的の HP が Showdown 193、port 168 など） |
| 直した後の exe | 全 7 ケースが通る |

- 直す前の exe では、かたやぶりの使い手でない対照とシールド持ちは通る。落ちるのは直した箇所だけ。
- 比べが空でないことの正の対照として、`test_showdown_moves_with_the_breaker` が Showdown 自身の答えを見る。かたやぶりの使い手の損傷は対照より大きく、シールド持ちの損傷は対照と等しい。
- `ally_rules`・`berry_abilities` のオラクルテストも通る。`cargo test --release`、`port_coverage.py --check`、`port_gate_audit.py --check`、ruff も通る。
- `agent_drift.py --check` は「8 道具が生成と違う」と出る。この変更は tools/ を触っていないので、この課題とは別の既存の状態。

## 見ていないこと

- 同じ特性の持ち主が 2 体いて、片方だけがアビリティシールドを持つ場面（アビリティ id で見ているため、シールドありと数える）。
- 3 体以上や、控えが入れ替わる途中の場面。
- 生成のプールにかたやぶりの体は居ないので、生成と対戦評価の強さへの影響は測っていない。

## 気づいた他の取りこぼし（監査はしていない）

- ふしぎなきのこのちから（Mycelium Might）は状態技だけが無視を持つ。`damage.rs` の防御側特性の読み飛ばし、`moves.rs` のミストバースト、`move_hooks.rs` の粘着など、ダメージ技で `is_mold_breaker` を呼ぶ箇所は、ふしぎなきのこのちからの使い手にも無視を効かせている可能性がある（コードを読んだだけで、Showdown とは比べていない）。
- `damage.rs` の防御側特性の読み飛ばしは、アビリティシールドを見ていない（コードを読んだだけ）。シールドを持つ防御側の特性が、かたやぶりの攻撃で無視される可能性がある。
