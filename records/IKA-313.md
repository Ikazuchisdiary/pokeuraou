## 1. Showdown の定義（vendor a5df827。champions mod はどれも上書きしない）

```
lightningrod / stormdrain（data/abilities.ts）:
    onTryHit(target, source, move) { if (target !== source && move.type === 'Electric') { boost spa; return null; } },
    onAnyRedirectTarget(target, source, source2, move) {
        if (move.type !== 'Electric' || move.flags['pledgecombo']) return;
        const redirectTarget = ['randomNormal', 'adjacentFoe'].includes(move.target) ? 'normal' : move.target;
        if (this.validTarget(this.effectState.target, source, redirectTarget)) { ...; return this.effectState.target; }
    },
    flags: { breakable: 1 },
followme / ragepowder / spotlight の condition: onFoeRedirectTarget（優先度 1・1・2）

        target = this.battle.priorityEvent('RedirectTarget', this, this, move, target);

    false の対象を飛ばして selfDrops（move.self）
```

読み取り:

* **引き寄せ**: `RedirectTarget` の事象の対象は使い手なので、選んだ対象がどちらの側かは関係ない。
  * このゆび・いかりのこな・スポットライトは `onFoe`: 使い手の相手だけが引き寄せる。相方を狙った技も引き寄せる
  * ひらいしん・よびみずは `onAny`: どちらの側の持ち主も引き寄せる（相方も）。使い手自身は `validTarget` で外れる（隣でない）。
    2 体いれば速い順（`speedSort`、同速は乱数）。選んだ対象が持ち主ならそれ自身に引き寄せる
  * `breakable`: かたやぶり（テラボルテージ・ターボブレイズ、きんしのちからは変化技だけ）の技は、どちらの側の持ち主にも
    引き寄せられない（`runEvent` が `suppressingAbility(effectHolder)` の handler を飛ばす）。とくせいガードの持ち主は別
  * 型は `ModifyType` の後（`useMoveInner` は `getMoveTargets` の前に `ModifyType` を走らせる）。雨のウェザーボールは水
* **ガード**: side condition の `onTryHit` は、その側の対象すべてに走る。使い手が誰かは見ない。相方のじしんは自分の側の
  ワイドガードで止まり、相方の先制技（しんそく等）も自分の側のファストガードで止まる
* **はねやすめ**: そのターンの残り（残差の 25 番まで）ひこうが外れる。相性・タイプ一致・`isGrounded` のすべて。
  満タンで使うと `-fail heal` で技が失敗し、`selfDrops` が飛ばされるので、ひこうのまま

## 2. port の直し（rust/src）

* `moves::redirection_target`（IKA-313）
  * 選んだ対象が自分の側なら何もしない、という早い return を外した
  * このゆび等は使い手の相手の側（`1 - action.side`）を見る。選んだ対象の側ではない
  * ひらいしん・よびみずは両方の側の持ち主（使い手自身を除く）を集め、2 体以上なら速い順（`by_speed_noting`、同速は
    `redirection speed tie (Showdown breaks it at random)` の注記）
  * かたやぶり系の使い手（きんしのちからは変化技のとき）なら、とくせいガードの無い持ち主を外す
  * 型は `damage::modified_move_type`（`calculate` と同じ読み: わるあがきの `???`、-ate 特性、技自身の `onModifyType`）。
    持ち主が場に居るときだけ使い手の Battler を作る
  * `reply_targets`（カウンター等）も同じ関数を通るので `&mut Turn` と `Result` にした
* `moves::absorb`: 吸収の回復・上昇も `ModifyType` 後の型で読む（雨のウェザーボールでよびみずが上がらなかった）。
  免疫の判定はもともと `calculate` の型だった
* `moves::blocked_by_protect`（IKA-314）: ワイドガード・ファストガードの `from_foe` を外した
* `battler::roosted`・`Turn::types_of`（IKA-315）: `roost` の volatile があればひこうを外す（空なら ノーマル）。
  `Battler::from_pokemon` も同じ。ダブルショック・もえつきるの型の書き換えと、へんしんの写しは外す前の型
  （`Turn::base_types_of`。へんしんは Showdown の `typeWas`）
* `moves::apply_status_move`（IKA-315）: 自分に向く回復技が満タンなら `self` の効果を付けず、`move_failed` を立てる。
  M-C の技表で `self` を持つ変化技ははねやすめだけ
* 生成物（inert.rs・modelled.rs）は変わらない。`port_coverage.py --check`・`port_gate_audit.py --check` は通る

**Python 側に同じ規則は無い**: `narrow` のダメージ点（port の `score`）も `qfeatures` も、引き寄せ・ガードをどちら向きにも
読まない。はねやすめの volatile はターンの始めの局面に残らない（残差で消える）ので、メニュー・葉の符号化には出ない。
`actions._grounded`（ありじごく）もターンの始めに読む。

## 8. 別課題の候補

* **味方の `allies` の技（いのちのしずく）を吸収特性が受けない**: diff_turn s3 battle 286 turn 3。Showdown はいのちのしずくを相方の
  よびみずが吸って（`onTryHit`、`target !== source`）とくこう +1、回復しない。port は回復する。自分への回復は通る。ちょすい等も同じ形のはず
* **溜め技の 1 ターン目も引き寄せが走る**: a5df827 の `getMoveTargets` には溜めの除外が無く、1 ターン目にも `-activate` が出る
  （s3 battle 83 turn 8）。port は 1 ターン目の選んだ位置を `targetLoc` に記録し、2 ターン目に引き寄せ直す。引き寄せた体がその間に
  引っ込むと違う。件数は数えていない
* **Showdown の局面のタイプがはねやすめの途中で固まる**: sim-bridge の `position.ts` は `p.getTypes()` を出すので、ターンの途中の局面
  （途中交代の待ち）にはねやすめの体が居ると、ひこうの抜けた型が局面に入り、port が残差で volatile を消しても戻らない。diff_turn の
  途中交代の比べだけに効くはず。確かめていない
* **pledgecombo**: M-C の技表に誓いの技が無いので入れていない。技表に入ったら要る
