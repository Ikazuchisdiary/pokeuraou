# IKA-407: ランクマ段 1a — 貼り付けの構築と相手 6 種族で選出（記録）

親 [IKA-404](https://app.notion.com/p/3eb4b8acaa6c811eb86dc9bd7918e3ad)（計画）。用語は用語集どおり。「型」は 1 体の技・持ち物・特性・性格・SP の組。ブランチ `ika-407-ranked-1a`（origin/master 33dd3b4 から）。

## 1. 決めたこと（10/1 ユーザーと調整役）

* 対戦後の検討・練習に使う（対戦中ではない）。見せ合いは種族だけ見える。相手の型の事前分布は大会データ。
* 配分（SP）の無い種族は仮の配分で読み、画面に「仮の配分」と出して上書きできる。読みの時間は今のまま。生成のプールは広げない。
* 段 1a は核（`src/pokeuraou/rankedentry.py` の純関数）と薄い画面（貼り付け・相手 6 種族・推定の型の表と上書き・選出の結果）まで。局面の入力は 1b。設定は歯車の中。
* 選出に使う型は種族ごとの最頻の 1 型。上位 3 型は候補として表示し、ワンタップで替えられる（混ぜて解くのは段 2）。完全一致の最頻が 3 体未満（`WHOLE_MIN`）のときは、特性・持ち物・性格・技 4 つを別々の最頻で取り、画面に「部分ごとの最頻」と出す。
* SP: プールの同じ種族（同じ性格を優先）、無ければ基礎能力から作る中立の案（regulation の dump の SP の合計 66・1 つ 32 の上限に従う）。
* 出どころは **Baltimore Regional 1 大会・1,077 構築（6,462 体）だけ**（SP は無い）。画面（相手の型の下の帯と歯車の中）と記録に書く。

### 推定の決め方（`FieldPrior`）

* 種族ごとに大会の全メンバーを数え、（特性・持ち物・性格・技の集合）の完全一致が最多の型を使う。同数は名前順で固定。完全一致の最多が `WHOLE_MIN`（3）未満なら部分ごとの最頻。
* 特性がメガ後のもので記録に無いメンバーは、その種族の最頻の特性、無ければ種族の最初の特性で埋め、注記を出す。
* 配分: プールの同じ種族・同じ性格の最頻 → 同じ種族の最頻（性格は違う） → 中立の配分（仮）。中立は、攻撃の高い方に上限 32、素早さ（基礎 60 以上）か HP に 32、残りを HP（HP が使用済みなら防御）へ。合計 66。
* 6 体の持ち物が重なるときは、後ろの種族を持ち物の違う次の候補に替えて注記する。替えられなければ問題として出し、読めない。同じ種族 2 体も止める。
* 大会に出ていない種族は止めて知らせ、枠を手入力にする（技が入るまで読めない）。
* 評価モデルが学んでいない id: 種族・技・持ち物・特性ごとに、体の上に「評価モデルが学んでいない: …」の札を出し、技は枠を縁取る。止めない。

### 学んでいない id の集合（キャッシュ）

`data/ranked/learned-ids-regmc.json`。`selfplay-mc0123-encoded.npz`（value-mc3 の学習データ。M-C の語彙の番号を名前に戻す）と `selfplay-gen11L-encoded.npz`（温間始動の元。M-B の語彙で名前に戻す）に出る id の和。大きな npz を毎回読まないよう、無いときだけ作って書く（`load_learned_ids`。読み取りに 5.3 秒）。今回の中身: 種族 127・技 212・持ち物 71・特性 91（mc0123 は種族 89・特性 65・持ち物 51・技 153、gen11L は種族 110・特性 82・持ち物 60・技 189）。gen11L の前の世代（gen11L の温間始動の元）の分は数えていない。

### 画面

貼り付け → 読み込み（6 体の表、規則の問題は体ごとに日本語で）→ 相手 6 種族（名前は日本語・英語どちらでも。候補の一覧から選べる）→「型を推定する」→ 6 体の型の表（出どころの札・仮の配分の札・上書きの札・未学習の札、上位 3 型のワンタップ、編集欄）→「選出を読む」（経過の帯、勝率の見積もり、おすすめの選出と混ぜる確率、体ごとの選出・先発の確率、相手の選出の読み、注記）。入力が変わると前の読みは消える。歯車の中は表示のテーマとデータの出どころだけ。

### 正の対照: 真の型 対 推定の型（局面集の代わりにプールの 40 組）

`tools/ranked_controls.py compare --pairs 40`。こちらはプールの構築 i、相手は構築 j。相手を (a) 真の型で解いた答えと (b) j の 6 種族だけから推定した型で解いた答えを比べ、(b) の混合を**真のゲーム**で採点する（損 = 真のゲームの値 − (b) の混合の最悪値）。葉だけ（深い読み無し）、value-mc3 x2、CPU、1 組 約 1.4 秒、全体 56 秒（4 コア）。

| 量 | 値 |
|---|---|
| 推定の型が真の型と一致した体（種族・特性・持ち物・性格・技。配分は比べない） | 91 / 240（38%） |
| あなたの値（真のゲーム／推定のゲーム） | 0.5145 ／ 0.5284（差の絶対値の平均 0.0465） |
| 損（推定の混合を真のゲームで採点） | **0.0286**（標準誤差 0.0038） |
| 損（一様な混合。尺度） | 0.1972（標準誤差 0.0079） |
| 損（真の混合。対照） | −8e-18（0） |
| 最多の選出が真のゲームと同じ | 24 / 40 |
| 2 つの混合の L1 距離の平均 | 0.891 |

読み方: 推定の型で選出すると、真の型を知っているときより平均 2.9 点の勝率を失う（一様な選出の 0.197 の約 15%）。型は 6 割以上外れても選出の質は大きくは落ちない。ただし 40 組はプールの構築どうしで、大会上位の定番に寄る（ランクマより最頻が当たりやすい。IKA-404 の段 0 と同じ注意）。**下限**として読む。真の混合の損が 0 になることは、この損の測りが 0 を取れることの対照。

## 5. 確かめていないこと

* 深い読み（90 秒）での「真の型 対 推定の型」。`compare` は葉だけ。深い読みで差が縮むか広がるかは測っていない。
* 局面集（IKA-394）は使っていない。プールの構築どうしの選出で代えた。ランクマの相手はプールとずれるので、損は大きくなるはず。
* ブラウザの確認は Edge のみ。スマホの実機は見ていない（幅 375 は iframe で再現）。デザイン担当の「可」は未取得（スクリーンショットは `C:/tmp/ika407/shots/`）。
* 学んでいない id の集合は、value-mc3 の学習データと gen11L の和。gen11L のさらに前の温間始動の元のデータは数えていない。0 の行（語彙に後から足された id）と初期値の乱数の行を区別していない。
* 型の混合・観測での絞り・入力の追跡は段 2 以降。メガは持ち物で決まるのでメガ前の種族名で入れる。技の順は名前順（元の順は大会データに無い）。
* 英語名以外の貼り付け（日本語名）は読めない。ゲームからの書き出しの形は確かめていない。
* 画面に既存の対局の画面（`live.html`）からのリンクは付けていない（別ポート 8338）。
* 別の課題の候補: 大会データを Brisbane・Frankfurt に広げる出どころ（`tools/fetch_standings.py` の M-C 分）。
