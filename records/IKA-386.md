## 5. 残り・別課題の候補（効き目の見込みの大きい順）

1. **開いた 24 s で port が重くなる分の切り分け**（見込み: 24 s で 1.03〜1.05 倍。中）: B で port の時間が 1 ノード秒あたり 50〜60 ms 増えた。`fillsServed` の中の写し（`copyUs`）・待ち（`waitUs`）・埋め・解くの内訳を `here`・`pool` に出し、深い段の大きい呼び出しで何が高いかを見る。写しを埋めと重ねる（束の配列を埋めた順に塊へ書く）か、解くのを束の待ちに寄せる。IKA-381 §7 の 2（24 s で速くならない理由）と同じ問いの続き。
2. **深いセルの子（`_kids_fill`）の葉と終わった枝の葉も port から依頼する**（見込み: 評価モデルの接続に残った `score` 依頼。開いた 1 スレッドで 58/204。小〜中）: `fillsServed` と同じ口で、Python の `__call__`（Python の符号化）を通る分は port の符号化とバイトが違うので、依頼のバイト一致ではなく値の一致で判定が要る。
3. **Q の依頼も port から**（見込み: Python の B3 の Q の配列 約 30 ms / ノード秒。中）: `qfeatures` の配列を port が推論サーバの Q に直接送る。
4. **CI（ubuntu）で `/dev/shm` の読み書きの道を確かめる**: この機械（Windows）でしか通していない。`tests/test_portserved.py` が suite で回るので、最初の取り込みの後の CI で分かる。
