# IKA-470: port の LP（HiGHS）の設定を変えて速くする

[IKA-470](https://app.notion.com/p/4264b8acaa6c8194ae41cbf7c61b5583)。状態: 単体の比較、生成の形の ABBA、対戦評価（SPRT(−10, 0)）まで済み。

## 1. 要点

* IKA-462 §2.2 の基準（1 局の実時間 約 200 ms）で、LP は約 28 ms（約 14%）だった。1 回 約 375 µs、1 局 75 回である。
* 生成の形の 300 局から LP を 5,578 個ダンプし、設定ごとに単体で解いた。presolve を off、simplex の scaling を off にして tolerance を 1e-8 にすると、1 回 483 µs が 107 µs になった（4.5 倍。§3 の表）。
* ゲームの値の差は最大 9.9e-8、制約の違反は最大 9.6e-9 だった（scipy の設定は 9.9e-8）。この設定で失敗した LP は 0 件だった。
* 縮退した LP で選ぶ頂点が変わり、5,578 個のうち 210 個で解の戦略が変わった。局は変わる。port と Python の LP の一致を見るテストは、ビット一致から「値が許容差以内で、戦略が均衡である」ことの確認に直した（§6）。
* 生成の形の ABBA（2,000 局・21 ワーカー、各 4 回）で、局/分は 2,080.7 から 2,256.2（+8.4%）、1 局の CPU は 0.3718 秒から 0.3448 秒（−7.3%）になった。
* 対戦評価 SPRT(−10, 0) は 719 対で H1 だった（§4.2）。
* この設定で失敗した LP は、scipy の設定で解き直す。800 局の run 4 回（約 237,000 LP）で解き直しは 0 回だった（§4.3）。

* 既知の影響: Q の解が混合で、台の手の数が候補集合の幅を超えるとき、候補集合に残す手が丸めで決まり、席や OS によって変わりうる。相手の解が混合なら、台の手の得点は無差別の性質で互いに等しくなるためである（§6.4）。鏡のテストで見えた。同じ四人・同じ先発の局で、2 つの席の候補集合が一致せず（16 局のどれも一致しなかった）、2 つの値の和が 1 にならなかった（6e-3 のずれ）。scipy の設定でも同じ構造だったはずである（確かめていない）。この影響の大きさ（実際の評価モデルの Q で、台の手の数が候補集合の幅を超える頻度）は調べていない。
* 絞り込み（同じチーム・同じ先発・同じ四人）のあとに残る鏡の局は、6 局のうち 5 局である。テストは 3 局以上を要求する。

### 6.4 鏡のテストの CI での失敗（Linux）と直し

* 失敗: `test_a_mirror_s_two_values_sum_to_one` が `assert 1.0749355692282 == 1.0 ± 1.0e-09` で落ちた（CI run 46128754110、Linux、Python 3.14.4）。ローカルの Windows では通っていた。「同じ四人・同じ先発」の絞り込みを通った局で、2 つの席のゲームが鏡でなかった。
* 原因（推定）: 席の候補集合は、Q の解の最善応答の得点で順位をつけた上位 4 手である。相手の解が混合のとき、均衡の台に載る手の得点は無差別の性質で互いに等しい（丸めの差を除く）。台の手の数が候補集合の幅（4）を超えると、どの 4 手を残すかが丸めで決まる。これは Q の同点に限らず、混合の解のゲームに共通する。Linux では丸めの結果が違い、2 つの席が別の 4 手を残した。Linux では再現していない。
* 裏付け: 直す前は、鏡の局でも `ownActions` と `foeActions` が一致する局が 16 局中 0 局だった（Windows）。席の候補集合が一致することを、テストは確かめていなかった。
* 直し: 鏡の代役の Q を、手ごとの強さ s の順位のゲーム（Q(i, j) = 0.5 + 0.4 tanh((s_i − s_j) / 2)、強さは手の符号化と特徴への固定の乱数の重み、両席で同じ重み）にした。最強の手が支配する行になるので、Q の解は純粋で、得点（その手への最善応答）は s の順に厳密に並び、同点がない。残す 4 手は丸めによらず強さの上位 4 手になる。
* テスト: 鏡の局について、`ownActions == foeActions`（両席が同じ 4 手）を、和の確認の前に assert する。鏡であることを仮定せず確かめる。
* 確認（Windows、IKA-470 の exe）: 6 局のうち同じ四人・同じ先発の 5 局で、`ownActions == foeActions` が成り立ち、値の和は 1.0（9 桁）だった。違う四人の 1 局は、和が 0.987 で、絞り込みで除かれる。5 局の値は、どれも searchValue が 0.5001077766048302、foeSearchValue が 0.4998922233951698（和は 1.0）だった。和の確認が要求する「0.5 との差が 1e-6 より大きい」を満たす（差は 1.08e-4）。この閾値は、直す前の 1e-4 から 1e-6 に下げた。
* 確かめていない: Linux で通ること（CI で見る）。強さの重みの乱数が、プラットフォームで同じ値になること（`numpy` の `default_rng(470).normal` は同じ値を返す仕様だが、Linux では回していない）。
