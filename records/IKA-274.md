### 2.2 鏡像と重複（ユーザーの案）

**鏡像**: 行列 M[a, b] は側 0 の勝率なので、側 1 から見た教材は 1 − M[b, a]。

* `encode.py` の局面の配列は側の軸を持ち、`Encoded.mirror()`（側の軸を反転、`field` はそのまま）が、両側を入れ替えた局面の符号化とビット一致する（6 局面）
* 候補の符号化（§3）は側から見た相対（自分の個体の行・相手の個体の行）なので、両側を入れ替えても同じ配列（6 局面）
* 両側を入れ替えた局面を port で埋め直すと、1 − M^T と最大 1.04e-7・平均 2.5e-8 で一致（葉が側 0 の値を返す約束と、反対称の葉。差は §2.1 と同じ float の揺れ）
* Q を**作りで反対称**にした（§5.1）ので、1 本の行列が両側の教材になる。**鏡像で増えた教材は 115,812 行列**（両側の視点で 231,624 行列相当、セルで 4.7 億）。
  学習で鏡像を引き直す必要は無い（引いても同じ損失）

**重複**:

* 同じ局の同じ決定は 1 回しか入っていない（index の (局, 決定) 334,077 がすべて別）
* ただし**両側の推測がどちらも当たる**と、2 つの視点が同じ局面になる（試作の 100 局面で 164 行列のうち 15 組、9%）
* さらに**別の局の同じ局面**: 同じ組の構築どうしでは、乱数が効く前の序盤は打ち手が決定論的なので同じ局面が何度も出る（ターン 1〜5 に多い）
* 全体で、**同じ局面・同じ手の行列は 163,420 のうち 42,580（26%）**（学習の読み込みで encode の配列と両側の手のハッシュで数えた）。学習はこれを 1 本にして読む
* 塊 3 から、**同じ決定の中の同じ視点は 1 本だけ埋める**ようにした（`side=2`）。前と後の道具で同じ 100 局面を CPU の葉で埋め、後の 149 行列がすべて前の行列とバイト一致、
  落とした 30 行列（15 組）は残した行列とバイト一致（`C:/tmp/ika274/dedupe_compare.py`）。**塊 3 は 18.3 → 21.8 局面/秒（+19%）**
* 別の局の同じ局面は生成では省いていない（局面を作ってから分かる。省くなら先に全局面を作って数える前処理が要り、得は残りの塊の 2 割ほどだった）
* 裏に触れないセルを決定化の間で共有する案: 2 つの視点は両方の裏が違う局面で、葉は裏も符号化するので**葉の採点は共有できない**。
  共有できるのは port の解決（行列あたり 0.32 CPU 秒）だけで、生成は GPU のサーバが律速（16 並列で port の CPU は 16 コアの半分以下）なので、入れなかった

## 4. 候補の特徴量（port の `qfeatures`、ユーザーの方針）

1 回の往復で、両側の候補の一覧（`narrow` と同じプールの列。IKA-319 のとおり二度作らない）に、候補あたり 34 の数を返す（`rust/src/qfeatures.rs`）:

```
  スロット t（2）× 相手の位置 k（2）: タイプ相性（log2）、期待割合、倒せる確率、先に動くか、当たるか      20
  スロット t: 味方への期待割合（全体技）                                                               2
  スロット t × 相手 k: 交代先が相手 k の技から受ける最大割合、交代先が相手 k に与える最大割合              8
  相手 k: 2 匹の合わせ技で倒せる確率、2 匹とも当てるか                                                  4
```

* ダメージは `score.rs`（`narrow` のダメージ点）と同じ `damage::calculate` を使い回した。Python の damage.py に同じものは書いていない。
  期待割合は `score` 命令の答えと 8,095/8,095 で float32 一致
* 倒せる確率: 16 通りの乱数 × 急所（port の `damage::crit_probability`）。命中率は入れない（技の性質の表に入る）
* 合わせ技: 2 つの分布（急所込み）を畳み込んだ確率。順番で変わる効果（きあいのタスキ・マルチスケイル・ばけのかわ、先に倒れて対象が移る）は入れていない。
  「2 匹とも当てる」の旗がこの近似の範囲を示す
* 先に動くか: 優先度（特性込み）・素早さ（`speed::effective_speed`）・トリックルーム。相手の技の優先度を 0 と置いた近似
* メガを宣言する手も今の姿で計算（`score.rs` と同じ）
* 費用: 1 行列（両側 約 120 候補）あたり 1.2〜5.5 ms。10 万局面の全シャードで 8 並列 23 s（それ以前の 668 シャードは 1 並列 704 s）。行列の埋め（0.3〜0.5 s）の 1% 未満。
  教材と推論で同じ命令を使う（開発用の exe と最終の exe、取り込み後の exe で、同じシャードの特徴量がバイト一致）
* テスト: `cargo test` に合わせ技の 3 本（`>=` を `>` にすると 1 本落ちる、を確かめた）。既存のテストも通る（取り込み後 11 本）。
  `port_coverage --check`・`port_gate_audit --check` 通過

**技の性質の表**（`qhead.move_table`、dex の固定の表から 1 回作る）: タイプ、分類、威力、命中（必中の旗）、優先度、変動威力の旗、対象の種類、
フラグ（接触・音・パンチ・かみつき・波動・切る・回復・まもる対象・弾・風・粉・踊り）、要約（まもる系・自分交代・反動・吸収・追加効果の確率・状態異常・
揮発の付与・自分と相手の能力変化・連続技・急所ランク・場の状態・天気/フィールド）。ID の埋め込みと並べて使う（「性質 + ID」）。

## 5. モデル（`qhead.build_net`、`tools/q_train.py`）

### 5.1 形（ユーザーの方針: 葉と胴体を共有できる形、作りで反対称）

* **胴体は出荷の葉と同じ**: `value.ValueNet` をそのまま中に持ち（同じ encoder・同じ語彙の指紋。`load_q` は指紋が違えば止まる）、
  埋め込み・個体の MLP・側のプーリングを使う（価値の頭は持つだけで使わない）。`--init-trunk` で出荷の葉の重みから始められる（葉は読むだけ）。
  技の性質は個体の表現にゼロ初期化の線形で足すので、葉から始めた胴体は最初は葉と同じ読みをする。その後に 8 体の間の注意 1 段
* 候補: 動く個体・対象・交代先の胴体の行 + 技の埋め込み（+ 性質）+ 種類・メガ → スロットの MLP → 2 スロットの和 + 局面の文脈（+ port の特徴量）→ 候補の MLP
* 組: g(u_i, v_j)（足し算型の MLP と低ランクの内積）。**ロジット = g(u_i, v_j) − g(v_j, u_i)**。胴体の行と側のベクトルは、両側を入れ替えると側の軸が反転するだけなので、
  入れ替えた局面の行の手は元の v、列の手は元の u になり、**Q(mirror s, b, a) = 1 − Q(s, a, b) が初期化から常に成り立つ**
  （テスト: 未学習の網で 3 局面、1e-5 以内。反対称の項を外すと落ちる）
* 損失: セルごとの軟らかい BCE、行列ごとに 1 回の重み。保留は局単位で 10%（11,634 行列、報告はそのうち 3,000）。AdamW 1e-3、10 エポック、1 本 23 分（GPU、2 本並べて）

### 5.2 保留した局面の誤差（10 エポック目）

```
  変種                      セル MAE   セル RMSE   均衡の値の誤差 平均（中央値）   Q の均衡を M で測った NashConv 平均（中央値）
  ID だけ・ゼロから           0.0652     0.1069      0.0580（0.0332）              0.165（0.132）
  ID だけ・葉の胴体から       0.0621     0.1028      0.0557（0.0319）              0.161（0.130）
  性質+ID・ゼロから           0.0509     0.0844      0.0446（0.0240）              0.112（0.082）
  性質+ID・葉の胴体から       0.0475     0.0797      0.0413（0.0220）              0.109（0.081）   ← 最良
  参考: 各行列の本当の平均を定数で置く   0.1173
  参考: 一様な方策                                                                 0.330
```

* 「均衡の値の誤差」= |v(Q の行列) − v(M)|。「NashConv」= Q の均衡の方策の組を本当の行列 M で測った被搾取性（両側の和）
