# IKA-444: 学んでいないギミックを局を足して学べるか

2026-11-23 起票。枝 `ika-444-gimmick-learning`。課題: https://app.notion.com/p/4214b8acaa6c8115b9e9c2dbe61863c5 。

## 要点

### 1 回目（2026-11-24）

* ユーザーの構築を含む組だけを 2 万局生成し、gen-0〜6 に足して評価モデルを学び直した（value-b）。
* 同じ 999 局で、ユーザーの構築の得点は 0.224 から 0.316 に上がった。対の差は +0.092 [+0.055, +0.129] だった。
* 選出の値と得点の平均の差は −0.248 から +0.036 になった。相手ごとの差の絶対値の平均は 0.264 から 0.138 だった。
* 本番のプールでは value-mc6 に SPRT(−10, 0) で H1 だった。+9.2 Elo [−4.3, +22.8]、1,132 対。
* バトンタッチを使った局は 0.6% から 1.2% にしか増えなかった。値と選出は学べたが、バトンの流れは学べていない。
* 次は 2 回目で、生成の片方の席でめいそうからバトンタッチまでの流れを固定する。

## 1. 何を確かめるか

広い範囲から強い構築を探し、評価モデルが知らないギミックを自分で学ぶ仕組み（IKA-445）は、次の前提に立つ。知らないギミックでも、それを含む局を足して学べば、評価モデルは値と打ち方の両方で取り込める。この課題はその前提を、IKA-419 のユーザーの構築 1 つで確かめる。

構築は `examples/diag-team-ika419.json` と同じ 6 体（リザードン（メガ Y）、ニョロトノ、エルフーン、ブリジュラス、クエスパトラ、ライチュウ（メガ X））である。クエスパトラ、バトンタッチ、エレキフィールドは gen-0〜6 の学習データに出てこない。

## 2. 判定の目安（測る前に決めた。Notion の課題の本文と同じ）

| 結果 | 次にすること |
|---|---|
| 勝率が上がり（差の 95% 区間が 0 を含まない）、値と得点の差の絶対値が半分以下になる | IKA-445 に進む |
| 値と得点の差は縮むが、勝率は変わらない | 評価は学べたが打ち方が伸びない。探索の深さと候補集合を調べる |
| どちらも動かない | 入力の符号化か局の量が足りない。重みや局を増やして 1 回やり直す |

## 3. 方法

### 3.1 プールと道具

* プールは `data/pool/regmc-matchupweb.json` の 65 構築に、ユーザーの構築（`C:/tmp/ika419c/pool7.json` の `ika419-user-rain-sun-screens`）を足した 66 構築（`C:/tmp/ika444/pool66.json`、id `ika444-pool66`）。作り方は `C:/tmp/ika444/make_pool66.py`。
* ユーザーの構築を含む組だけを打つ。対戦評価の道具は `tools/pool_match.py --pairs-with espathra --pairs-no-mirror`（IKA-419 で足したフラグ）。
* 生成の道具には同じフラグが無かったので、この枝で足した（`tools/selfplay.py --pairs-with` / `--pairs-no-mirror`、`poolplay.generate_pool` の `pairs`、コミット f92517a）。フラグが無ければ局は変わらない。テストは `tests/test_poolplay.py` の 4 本。
* port の exe はこの枝の `rust/` から作り（`C:/tmp/ika444/exe/`）、`POKEURAOU_RUST_NODE_BIN` で渡した。

### 3.2 学ぶ前と後の測り

`C:/tmp/ika444/run.py`（`match_queue.py --pool`、served、裏非公開、幅 12、rank-leaf、q-nocover は q-mc6、選出の探索なし）。両腕を同じ評価モデルにする。両腕が同じなので、局の番号 i の 2 席は同じ局になる（確かめた。手順まで一致）。集計は `C:/tmp/ika444/analyze.py` が局の番号で重なりを除いて行う。学ぶ前と後は同じ種 44401・同じ 1,000 局の番号で打つので、組と席は前後で同じになる。

### 3.3 局を足して学ぶ

* 生成と同じ形（`generate_queue.py --pool`、value-mc6 x1、q-mc6、選出の探索 ε 0.25・T 0.5）で、ユーザーの構築を含む組だけを 2 万局打つ（`C:/tmp/ika444/gen.sh`、種 44402）。
* その局を符号化し、gen-0〜6 と結合する（`C:/tmp/ika444/chain2.py`）。
* CLAUDE.md の「次の世代」の命令を種 10 で 1 本学ぶ（value-mc6.pt と同じ作り方）。value-mc6.pt が「2 万局を足さない」対照になる。保留局の分け方は局の総数で決まるので、value-mc6 と同じ分け方にはならない。比べるのは勝率と値なので、この差は記録に残すだけにする。

## 4. 結果

| 選出の値の平均（ユーザーの席） | 0.472 |

value-mc4 で測った IKA-419 の数字（値 0.505、実勝率 0.314、51 局）と同じ向きで、値が得点より 0.25 高い。

### 4.2 局を足して学ぶ

* 生成: 2 万局（`C:/tmp/ika444/selfplay-baton`、種 44402）。21 ワーカー・推論サーバ 2 で 1,396 秒（約 23 分）。
* 符号化 12 秒、gen-0〜6 との結合 605 秒。結合のデータは 1,899,969 局・22,308,568 決定（gen-0〜6 の 1,879,969 局に 2 万局を足した数）。
* 学習 4,643 秒（約 77 分）。出力は `C:/tmp/ika444/models/value-b.pt`（以下 value-b）。保留局の手番の AUC は 0.9114（生成の探索 0.9105）、交代の AUC は 0.9048（同 0.8896）。

### 4.3 学んだ後（value-b x1）

4.1 と同じ種 44401・同じ局の番号で打った。2,000 席のうち 1,998 席が書かれ、999 局になった（1 局の 2 席が書かれなかった。ワーカーの失敗は 0）。225 秒。

| 量 | 学ぶ前（value-mc6） | 学んだ後（value-b） |
|---|---|---|
| ユーザーの構築の得点 | 0.224 [0.198, 0.250] | 0.316 [0.287, 0.345] |
| 選出の値の平均（ユーザーの席） | 0.472 | 0.281 |
| 得点 − 値 | −0.248 | +0.036 |
| 相手ごとの得点と値の差の絶対値の平均（65 相手） | 0.264 | 0.138 |
| バトンタッチを使った局 | 0.6%（6 局、得点 0.83） | 1.2%（12 局、得点 0.75） |
| ライチュウをメガ進化させた局 | 30.4%（得点 0.247、しない局 0.214） | 17.4%（得点 0.385、しない局 0.302） |
| クエスパトラを選出した局 | 41.7%（得点 0.211、しない局 0.233） | 69.2%（得点 0.321、しない局 0.305） |

同じ局の番号の 999 組で対にした得点の差は +0.092 [+0.055, +0.129] で、95% 区間は 0 を含まない。

得点と値の差は 2 つの量で縮んだ。平均の差は −0.248 から +0.036 になり、絶対値は 15% になった。相手ごとの差の絶対値の平均は 0.264 から 0.138 になり、52% になった。

両席を同じ評価モデルが打つので、得点の上がり方には 2 つの成分が混ざる。1 つはユーザーの構築を打つ側の上達で、もう 1 つは相手の 65 構築を打つ側の変化である。この測りでは 2 つを分けられない。

### 4.4 本番のプールで弱くならないか

value-b の選出を `regmc-matchupweb` の 2,145 組で解いた（`C:/tmp/ika438/presolve.py`、198 秒）。対戦評価は value-b x1 対 value-mc6 x1、65 構築のプール、幅 12、rank-leaf、q-nocover（q-mc6）、裏非公開、種 44403、SPRT(−10, 0)。

| 量 | 値 |
|---|---|
| 判定 | H1（10 Elo 以上悪いとは言えない） |
| 対の数 | 1,132 対（2,264 局）、204 秒 |
| 勝ち・引き分け・負け（対） | 268・626・238 |
| value-b の得点 | 0.513、+9.2 Elo [−4.3, +22.8] |
| LLR | +2.976 |

2 万局を足しても、本番のプールでの強さは下がらなかった。区間は 0 を含むので、強くなったとは言えない。

## 5. 判定

§2 の 1 行目の条件を照らす。

| 条件 | 結果 | 満たすか |
|---|---|---|
| 勝率が上がり、差の 95% 区間が 0 を含まない | +0.092 [+0.055, +0.129] | 満たす |
| 値と得点の差の絶対値が半分以下 | 平均の差 0.248 → 0.036（15%）、相手ごとの差 0.264 → 0.138（52%） | 平均の差は満たす。相手ごとの差はわずかに届かない |

評価モデルは、局を足すことでこの構築の値を学び、打ち方も上がった。一方で、ギミックの中身であるバトンタッチの使用は 0.6% から 1.2% にしか増えていない。得点の上がり方は、クエスパトラを選出に入れる局が増えたこと（41.7% → 69.2%）と、選出の値が実勝率に合ったことによる部分が大きいと読める。バトンの流れそのものは、まだ学べていない。

ユーザーと決めた手順に従い、バトンの使用が増えなかったので 2 回目を回す。2 回目では、生成の片方の席だけでクエスパトラのめいそうからバトンタッチまでの流れを固定する。この流れを含む局を学ばせ、評価モデルが流れの後の局面の値を学べるかを見る。IKA-445 に進むかは 2 回目の結果で決める。
