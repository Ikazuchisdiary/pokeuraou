# IKA-181 味方を狙う単体技が候補集合に無い

Notion: https://app.notion.com/p/3e64b8acaa6c811389faf97eab5621cb

駆動のスクリプトは `C:/tmp/ika181/` で回し、写しを `scratchpad/ika181/` に置いた。

## 問い

Showdown は `normal` の単体技で味方を選べる。Python の行動一覧（`actions._targets_for`）は、この選択肢を候補集合に出していなかった。
味方の特性や持ち物で得がありうるときに味方への技を足すと、強くなるか。

## 答え

- Showdown の `validTargetLoc` で味方を選べる種別は `normal`・`any`・`adjacentAlly`・`adjacentAllyOrSelf` の 4 つ。今の一覧は `normal` だけ味方を出していなかった。
- M-C の 65 構築のうち、味方に撃って得がありうる組がある構築は 19（対 2,145 のうち 1,064）。ほとんどはブリジュラスのじきゅうりょく（Stamina）で、121 組のうち 104 組。
- 旗 `benefit` は、得がありうるときだけ味方への技を足す。行動の数は 1 側あたり平均 52.0 から 53.4 に増え（+2.6%）、Q の行列は 4.8% 大きくなった。
- port に 1 つ不具合があった。味方を狙ったふいうちが、Showdown では当たるのに port では失敗した。直した。
- 対戦評価（得がありうる組だけ、生成の形）: SPRT(0, 10) は 417 対で H0。固定 1,500 対は Elo +3.7 [−0.7, +8.2]。強くなったとは言えない。
- 提案: 既定は off のまま。旗と port の直しは残す。

## 1. Showdown の規則と、Python・port の扱い

`sim/battle.ts` の `validTargetLoc` は、`normal` を `isAdjacent` だけで判定する。ダブルでは味方は隣なので、味方を選べる。
`sim/side.ts` は `targetTypeChoices` の 5 種（`normal`・`any`・`adjacentAlly`・`adjacentAllyOrSelf`・`adjacentFoe`）で対象を求め、そのあと `validTargetLoc` で確かめる。

| 種別 | Showdown が味方を許すか | 直す前の Python の一覧 |
|---|---|---|
| normal | 許す | 相手だけ |
| any | 許す（自分以外） | 相手と味方 |
| adjacentAlly | 味方だけ | 味方 |
| adjacentAllyOrSelf | 味方か自分 | 味方と自分 |
| adjacentFoe | 許さない | 相手だけ |

- `tests/test_actions.py` の近い誤り（near-miss）は、対象の数の誤りしか試していない。味方を狙う `normal` の技は一度も Showdown に聞いていなかった。これが見落としの理由。
- port の `legal.rs` は Python の一覧と同じ形で、同じく味方を出さない。port の解決（`moves.rs` の `resolve_targets`）は負の対象を味方として扱う。

## 2. プールの数え上げ（`count.py`、出力 `count.json`）

構築ごとに、6 体のうち異なる 2 体の順序付きの組（使い手と味方）と、使い手の `normal` の技について `actions.ally_benefits` を当てた。特性と持ち物は構築の値で読む。

| 項目 | 数 |
|---|---|
| 構築 | 65 |
| 得がありうる組がある構築 | 19 |
| 対（どちらかの構築に組がある） | 1,064 / 2,145 |
| 組（構築・使い手・味方・技） | 121 |
| `normal` の技の枠（全構築） | 846 |

| 理由 | 組 |
|---|---|
| 特性 じきゅうりょく（ブリジュラス） | 104 |
| 技 スキルスワップ | 5 |
| 技 じこあんじ | 5 |
| 特性 かるわざ（はたきおとす・トリック） | 4 |
| 特性 もらいび（おにび・マジカルフレイム） | 3 |

- 課題の例（じゃくてんほけん・せいぎのこころ・ちょすい・ちくでん）は、プールに持ち主がいない。M-C の図鑑にはじゃくてんほけんが無い。
- ひらいしん（10 構築）は数えていない。ひらいしんは味方の電気技を相手に向けても自分に引き寄せる（`onAnyRedirectTarget`）。味方を名指ししても結果が同じなので、行動を増やさない。よびみずも同じ扱い。

`ally_benefits` が見るもの:
- 吸収する特性: ちくでん・でんきエンジン・ちょすい・かんそうはだ・そうしょく・もらいび・こんがりボディ・どしょく（その型の技、変化技を含む）
- 攻撃を受けて能力が上がる特性: せいぎのこころ・びびり・じょうききかん・ねつこうかん・みずがため・じきゅうりょく・ぎゃくじょう・いかりのこうら・でんきにかえる、くだけるよろい（物理）
- 状態異常で得をする特性: こんじょう・はやあし・ふしぎなうろこ・ポイズンヒール・どくぼうそう・ねつぼうそう
- あまのじゃく（能力を下げる変化技、すてゼリフ）、マイペース（いばる・おだてる）、かるわざ（持ち物を奪う技）
- 持ち物: じゃくてんほけん（効果抜群）、きゅうしゅうきゅうこん・ひかりごけ・じゅうでんち・ゆきだま・アッキのみ・タラプのみ
- 味方に使うための技: さきおくり・さいはい・かふんだんご・ハバネロエキス・デコレーション・じこあんじ・スキルスワップ・なりきり・なかまづくり・ひっくりかえす

ウェザーボール・だいちのはどう・-スキン系の特性・うるおいボイスで型が変わる技は、変わった後の型も含めて見る（多めに出す側に寄せた）。

## 3. 実装（既定 off の旗）

- `actions.ALLY_TARGETS`: `off`（既定）・`benefit`・`all`。`ally_targets(mode)` で区間だけ切り替える。
- `_targets_for` は、`normal` の技で、生きている隣の味方を相手の後ろに並べる（`any` と同じ並び）。`all` は全部、`benefit` は `ally_benefits` が真のときだけ。
- `play_game(ally_targets=(a, b))`: 側ごとの候補集合と解を、その側の旗の下で作る（IKA-413 の `binary_scope` と同じ区間、`_agent_scope`）。旗が違えば候補集合を共有しない（`same_menu`）。
- 記録: `allyTargets`・`allyMenus`（候補集合に味方への技があった手番）・`allyPlayed`（打った手番）。旗が off なら書かない。
- `PoolArm.ally_targets`、`tools/pool_match.py --ally-targets / --baseline-ally-targets / --pairs-ally-benefit`。ワーカーは席ごとに出す（陽性対照）。
- `portmenus.q_menus` は旗が off でないとき古い道を通る。port の `legal.rs` は味方を出さないので、port で候補集合を作ると Python と食い違う。

|---|---|---|---|
| off | 51.99 | 3,416 | なし |

## 5. port 対 Showdown（`diff_ally.py`）

`tools/diff_turn.py` の比べ方（1 ターンずつ、乱数を固定して局面を比べる）を使った。プールの構築から 4 体を選び、先発を組の 2 体にする。各側は確率 0.5 で味方を狙う行動を選ぶ（旗 `all`）。Showdown は味方を狙う選択を 1 つも拒まなかった（`refused a choice` 0）。

| 走らせ方 | 先発 | port | 比べたターン | 味方を狙ったターン | 味方ターンの乖離 | うち注記なし |
|---|---|---|---|---|---|---|
| 旗 off（対照） | 得のある組 | 直す前 | 2,348 | 0 | なし | なし |
| 旗 all | 得のある組 | 直す前 | 2,260 | 1,985 | 103（5.2%） | 37（1.9%） |
| 旗 all | 得のある組 | 直した後 | 2,260 | 1,985 | 87（4.4%） | 23（1.2%） |
| 旗 off（対照） | どの 2 体でも | 直す前 | 2,182 | 0 | なし | なし |
| 旗 all | どの 2 体でも | 直す前 | 2,110 | 1,849 | 120（6.5%） | 94（5.1%） |
| 旗 all | どの 2 体でも | 直した後 | 2,110 | 1,849 | 75（4.1%） | 58（3.1%） |

旗 off の全体の乖離は 3.71%（注記なし 1.32%、得のある組）と 4.22%（同 2.66%、どの 2 体でも）。直す前と直した後の exe で数は同じだった。

- 注記なしの乖離のうち、味方へのふいうちが一番多かった（直す前、どの 2 体でも 94 のうち 41、得のある組 37 のうち 14）。
- 原因: `moves.rs` のふいうちは「まだ動いていない**相手**が攻撃技を選んでいる」ことを求めていた。Showdown の `onTry` は対象が攻撃技を使うかだけを見て、側を見ない。直し: 側の条件を外した（1 行）。
- 直した後、味方ターンの注記なしの乖離は 3.1%（どの 2 体でも）と 1.2%（得のある組）。旗 off の 2.7% と 1.3% とほぼ同じ。残りは技がばらけていて（はがねのローラー 7、フレアドライブ 7 など）、ノーてんきやオーロラベールなど味方に限らない既知の型が混ざる。1 つずつは調べていない。
- 比べ方が乖離を拾える対照: Showdown にだけ味方の対象を相手 1 に替えて渡すと（`--control`）、比べた 437 ターンの 78.5% が乖離した。
- 通りがかりに見たもの（味方とは関係ない）: メガシンカしたターンのはたきおとすでメガストーンが外れる（IKA-214 の既知の穴）、ノーてんきの下のエレクトロビーム。

## 6. 対戦評価（`board.py`、10/2 01:45〜02:05、専有）

条件: `match_queue --pool`、served 2 サーバ・24 ワーカー、裏非公開、幅 12、rank-leaf、q-nocover（Q は q-mc4）、両側とも value-mc4x2（IKA-409 のファイル。`data/models/value-mc4.pt`・`-s1.pt` と sha256 が同じ）、選出は IKA-409 の先に解いた store の写し（両側に渡した）。port は直した後の exe。

| 対戦 | 中身 | 局 | 結果 |
|---|---|---|---|
| id-old 対 id-new | master のコードと直す前の exe の両側 off 対 このブランチと直した後の exe の両側 off、全部の対、同じ種 | 200 対 200 | **200/200 が同じ局** |
| id-new 対 chg-ben | 両側 off 対 両側 benefit、全部の対、同じ種 | 200 対 200 | **60/200 が違う局**。候補集合に味方への技があった局 26、ほか 34 局は最初に違った手番で合法な行動が増えていた（34/34） |
| main-sprt | benefit 対 off、得のある組の対、SPRT(0, 10) | 417 対で打ち切り | **H0**、LLR −2.947。対の内訳 勝ち 11・分け 395・負け 11 |
| main-fixed | 同じ、固定 1,500 対 | 3,000 局 | 50.53% ±0.64%、**Elo +3.7 [−0.7, +8.2]**。対の内訳 勝ち 56・分け 1,404・負け 40 |

- 陽性対照: main-fixed で試す側の候補集合に味方への技があった手番は 859、打った手番は 55（全部の行動の手番は両側で 26,500）。main-sprt では 273 と 10。
- 比べ方が違いを拾える対照: id-new 対 chg-ben で 60 局の違いを拾った。
- 読み: 得のある組だけで打っても、10 Elo の上積みは無い（H0）。固定 1,500 対の点推定は +3.7 で、区間が 0 をまたぐ。全部の対で打てば、得のある組は約半分（1,064 / 2,145）なので、効きはさらに薄まる。
- 時間の費用は測っていない（両側 off の同じ対の壁時計を並べていない）。行動の数の増え方（Q の行列 +4.8%）が上限の目安。

## 7. 提案

- 既定は off のまま。SPRT(0, 10) が H0 なので、生成と対戦評価の既定は変えない。
- 旗は残す。人と打つ道具や検討で、味方への技を候補に見せたいときに使える。そのときは `legal.rs` にも同じ規則が要る（port で候補集合を作る道 `portmenus` は、旗が off でないと古い道を通る）。
- port のふいうちの直しは入れる。旗が off なら味方へのふいうちは出ないので、生成の局は変わらない（id-old 対 id-new が 200/200 同じ）。
