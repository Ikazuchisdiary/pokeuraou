# IKA-349: 対戦モードと分析モードで画面を分けた —— 上の帯で「対戦 | 分析」を行き来し、設定（テーマ・AI の読みの見せ方（見せる／手を送るまで隠す／隠す）・分析の読みの設定と読みの量）は歯車の中へ。分析は対局全体の値の推移とこのターンに打った手の評価を足し、port の注記を人向けの日本語にした

2026-09-27。担当 IKA-349（worker）。master 91683b5 から切った `ika-349-mode-split`。画面の写しと試作は `C:/tmp/ika349/`（コミットしていない）。
デザインは IKA-345 と同じデザイン担当と、実際の画面のスクリーンショットで 5 往復して詰めた（§3）。

答えた問い（課題の本文。9/27 ユーザー）:
1. 対戦モード: 主役は場とあなたの手。AI の読みのオンオフ（既存の「手を入れるまで読みを隠す」との関係も決める）。選んだ状態は localStorage
2. 分析モード: 記録のターンの移動、混合・値・読み筋を大きく、対局全体の値の推移を全ターンで
3. IKA-345 から回したもの: 読んでいる途中で幅を広げる操作、2 つの読みを並べて比べる表示
   → 途中で入った指示（9/27 ユーザー、調整役経由）で、比べる表示は要らない（幅を変えたら、その設定で読み直すだけ）。一度作った A・B の比較の表は外した
6. 途中で入った指示（同）: デザインの設定とエンジンの設定は歯車の中にまとめ、画面には使う操作だけを残す。既定のままで快適に使えること
4. 注記の port の id（`attacker.ability:magicbounce` など）を、特性・技の日本語名＋近似の旨の人向けの文に（名前は Showdown のデータから生成したもの）
5. 対局が終わったらその記録を分析で開く導線、「この局面を検討」、2 つの画面の行き来の形

## 1. 入れたもの

### 1.1 2 つの画面の行き来
* 対戦（`play_human --person web --view`、play.py では :8332）と分析（`analyze`、:8337）は別のプロセス・別のサーバのまま。上の帯の「対戦 | 分析」で互いを別のタブ（名前付きのタブ `pokeuraou-game`・`pokeuraou-analysis`、2 度目からは同じタブ）で開く。
* 相手の画面のアドレス: サーバがページの meta に書く（`LiveServer(links=...)`）。`tools/play_human.py --analysis-url`・`tools/analyze.py --game-url`（足した旗）。`tools/play.py` は自分のポートで両方を渡す。旗が無ければ、同じホストの :8337・:8332 と見なす。
* 分析の画面の URL の問い: `?open=current`（進行中の局の今の局面、play_human `--current-out` のもの）、`?open=last&turn=T`（記録を読み直してから、最後の局のターン T）。ページは選んで読み始め、問いを URL から消す。
* 対局の途中の「この局面を検討」（上の帯の「分析」）は、読みの段に従う: 見せる＝いつでも、手を送るまで隠す＝手を送った後だけ、隠す＝対局が終わるまで押せない（title で理由）。押せる時の title は「読んでいる間は AI の手の時間とコアを取り合います」。
* 終局: 場に重ねるカードに理由（「ターンの上限で打ち切り」「AI の 4 体がひんし」など）と「この対局を分析する」（`?open=last`）。下に「続けて打つには tools/play.py を起動し直してください」、次の局が残っていれば「次の局を待っています」（`play_human` が局の始めに `session` の出来事 `gamesLeft` を出す）。経過の欄の各ターンに「分析」（`?open=last&turn=T`、終局の後だけ）。

### 1.2 対戦の画面
* AI の読みの見せ方「見せる／手を送るまで隠す／隠す」（歯車の中、§1.4）。既存のチェック欄はこれにまとめた。既定は「手を送るまで隠す」、選んだ段は localStorage（`pokeuraou-read`、読めなくても動く）。
* 隠す: 読みの欄を消して 1 列（最大 760 px）、場の札を大きく（絵 112 px）、場の下に案内と「見せる」。
* 上の帯は ロゴ・「対戦 | 分析」・状態の札・歯車。375 px でも 1 段（状態の札は短い文、全文は title）。ダークでは選んだ段を溝より明るく。

### 1.4 歯車（設定）
* 上の帯の右端の歯車（40×40、aria-label・title「設定」、aria-expanded）。1280 は歯車の下に右端をそろえたポップオーバー（幅 340 px、外を押すか Esc で閉じ、フォーカスを歯車に戻す）、375 は下から出る全幅のシート（最大 85vh、掴みの印・「閉じる」、後ろを 40% 暗く）。
* 中の組: 表示（テーマ 自動／ライト／ダーク）、AI の読み（対戦の画面だけ。3 段と 1 行の説明）、読みの設定（分析の画面だけ。記録・読む側・幅・深さの上限・評価モデルなどの説明・「記録を読み直す」「この設定で読み直す」）、読みの量（閉じた折りたたみ。メモリの計器）。
* 値はその場で効く（保存のボタンは無い）。テーマと AI の読みは localStorage に残す。読みの設定（幅・深さの上限）は保存せず、道具が起動時に送る既定を表示する（画面は数を持たない）。既定のまま、歯車を開かずに対戦も分析もできる。
* 持ち時間・スレッド数は起動の旗（play.py / play_human / analyze）で決まるので、画面からは変えない（歯車の中の説明に出す）。

### 1.3 分析の画面
* 一番上に全幅の「対局全体の値の推移」: ◀ T ▶、全ターンの線（灰＝記録の値（側 0 の `searchValue` を読む側から）、側の色＝この画面で読んだ値、値の無いターンは細い破線でつなぐ）、ターンの札（今のターン、読んだターンに緑の印）。
  記録の値は局の一覧（catalogue）の決定ごとに `value` として送る（`analysis.Point.value`）。
* 値の推移のカードの見出しの行に、局の選択（小さなプルダウン）。記録のファイル・読む側・幅・深さの上限は歯車の中。「この局面を読む」「止める」は読みのカードの見出しの右。
* 5:7 の 2 列: 左は場 → 「このターンに打った手」（その下に注記）→ 経過・チーム（閉じる）、右は読み（読み筋は開いた状態）。960 px 以下は 1 列。
  375 の分析の札は 3 段（名前を札の幅いっぱい ／ 絵 40 px と % ／ HP の帯を札の幅いっぱい）: 札の内側が約 124 px しかなく、絵・帯・% を 1 行に並べると % がはみ出すため。
* このターンに打った手: 記録の各側の手（`ownChosen`・`foeChosen`、`analysis.Point.played`）を、読みが候補集合に付けるのと同じラベルにして読み始めに送る（`analysis` の出来事の `played`）。ページは読みの候補集合から引き、確率と損を出す。無ければ「候補集合の外」、確率 0.5% 未満は「打たない手」、損 0.02 以上は赤。
* 幅を変える: 歯車の中の幅・深さの上限を変えて「この設定で読み直す」を押すと、今の読みを止めて同じ局面をその設定で読み直す（読んでいる途中でも押せる。前の読みは残さない）。
  1 手の中の値の推移は読みごとに線を分け、同じターンの読み直しの目盛りは「T2 1 回目」「T2 2 回目」。
  深化の途中で候補集合そのものを広げる（行列に行と列を足して木を付け替える）作りにはしていない。
* 注記: port の注記を `src/pokeuraou/notes_ja.py` で日本語に（`analysis` の出来事の `notes`、元の文は `notesRaw` で title に）。`--out` の記録は port の文のまま。
  * 固定の文（`report("...")`）はすべて表で訳す（新しい文が port に入ると `tests/test_notes_ja.py` が落ちる）
  * `attacker./defender.ability:X`・`.item:X` は「近似: 攻撃側・防御側の特性 マジックミラー をダメージ計算に入れていない」（両側の同じ特性は 1 行）
  * `damaging move:`・`status move:`・`contact ability:`・`on-hit ability:`・`berry eaten by another:`・`boost:` は名前を入れた文、`depth-2 kept ...` は「選択的延長のセルで …」
  * 知らない文は「注記: 」＋元の文（中の id は名前に）
  * 名前はすべて `names.Localiser`（Showdown の vendor/data/text から生成）で引く

## 5. 別課題の候補
