## 1. Showdown の計算（vendor a5df827。champions mod は `hitStepAccuracy` を上書きしない）

`sim/battle-actions.ts` 690〜754 行の `hitStepAccuracy`（OHKO の枝は省く）:

```
accuracy = this.battle.runEvent('ModifyAccuracy', target, pokemon, move, accuracy);   // 712
if (accuracy !== true) {
    let boost = 0;
    if (!move.ignoreAccuracy) {
        const boosts = this.battle.runEvent('ModifyBoost', pokemon, null, null, { ...pokemon.boosts });
        boost = this.battle.clampIntRange(boosts['accuracy'], -6, 6);
    }
    if (!move.ignoreEvasion) {
        const boosts = this.battle.runEvent('ModifyBoost', target, null, null, { ...target.boosts });
        boost = this.battle.clampIntRange(boost - boosts['evasion'], -6, 6);
    }
    if (boost > 0) accuracy = this.battle.trunc(accuracy * (3 + boost) / 3);
    else if (boost < 0) accuracy = this.battle.trunc(accuracy * 3 / (3 - boost));
}
if (move.alwaysHit || (move.id === 'toxic' && gen >= 8 && pokemon.hasType('Poison')) ||
    (move.target === 'self' && move.category === 'Status' && !target.isSemiInvulnerable())) {
    accuracy = true;
} else {
    accuracy = this.battle.runEvent('Accuracy', target, pokemon, move, accuracy);      // No Guard など
}
if (accuracy !== true && !this.battle.randomChance(accuracy, 100)) { miss }             // 738
```

* **順番**: 特性・道具の補正（ModifyAccuracy）が先、段階が後。段階は命中と回避を 1 つの段にまとめ（命中を先に ±6 で切り、回避を引いてからもう一度 ±6 で切る）、`boostTable` ではなく `(3+b)/3`・`3/(3-b)` を掛けて `trunc`。`boostTable = [1, 4/3, 5/3, 2, 7/3, 8/3, 3]` を小数で掛けるのは連続技の 2 発目以降（`multiaccuracy`、`hitStepMoveHitLoop` 912 行、champions mod の scripts.ts 483 行も同じ形）だけ
* **`ignoreEvasion` の技でも使い手の命中の段階は読む**（`ignoreAccuracy` だけが使い手の段階を外す）
* **確率**: `randomChance(n, 100)`（sim/battle.ts 350）→ `prng.randomChance`（sim/prng.ts 115）は `this.random(denominator) < numerator`。0〜99 の整数と比べるので当たる確率は n/100、n ≥ 100 は必ず当たる
* **丸め**（sim/battle.ts）:
  * `chainModify`（2321）: `previousMod = trunc(modifier * 4096)`、`nextMod = trunc(num * 4096 / den)`、`modifier = ((previousMod * nextMod + 2048) >> 12) / 4096`
  * `runEvent` の終わり（929〜933）: 戻り値が非負の整数なら `relayVar = this.modify(relayVar, this.event.modifier)`
  * `modify`（2331）: `tr((tr(value * modifier) + 2048 - 1) / 4096)`（半分は切り捨て）
  * 最初の `chainModify` は 4096 からなので値そのもの。だから補正 2 つまでは順番が効かない
* **補正の handler**（data/abilities.ts・data/items.ts。handler の順は priority の高い順、同じ priority は持ち主の速さの順〔`comparePriority`、同速は乱数〕）:

* **ユニーク** の `onAnyModifyBoost`（命中・回避の段階を 0 に。攻撃・防御の段階も）: port のエンジンが名前を出さない id（inert.rs）。g600 0 体
* **一撃必殺技**（じわれ・ぜったいれいど・つのドリル・ハサミギロチン）: Showdown は補正も段階も掛けず 30（こおりタイプでない使い手のぜったいれいどは 20）+ レベル差、レベルが低ければ無効。port は普通の技として補正と段階を掛ける。g600 0 回
* **こうかくレンズ・ひかりのこなの順番**: 前に -1 の補正（ふくがん・はりきり・ゆきがくれ）があると、2 つの順で 1 違う。Showdown は持ち主の `pokemon.speed`（同速は乱数）で、port は使い手が先。g600 ではひかりのこな 0 体
* **連続技の 2 発目以降の命中**（`multiaccuracy`、トリプルアクセル・ネズミざん など）: port は技ごと断る。入れるときは、Showdown が `boostTable` の小数を先に掛け、`ModifyAccuracy` の終わりの `modify` は値が整数のときにしか掛からない（67.5 には補正が掛からず、`random(100) < 67.5` で 68%）ことに注意。g600 でトリプルアクセルは 9 体
* **effects.rs の `Slot::Accuracy` の行**（hustle 0.8・widelens 4505/4096・zoomlens 1.2・brightpowder 0.9）はどこからも読まれていない。値も Showdown と違う（ズームレンズは 4915/4096、ひかりのこなは 3686/4096）。消すか `showdown_accuracy` の表にまとめるのが筋
