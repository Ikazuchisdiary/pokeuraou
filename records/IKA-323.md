# IKA-323: 根の葉の順位のメニューから覆いを外す —— 対戦評価では決まらない（SPRT(0, 10) は上限 2,000 対で判定なし、覆いなしの 50.90% ±1.35、Elo +6.3 [−3.1, +15.6]）。費用は同じで（1 決定あたりの CPU は −3%）、既定の局は 600/600 一致

2026-09-26。担当 IKA-323（worker）。master 9dc08de から切った `ika-323-root-no-cover`。

答えた問い: **根のメニュー（葉の順位 refs2 で並べる）から覆いを外し、12 本を全部順位で埋めると、対戦評価で強くなるか。**

用語: 「覆い」＝`narrow` の「全選択肢が 1 度は出る」ための貪欲な集合被覆。「裏」＝選出した 4 体のうち場に出ていない 2 体。「対戦評価」＝盤。

## 1. 実装

* **ラベル**: rank-fill のラベルに `-nocover` の接尾辞を足した（`refs2-nocover`、`refs2-fast-nocover`）。`search.rank_fill_covers(label)` が覆うかどうかを返す。
  `parse_rank_fill` は今までどおり (参照応手の数, fast) を返す。既定の `refs2` は今のまま
* **narrow**: `narrow(..., cover=False)` は、順位の上位 `limit` 本だけを取り、覆いを作らない。メニューに 1 度も出ない選択肢は
  `Narrowed.uncovered` / `uncovered_options` に残す（予算不足のときと同じ書き方）。`rank` を渡さない（ダメージ点だけの）`cover=False` は `ValueError` で止める
* **根だけ**: `selfplay._menus` が葉の順位のメニュー（根の 2 本と、根の double oracle の広いメニュー `wider`）を `cover=False` で作る。
  部分ゲーム（`search.py` の `narrow(limit=sub_limit)`）・deepen の子（`deepen.py`）・葉の順位の参照応手（`leaf_ranking` の `narrow(limit=8)`）は
  ダメージ点の narrow のままで、覆いを残す。ダメージの順位・方策の順位のときはラベルは何も変えない（rank-fill と同じ）
* **両席への届き**: ラベルなので、rank-fill の配管（IKA-268）にそのまま乗る。`pool_match.py` の腕ごとの `--rank-fill` / `--baseline-rank-fill`、
  記録の `rankFill`、provenance の `rankFills`、エージェント名の `/rankfill:refs2-nocover`、対戦評価のタグ `@rankfill:refs2-nocover`、
  `play_game` の `same_menu`（ラベルが違えば腕ごとにメニューを作る）
* **陽性対照の数え**: `narrow.COVERLESS[label]` に、覆いなしで作った根のメニューの数・選択肢を落としたメニューの数・落とした選択肢の数を足す。
  `pool_match.py` の worker の echo が、腕ごと・席ごとにその差分を出す（`coverless menus N (M leaving options off, K options)`）
* **原則の節**: narrow.py の冒頭に「覆いはダメージ点の盲点（まもる・変化技・交代が 0 点）を補うためのもの。葉の順位にはその盲点が無いので、
  根の葉の順位のメニューは覆いなしで作ってよい。消えた選択肢は `uncovered` に残し、`COVERLESS` で数える。ダメージ点のメニューは覆いを残す」を書き足した
* テスト `tests/test_root_no_cover.py`（5 本）: ラベル、narrow の覆いなし（上位 limit 本と一致・消えた選択肢が全部 `uncovered` にある・覆いありと違うメニューになる陽性対照）、
  ダメージ点だけの覆いなしは止まる、`_menus` の既定は数えず覆いなしは数える（広いメニューも覆いなし）、対戦評価の 1 局で覆いなしの腕だけが両席で数えられる（同じ覆いありの腕どうしは 0）。
  直す前の src（master）ではこのテストは集めの段で落ちる（`rank_fill_covers` が無い）

## 3. 対戦評価

形（IKA-292）: `match_queue.py --pool regmc-matchupweb --served --servers 2 --workers 24 --hide-bench --sprt 0 10 --games 2000 --value value-mc0.pt value-mc0-s1.pt
-- --baseline-inference-arm value --rank-leaf --baseline-rank-leaf --limit 12 --baseline-limit 12 --rank-fill <試す腕> --baseline-rank-fill refs2
--selection-store S --baseline-selection-store S`（`C:/tmp/ika323/board.py`）。両腕は mc0x2 を 1 つのサーバの腕で打つ。S は IKA-292 の全 2,145 対の store の写し
（対戦評価の中で選出を解かない）。試す腕 = 覆いなし。H1 は「覆いなしが 10 Elo 以上強い」。木はこの枝の a9290f9。

### 3.1 帰無対照（同じ腕どうし）

覆いなし 対 覆いなし（種 32301、100 対、SPRT なし）: `pair_divergence` は動いた対 0（100/100 が同じ局）、50.00% ±0.00、Elo 0。
echo はどちらの腕も `rank fill {'refs2-nocover': n}` で、覆いなしのメニューを数えている（2 つの腕が同じラベルなので数えは共有）。

### 3.2 発火率（`tools/pair_divergence.py`）

```

### 3.3 両席への届き

* **局の記録**: 4,000 局すべてで、記録の `rankFill` と provenance の `rankFills` が期待どおり（席 0 は `["refs2-nocover", "refs2"]`、席 1 は `["refs2", "refs2-nocover"]`、不一致 0）
* **worker の echo**（24 worker の和）: 試す腕は席 0（side 0）で覆いなしのメニュー 31,416（うち選択肢を落としたもの 24,197、落とした選択肢 142,603）、
  席 1（side 1）で 31,814（24,511、144,897）。相手の腕（refs2）はどちらの席でも数えが出ない（0）。rank fill の echo も腕ごとに `refs2-nocover` / `refs2`
* 覆いなしのメニューの 77% が何かの選択肢を落とし、1 メニューあたり平均 4.6 個（IKA-311 §4 の「両側で約 7.5 個」と同じ桁。こちらは 1 側）
* worker のログに Traceback は 0

```

読み:
* **強くなるとは言えないし、弱くなるとも言えない**。SPRT(0, 10) は上限まで走り、LLR +0.547（境は ±2.94）で判定なし。上限の固定数の答えとして、
  区間 [−3.1, +15.6] は 0 と +10 の両方を含む。点推定は覆いなしの向き（+6.3）
* IKA-312 の予言（実際の相手の方策に対する値 +0.009 [+0.003, +0.015]）を Elo に直した大きさは、S4 の例（1 決定あたり 0.0099 で +7.4 Elo）と同じ桁で、
  点推定 +6.3 と矛盾しない。ただしこの対戦評価の幅（±9 Elo）では、その大きさは見分けられない
* 費用は同じ（§2）なので、CLAUDE.md の「速さと強さの引き換え」の形の問題は無い（同じ費用の比較そのもの）

## 4. 判断

* **既定は変えない**（`refs2` のまま）。ラベル `refs2-nocover` は腕として残す（IKA-268・270 と同じく捨てずに口を残す）
* 覆いを外す向きの損は見えない（区間の下端 −3.1）。生成に使うかは別の問い（IKA-73 の形: 同じ壁時計で作ったプールから学んだ葉の強さ）で、
  費用が同じなのでその比較は「同じ局数」でよい
* 大きさ +6 Elo 前後を見分けるには、対戦評価で約 4 倍（8,000 対）の局が要る（±1.35% → ±0.7%）

## 6. 別課題の候補

* **覆いなしの大きさを決める**: 同じ形で 8,000 対（約 33 分の専有）、または覆いなし 対 覆いありを複数の種で。+6 Elo 前後が本物なら IKA-312 の予言と合う
* **生成で覆いなしを使うか**（IKA-73 の形）: 費用が同じなので、同じ局数のプールから学んだ葉の強さで比べられる
* **IKA-274 の Q 順位と組み合わせる**: IKA-274 は「Q で並べた覆いなしの幅 12 の再現率の多くは覆いを外したことから来る」と書いている。Q の順位に `-nocover` を付けた腕と、この refs2-nocover を比べる
* **`COVERLESS` をプロファイラの数えにも出す**: 今は対戦評価の echo だけ。生成の worker の報告（`profile_stages`）に出すと、生成の本でも陽性対照の数が取れる
