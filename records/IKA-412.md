# IKA-412 場の左右を入れ替えて教師局面を水増しする

Notion: https://app.notion.com/p/3ec4b8acaa6c81bdb83dde40155a4c07

駆動のスクリプトは `C:/tmp/ika412/` で回し、写しを `scratchpad/ika412/` に置いた。

## 問い

評価モデルは在場を平均・最大でまとめるが、体ごとの `active_slot_0/1` と枠ごとの場の状態（`slot{0,1}_…`）は持つ。
場の左右（片側・両側、最大 4 通り）を入れ替えた局面は、規則の上では同じ値のはず。入れ替えて水増しすれば、1 つの局面から 4 つの教師が取れるか。

## 答え

**水増しは効かない（捨てる）。** 規則は左右で（ほぼ）変わらず、入れ替えは作れる。ただし今の評価モデルはもともと左右にほぼ鈍く、水増しで学ばせると鈍さは 13 倍増えるが、保留局の損失は種の揺れの中に収まる。対戦評価（SPRT(0,10)）の計画は立てない。

| | value-mc4 x2 | 水増しあり x2 | 差 |
|---|---|---|---|
| 保留局の損失（そのままの並び） | 0.3910 | 0.3908 | 0.00018（保留局の抽出の se 0.00003。種の揺れ 0.0006 より小さい） |
| 左右を入れ替えた並びでの損失（両側） | 0.3914 | 0.3908 | |
| 入れ替えでの勝率の動き（平均 \|Δp\|、両側） | 0.0132 | 0.0010 | |

### 見つけたこと（先に）

1. **入れ替えは「在場の枠」の反転では足りず、体の並びごと入れ替える。**
   局面の `pokemon` の並びは場の順（位置 i の体が `pokemon[i]`、`active == [0, 1]`）で、交代は並びの 2 要素を入れ替えて `Pokemon.slot` を振り直す（`_do_switch`）。
   `active` だけを反転すると port の交代が壊れ（交代先が `active=[1,1]` になる）、行列のセルの約 4 割が 0.1 級にずれた。
2. 入れ替える物（`slotswap.swap_positions`）:
   * `Side.pokemon` の 0 と 1、`Pokemon.slot` の振り直し、`Side.active`・`active_index`・`mega_capable_slots` の対応
   * `Side.slot_conditions` の 0 と 1
   * 入れ替えた側の体を `source_slot` に持つ効果の、位置の桁（`"01"` 形式と `"p1a"` 形式）
   * **`twoturnmove.extra.targetLoc`**（ためる技の狙い先は体でなく位置）。これを見落とすと、ファントムフォースの 2 ターン目が別の相手に当たり、最大 0.22 ずれた。直すと 0.07。
   * 行動は `slots` を反転し、味方の対象 -1/-2 と相手の対象 1/2 を、入れ替えた側に合わせて交換する（`swap_action`）。
   * 動かさない物: 控え、`Pokemon.slot` 以外の体の状態、場、側の状態。
3. 符号化の配列では、入れ替えた側の体の行 0 と 1、`active_slot_0/1` の列、`slot0_* / slot1_*` の列を入れ替える（`swap_encoded`）。**`encode(入れ替えた局面)` と配列の入れ替えが完全に一致する**ことをテストで確認した。
4. **M-C に Ditto は居る**（レギュレーションの species に `ditto`、語彙に `imposter` = 116）。ただし生成した 12,436,572 行に Imposter を持つ体は 0（学習の始めに数えた）。入れ替えの除外（`position_reader_rows`）は実装・テストしたが、今のデータでは何も除かない。
5. 「前のターンにまもったか」（`stall`）・こだわり・きあいのタスキ・最後に使った技などは**体ごと**に局面が持ち、port の枠で持つ配列（`attacks`・`hurt_this_turn`・`move_failed`・`acted`・`move_hit`・`move_start_hp`）はターンの中だけ（`Turn::new` で空から始まる）。左右の入れ替えで変わる割合は、これらの状態を持たない局面と同じ（§1.3）。

## 1. 規則の確かめ（port 対 自分）

`tools/slot_swap_check.py`。記録の局面を無作為に 3,000（局面を決定ごとに一様に引く。`data/selfplay-mc4`、seed 0）取り、探索の候補（幅 6、両側）で 1 ターンの hp-share の行列を port で解き、入れ替えた局面（候補も対応させて）の行列と全セルを比べる。予算は `Budget.matrix()`（中央の乱数、同速は列挙）。3 つの入れ替え（自分側・相手側・両側）。

### 1.1 結果

```
                       入れ替えた局面          1e-6 超      2e-3 超   セルが 1e-6 超      最大のずれ
  gen-4 の局 3,000 局面  自分側                 270 (9.0%)   6        612 / 104,450      0.019
  （targetLoc の対応後） 相手側                 275          8        609                0.070
                        両側                   480 (16.0%)  13       1,180              0.070
  gen-3 の局 3,000 局面  自分側                 276          6        597 / 103,916      0.077
  （seed 1）             相手側                 275          8        577                0.055
                        両側                   477          14       1,128              0.077
  （参考）targetLoc の対応前  自分側 273 / 10, 相手側 278 / 11, 両側 486 / 20、最大 0.221
```

局面の 91% は 1e-6 以内で一致、99.8% は 2e-3 以内（相手側）。一致しないセルは全セルの 0.6%（自分側）で、そのずれの平均は 3.5e-5（セルあたり）。

対照（比べ方が落ちうること）:
* `--control actions`（局面だけ入れ替えて候補はそのまま）: 2,970 / 3,000 局面が 1e-6 超、2,958 が 2e-3 超（最大 1.0）。
* `--control sources`（`source_slot` の桁を入れ替えない）: **本線と全く同じ数**。つまり、この標本では `source_slot` の対応が答えを動かす局面が無く、この桁の入れ替えが正しいことは**データでは確かめていない**（テストは形だけ）。
* 入れ替えの作り方の誤りは、前述の `active` だけの反転で 4 割のセルがずれた形で出ており、比べ方は落ちうる。

### 1.2 一致しない局面の型

2e-3 超の局面（上位 10 点を事例ごとに）と、2e-3 以下を無作為に 120 局面（最もありそうな枝の局面まで比べた）で型を分けた。**同速の乱数の扱いが位置に依存している型は見つからなかった**（同速かどうかを局面ごとには数えていない）。メガシンカの宣言も、独立の原因としては出なかった（メガの絡む局面が多いのは、メガの体が多いため）。

| 型 | 原因 | 規則は左右で違うか | 数 |
|---|---|---|---|
| A. ためる技の狙い先 | `twoturnmove.extra.targetLoc` が位置。入れ替えの作りの抜け（直した） | いいえ（体を追う） | 3,000 中 9 局面が持つ |
| B. 全体技で先の相手が倒れると、後の相手の「味方を守る」特性・オーラが消える | port が全体技を 1 体ずつ当てる。Showdown は先に全員のダメージを計算してから与える（`getSpreadDamage`）。port の注記（`field_for_hit`）に、Ruin 系だけを戻して、フレンドガード・オーラ・ノーてんきは戻さないとある | **いいえ（port の癖）。オラクルで確認** | 大きいずれ（2e-3 超）の主因。フレンドガードを持つ 26 局面で 2e-3 超が 23%（持たない 0.2%）、フェアリーオーラ 217 局面で 2.3%（0.3%）|
| C. 全体技の追加効果（ひるみ・やけど・能力変化）の枝の数え方 | 全体技の追加効果は 2 体分までの組を列挙し、残りは「起きなかった」にする（`spread_secondaries`）。落とす枝が相手の位置の順で決まる | いいえ（port の近似。Showdown の追加効果は体ごとに独立） | 1e-6〜2e-3 のずれの大半（無作為 120 局面のうち 97 は最もありそうな枝の局面が同じで確率だけ違い、20 は枝の数が違う）。ずれは枝 0.3% 級 |
| 残り | 最もありそうな枝で hp が違う 2 局面（B か C と思う。調べていない） | | 2 / 120 |

B のオラクル確認（`scratchpad/ika412/spread_probe.py`）: 相手の 2 体は イッカネズミ（フレンドガード、味方への技のダメージ 0.75 倍。HP を絞って振る）とカビゴン（左右を両方の順で試す）、自分はサーフゴーのゴールドラッシュ（全体技）で、相方のガブリアスが先にイッカネズミを削って、ゴールドラッシュで倒す。Showdown の 2 体目へのダメージは、1 体目が左でも右でも **208/267 で同じ**（1 体目が倒れてもフレンドガードは効いたまま）。port は 1 体目が左なら **188/267**（フレンドガードが消えた）、右なら 208/267。これは入れ替えと関係なく、実戦でも起きる port の不具合（別課題の候補）。

### 1.3 体ごとの状態が枠に結びついていないか（調整役の懸念）

400 局面（無作為、両在場が生きている局面から 360）で、**自陣の左の体だけ**に次の状態を足し、左右を入れ替えて行列が変わる局面の割合を、状態を足さない場合と比べた（`scratchpad/ika412/slotstate.py`、1 つの状態あたり 720 回 = 局面 360 × 2 側。下表は自分側の入れ替え）:

```
  足す状態               入れ替えで 1e-6 超  2e-3 超   足した状態が答えを動かす局面（正の対照）
  （足さない・参考）     9.0%（3,000 中）    0.2%      —
  stall（まもるの連続）  45 / 360 (12.5%)    1         155 / 360 が 2e-3 超で動く
  こだわり（スカーフ）   33 / 360            1         （候補が変わるので比べられず 1 局面）
  最後の技・失敗         45 / 360            1         6 / 357
  被弾回数・動いた回数   45 / 360            1         0 / 338（ふんどのこぶしなどの技が無く、この標本は試せていない）
  出たばかり             45 / 360            1         0 / 321（ねこだましの局面が無い。同上）
  タスキ + HP 半分       33 / 360            1         72 / 77
  やけど                 36 / 360            1         314 / 324
  能力変化               44 / 360            1         181 / 261
  ちょうはつ             41 / 360            1         0 / 143（効く局面が候補を変えるだけ）
```

2e-3 超の 1 局面は毎回同じ（§1.2 の B）。どの状態も、足さない場合の割合（9〜12%、2e-3 超 0.2〜0.3%）と変わらず、足したことで左右の入れ替えに弱くなる状態は見つからなかった。「偏りの上位」に stall・タスキ・いのちのたま・状態異常が出たのは、各特徴を持つ局面の数が多いだけだった（`enrich.py`）: 入れ替えで 1e-6 超に動く割合は stall あり 7.6% / なし 10.0%、タスキ 9.5% / 8.7%、いのちのたま 9.7% / 8.6%、状態異常あり 7% / なし 9%。強い偏りは B の特性（フレンドガード 23% 対 0.2%）だけ。
port のソースでは、跨ぎターンの状態は局面の `Pokemon`・`Side` の欄だけが運ぶ（`resolve.rs` の枠の配列は `Turn::new` で空から始まる）。`commands.rs` の枠の旗は途中停止の再開用で、port が自分で作ったものを返す。

### 1.4 確かめていないこと

* 同速の扱い（位置による決め方）を局面ごとに数えていない。上位 10 点と無作為 120 局面では出なかっただけ。
* C の「Showdown の追加効果は体ごとに独立」は、ソースの読みで、オラクルでは試していない。
* 在場が 1 体（片方が倒れた局面）の入れ替えは、標本に少ししか含まれない。
* ためる技・`source_slot`・ねこだまし・ふんどのこぶしは、データの標本では効く局面が少なく、入れ替えの正しさは形のテストだけ（`source_slot` は対照が本線と同じ）。
* 記録の局面は M-C の 65 構築のプールの自己対戦に限る。

## 4. テスト

`tests/test_slotswap.py`（9 本、`-n 0`）:
* 局面の入れ替えは二度でもとに戻る（3 通りすべて、変わらないことで空振りしない確認つき）
* 入れ替えが動かす物（並び・`slot`・`active`・`slot_conditions`・`source_slot`・`targetLoc`）
* 符号化の配列の入れ替えが、入れ替えた局面の符号化と一致し、二度でもとに戻る。torch のバッチ版が numpy 版と一致する
* 網が左右を区別するのは `active_slot_*` と `slot*_*` の入力の重みだけ: 初期値では区別し（対照）、その重みを 0 にすると答えが一致する（< 1e-5）
* Imposter を持つ局面（控えの Ditto を含む）が検出され、`draw` が入れ替えないこと（対照: 他の行は入れ替わる）
* port 対 自分: 入れ替え後の行列が元と 2e-3 以内。同じ比較が、候補を対応させない対照では 0.02 超ずれる（比べ方が落ちうる）
* 行動の入れ替えが対象の番号も動かす

`ruff check` は通る。

## 5. 別課題の候補

* **全体技で先に倒れた相手のフレンドガード・オーラ等が後の相手に効かなくなる port の不具合**（§1.2 B）。`rust/src/moves.rs` の `field_for_hit` が Ruin 系だけ戻している。Showdown は先に全員のダメージを計算してから与えるので、フレンドガード（0.75 倍）・フェアリーオーラ・ダークオーラ・オーラブレイク・ノーてんき等を同様に戻す。オラクルの再現は `scratchpad/ika412/spread_probe.py`（直す前の exe で 188 対 208）。
* 全体技の追加効果の枝の打ち切り（§1.2 C）。打ち切る枝が相手の位置の順で決まる。質量は 0.3% 級。

## 6. 機械時間

* port の確かめ 3,000 局面: 1 コア 23〜29 秒 × 6 回（本線 2、対照 2、gen-3 1、再実行 1）。専有（showcase）の待ちで 7 分の遅れ。
* value-mc4 x2 の入れ替えの動き: GPU・4 コア 282 秒。保留局の損失の比較 2 回: 331・318 秒。
* 学習 2 本: `--exclusive --gpu` 1,379 秒（715 + 664、GPU 全体の最大 4,186 MB）。
* port の release ビルド: 8 コア 75 秒。
