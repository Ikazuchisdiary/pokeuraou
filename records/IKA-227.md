# IKA-227: diverge_report も途中交代で止まったターンを続けて比べる —— 20 種 × 20 局で脇に置いていた 129 ターンを全部採点し、うち乖離 8（silent 3・flagged 5）。壊した build（ika211-control）は前は本物と 1 文字も同じ報告だったが、後は同じ 129 ターンで 65 外れ、U-turn・とんぼがえり・すてゼリフが順位の上に来る。`--jobs N`（種ごとの並列）を足し、`--jobs 1` と集計がバイト一致

9/24。ブランチ `ika-218-227-compare-tools`（master f025265 から、IKA-218 と同じ枝）。

## 1. 何をしたか

* **続け方は diff_turn（IKA-217）のものをそのまま使う。** port と Showdown が両方とも途中交代で止まったターンは、port の pause を `diff_turn.PortPending` に置き、以後の Showdown の step（`diff_turn.StepTap` が記録）ごとに `diff_turn.follow_port` で再開する。交代先は Showdown が受け取った選択から読む（`showdown_picks`）。ターンが終わったら、その終わりの局面を他のターンと同じ `_tally` で採点する。
* **Showdown を進めるのは今までどおり run の次の反復の `default` だけ。** port は Showdown を進めず、乱数も引かないので、**打つ局と、前から採点していたターンの判定は 1 つも変わらない**（§2 で確かめた）。
* 最後の反復（max-turns 目）で止まったターンは、次の反復が無いので、ループの後に同じ `default` を送って終わらせる。以後は何も採点せず乱数も引かない。これが無いと 129 中 8 が「battle stopped inside a paused turn」で残った。
* 止まる・止まらないの食い違い（`mid-turn interrupt`）と、再開後に交代の要る枠が食い違う場合も、diff_turn と同じく乖離として数える。続けられずに残ったものは `skipped` に `carried on, then …` として理由付きで出る（今回の 400 局では 0）。
* 表示: 1 行目の下に `stopped with Showdown at a mid-turn replacement N times; carried on and scored K turns: S silent, F flagged`。`skipped` から「stopped at a mid-turn replacement (no command to continue it)」が消える。
* diff_turn へは足しただけ: `PortPending.decided`（`_resume_port` が決めた終わりの局面の ours / theirs / unmodelled）と、それを作る `_decided`。diff_turn の出力は変わらない（IKA-218 の null 対照、master の出力とバイト一致）。
* **`--jobs N`**: 種（seed）を単位に process を分ける（種ごとにチームと選択の乱数が独立なので）。種 k は `k % jobs` 番目の process、集計は種の順に `Aggregate.merge` で足す。Counter と dict は最初に見た順を保つので、1 process で回したのと同じ報告になる。既定は 1。
