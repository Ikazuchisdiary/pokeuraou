## 方針（ユーザー 2026-11-26〜27）

* 既定は Rust の道にする。使われなくなった Python の道は、既定 off で残さず消す。
* 残すのは、M-C の裏を隠す生成とその対戦評価、人と打つ道具・検討。M-B と、裏を隠さない局（開いた局）は残さない。
* ビット一致は要求しない。Rust の道が弱くならないと確かめられたら on にしてよい。
* 学習（torch、`train_value.py`・`q_train.py`、符号化の配列の形）は Python に残す。

## 3. 段 3: 人と打つ道具・検討を Rust の道に切り替える

### 3.1 両立するかの調べ（読んだコードと確かめ）

| 論点 | 調べたこと | 結論 |
|---|---|---|
| `HELD` の前提 | `rust/src/beliefnode.rs` の `HELD`（fill の配列）は port の過程の、要求を読むスレッドの `thread_local`。`hold(clear=true)` は節の始めに全部を捨てる。同じ過程に 2 つのスレッドの節の要求が混ざると、片方の fill が消える | 混ざる形が人と打つ道具にあるかを調べた |
| 人と打つ道具の port の使い方 | `humanplay` は `rustnode.hold_positions` を呼ばない（生成だけ）。節の要求（`belief_payoffs`）は、読む本線のスレッドだけが module の過程へ出す。`deepen` の補助スレッドは `rustnode.own_node`（スレッドごとの別の port 過程）か、別の worker 過程で、節でなく `turn`・展開の要求だけを出す。ladder の worker は別の過程で、`beliefnode` を使わない（`grep` で確かめた）。`ponder-ask`・`person-select` のスレッドは人の選択を待つだけで port を読まない | 1 つの port 過程に 2 つのスレッドの節の要求が混ざる形は見つからなかった。ただし、コードを読んだ範囲 |
| `rustnode._HOLD`・`_HELD`（Python 側） | module 全域の dict（`id(pos)` が鍵）。生成だけが `hold_positions` で on にし、人と打つ道具は off なので、局面は毎回 JSON で渡る | 干渉しない。`own_node` は `_HOLD` が on だと拒む（人と打つ道具では off） |
