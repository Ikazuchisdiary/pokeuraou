# IKA-460 段 4: Python の探索と対局の道を退役させる

課題: https://app.notion.com/p/4244b8acaa6c810aab72e3b40e08fd71 （親 IKA-453）。
始点は origin/master の fe0b2d7。

## 方針（ユーザー 2026-11-26〜27）

* 既定は Rust の道にする。使われなくなった Python の道は、既定 off で残さず消す。
* 残すのは、M-C の裏を隠す生成とその対戦評価、人と打つ道具・検討。M-B と、裏を隠さない局（開いた局）は残さない。
* ビット一致は要求しない。Rust の道が弱くならないと確かめられたら on にしてよい。
* 学習（torch、`train_value.py`・`q_train.py`、符号化の配列の形）は Python に残す。

## 1. 棚卸し

### 1.1 `portlp` の段のフラグ

環境変数は `POKEURAOU_GEN_PORT_*`（LP だけ `POKEURAOU_LADDER_PORT_LP`・`..._SERVED`・`..._MENUS`）。
既定は module の値（すべて off、`GAME` だけ on）。生成と対戦評価のエントリ（`tools/selfplay.py --pool`、`tools/pool_match.py`）が `portlp.default_on_for_generation()` で段 3.6 まで on にする。人と打つ道具・検討・ライブラリ・テストは off のまま。

| フラグ | 段 | 守っている Python の道（前の道） | 読む場所 |
|---|---|---|---|
| `GEN` / `ON` (`LADDER_PORT_LP`) | 1 | `equilibrium.solve` で解く LP（Q の行列・ベイズ型・副ゲームの畳み） | `qrank.py`、`search.py`、`ladder.py`、`deepen.py` |
| `FOLD` | 1.2 | 副ゲームの畳みを Python（`fold.fold_value`、numpy の dot）で行う | `beliefnode._fold_in_port` |
| `STACK` | 1.3 | 補完の葉を Python が積む（`_stacked`・`_patched`・`_Patcher`） | `beliefnode.py` |
| `NODE` | 1.4 | `belief_payoffs` の補完ごとの積み・畳み（`_per_completion`） | `beliefnode.py`、`selfplay.py`（既定の入口） |
| `EXACT` | 2.1 | 裏のない節を Python の `search` で解く | `beliefnode.py`、`playgame.py` |
| `REPLACE` | 2.2 | 交代ノードを Python（`replacenode.solve`）が組む | `replacenode.py` |
| `MENUS` | 2.3 | 技の選択肢を Python（`rootmenus.menus`、`narrow`）が作る | `rootmenus.py` |
| `DECIDE` | 2.4 | 選択肢とノードを別の要求にする | `selfplay._decide`、`playgame.py` |
| `ADVANCE` | 3.1 | 1 手番の重み・引き・枝を Python が行う（`selfplay._advance_turn`） | `selfplay.py` |
| `HIDDEN` | 3.3 | 裏の完成形を Python（`hidden.completions`・`substitute`）が作る | `hiddenstep.py`、`selfplay.py` |
| `PREP` | 3.4・3.5 | 局の準備（引き・選出・`LazyPriors`）を Python が行う | `prepgame.py`、`poolplay.py` |
| `SELFSWITCH` | 3.2 | 自己交代のノードを Python（`_do_self_switch_node` など）が解く | `selfplay.py` |
| `PLAY` | 3.6a | 交代の局面（`_do_replacement_node`）を Python が回す | `replacephase.py`、`selfplay.py` |
| `GAME` | 3.6b | 1 手番ごとに要求を出す（既定 on の逆向きの切り替え） | `playgame.py` |

ほかに、`portserved`（`LADDER_PORT_SERVED`）と `portmenus`（`LADDER_PORT_MENUS`）の 2 つの module が、ladder（人と打つ道具・検討の深い読み）の推論サーバ経由の道を持つ。どちらも既定 off で、`ladder.py` のワーカーが message で受け取って設定する。

### 1.3 M-B と開いた局だけが使うもの（段 2 の対象の候補）

* `selfplay.generate`（M-B の自陣のロスタ対プール）、`search.ROSTER_RANK_FILL`、`tools/selfplay.py` の非 pool の道（`--hide-bench`・`--open-bench`、roster）。
* `play_game` の `sheets is None`（`open_information=True`）の枝と、`record.information = "open"` を作る所。
* `open_information` を渡す tools: `asymmetry.py`、`bench_generation.py`、`book_check.py`、`cycle_match.py`、`forced_handoff.py`、`generation_match.py`、`profile_generation.py`、`resume_generate.py`、`selection_check.py`、`width_match.py`、`worker_growth.py`、`oneshot/matchup.py`。`agent_drift.py` と `analyze.py` も触れる。
* `open_information` を渡す tests（12 ファイル）: `test_ally_targets`、`test_bench_default`、`test_deepen`、`test_encode_games_port`、`test_equal_wall_clock`、`test_final_position`、`test_hidden`、`test_luck`、`test_poolplay`、`test_record_both_sides`、`test_refs2_named`、`test_selfplay`。`generate` を呼ぶ `test_selection_book` もある。

### 1.4 いま確かめていないこと

* 上の「使い手」の列は、grep の import の有無と、記録の記述から付けた。1 関数ごとの呼び手は、消す段で grep して記録する。
* 研究用の tools（`tools/` の約 100 本）のうち、M-C の本番でも人でもないものの一覧は、段 2 で `play_game`・`generate`・`open_information` を使う分だけ決める。それ以外（例: 学習・集計だけの道具）は消さない。
