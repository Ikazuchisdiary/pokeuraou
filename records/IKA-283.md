# IKA-283: 重み 5% 未満の裏の決定化を落とす設定（bench_drop）を入れた —— 生成の葉が 45% 減って 1.14〜1.19 倍（CPU −16%）、メニューは変わらず、対戦評価では 163 対すべてで両席の打ち筋が同じ（SPRT H0）。既定は変えない

2026-09-25。担当 IKA-283（worker）。master 3277e40 から切った `ika-283-drop-light-completions`。

答えた問い: **裏を隠したノードで、ベイズの事前分布がほとんど重みを置かない裏の決定化（completion）を落として
正規化し直すと、M-C の生成はどれだけ速くなり、打ち筋と対戦評価の強さはどれだけ変わるか。**（IKA-279 §6 の案 C を実装して測った）

## 1. 入れたもの（既定の動きは変えていない）

* **腕ごとの設定 `bench_drop`**（`hidden.parse_bench_drop`・`hidden.drop_light`）
  * `none`: 何も落とさない（既定 `DEFAULT_BENCH_DROP`。今までと同じ）
  * `w<P>`: 重みが P% 未満の決定化を落とす（`w5`、`w10`、`w0.5` など）
  * `m<P>`: 重い順に足して質量が P% に届くまで残し、残りを落とす（`m95`、`m99` など）
  * どの規則でも **一番重い決定化は必ず残す**（等しい最大は列挙順の最初。メニューの順位付けが読む `_menus.views` の
    `max` と同じもの）。残りの順は列挙順のまま。重みは残ったものの和で割り直して和を 1 にする
  * 落とすものが無いときは **同じリストのオブジェクトを返す**。だから落とす決定化が無い局面では既定とビット一致
* **どこで効くか**: `play_game` が手番ごとに `completions` で両側の決定化を作った直後に、`selfplay._believed` が落とす。
  `spreads[s]`（側 s の裏）は側 1−s の信念なので、側 1−s の腕の規則で落とす。一つの dict で両腕を賄える
  （各側のゲーム・メニュー・ベイズ解は相手側のリストしか読まない）。この後の `_menus`（順位付け）と
  `belief_solve`（`belief_payoffs` の行列と `solve_bayesian`）の両方が同じ落とした後のリストを読むので、
  正規化は一貫する
  * 順位付け（`believed_ranking`）は一番重い決定化 1 つから作る（IKA-143）ので、それを必ず残す限り **メニューは
    変わらない**。これはテスト（`test_the_menu_ranks_from_the_same_completion`）と生成の実測（§3、9,159 手番で
    メニューの違い 0）で確かめた
  * 手番の move ノードだけ。交代（replacement）と自分交代（selfswitch）のノードは今のまま全部の決定化で解く
    （葉の 0.5%、IKA-279 §1）
* `GameRecord.bench_drop`、JSON の `benchDrop` は `none` 以外のときだけ書く（既定の局はバイト一致）。
  `provenance(bench_drops=…)` → `benchDrops`、`agent_name` に `/benchdrop:<ラベル>`（裏を隠す局だけ）。
  `LEGACY_BENCH_DROP = "none"` は provenance に置いた（IKA-268 の `rank_fill` と同じ形）
* 口: `poolplay.generate_pool(bench_drop=)`・`PoolArm.bench_drop`・`tools/selfplay.py --bench-drop`（プールの道だけ。
  名簿の道で既定以外を渡すと止まる）・`tools/pool_match.py --bench-drop/--baseline-bench-drop`（腕の行・席ごとの
  echo は `record.bench_drop`、つまり `play_game` が受けた値から数える）・`profile_stages` の echo に `--bench-drop`
* `tools/agent_drift.py` の `AGENT_ARGS` に `bench_drop`（既定が出荷なので省いても漂流にならない）。`--check` 通過
* 計器: `timing.count("completions.dropped")`（落としたときだけ数える。既定では呼ばれない）
* **記録の注意**: 落とすと `rankViews` の添字は落とした後のリストでの位置になる（種族は同じ）。既定では変わらない

## 2. テスト（`tests/test_bench_drop.py`、12 本）

* ラベル: `none`・`w5`・`w10`・`w0.5`・`m95` が読め、`w0`・`w100`・`m100`・`x5`・`W5` などは止まる
* 落とし方: `w5` で 0.02・0.9・0.05・0.03 → 0.9・0.05 が残り、重みは 0.9/0.95 など。`m95` は重い順に 0.6+0.3+0.06 まで。
  15 個が 1/15 ずつで `w10` なら最初の 1 つだけ（重み 1）。重み 0 の決定化はどの閾値でも落ちる
* **null**: 落とすものが無ければ同じリスト（`none`・閾値を越える重みだけ・`m99`・exact の 1 つ）。`_believed` は両腕
  `none` なら dict そのもの。側 0 の腕の規則は側 1 の決定化だけに効く
* **ベイズ解の一貫**（port を使う）: 決定化 6 つに重み 0.01/0.02/0.9/0.03/0.02/0.02 を置き、側ごとに `m90`・`w3` で
  落とした `belief_solve` が、落とさないノードの行列から残った決定化の行列を取り出して正規化した重みで
  `solve_bayesian` した答えと **ビット一致**（戦略・値・classes）。落とした後のノードは行列を 1・2 個しか作らない。
  対照: 全部の決定化で解くと値が違う（テストが空振りしていない）
* メニュー: 落としても落とさなくても `_menus` の両側のメニューと、読んだ決定化の種族が同じ
* 対戦評価の口: 腕の設定がどちらの席でも自分の側に付き、`benchDrop` は違うときだけ書かれる
* **落とすものが無い局は既定と同じ局**: 事前分布なし（6 決定化が 1/6 ずつ）で `w5` の局は `none` の局と
  `benchDrop`・`searchSeconds`・`engine` を除いて同じで、`belief_solve` が受けた決定化の数も同じ。
  陽性対照: `w20` では最初の手番から (1, 1) になる
* provenance: `none` なら何も書かず、違う側だけ名前に `/benchdrop:w5`。開いた局では名前を変えない
* **陽性対照（正規化を忘れる）**: `_assert_a_belief`（和が 1、残った重み = 元の重み / 残った質量）に、正規化しない
  落とし方を渡すと落ちる（`test_forgetting_to_renormalise_is_caught`）。さらに `hidden.drop_light` 自身の
  `item.weight / total` を `item.weight` に書き換えて回すと（`C:/tmp/ika283/mutate.py`、戻したことをバイトで確認）、
  12 本のうち 4 本が落ちる（`w5`・`m95`・最重だけ残る場合・ベイズ解の一貫。例: 「not renormalised, 0.93 == 1.0」）
