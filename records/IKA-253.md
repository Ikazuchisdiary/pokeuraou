# IKA-253: 学習した葉が決着した局面をネットで採点していたのを、hp-share と同じ 1/0（引き分け 0.5）に直した —— 生成の葉の 0.6% が決着局面で、1,200 局のうち 696 局で打つ手が変わる。対戦評価（直す前 対 直した後）は SPRT H0（101 対で 100 引き分け・1 対は直した側の勝ち）。速さは変わらない

2026-09-25。担当 IKA-253（worker）。master ffc07b7 から切った `worktree-agent-a09039e7c150dcaf1`（報告前に master e7c63ce の IKA-111 を取り込んだ）。

答えた問い:
1. **学習した葉の経路（ローカル・サーバ・port の encoded 葉・裏を隠すノード）で、決着した局面に結果（1/0/0.5）を置けているか。** 置けていなかったので直した
2. **直すと生成の局はどれだけ変わるか、遅くなるか。** 決着局面は葉の 0.6%。局は変わる（打つ手が全部同じ局は 504/1200）。速さは変わらない
3. **直すと弱くならないか（対戦評価、`--sprt 0 10`）。** 弱くならない（H0）

用語: 「裏」＝選出した 4 体のうち場に出ていない 2 体。「対戦評価」＝盤。「裏の決定化」＝完成形（completion）。

## 1. 原因

* hp-share・faints は `payoff._decided`（Python）と `rust/src/objective.rs` の `decided` で、`pos.ended` の局面を 1/0/0.5 にしている。
  学習した葉には、この置き換えが一つも無かった:
  * `BatchedValue.__call__`（局面を渡す道: `port._scored_here`、`search._subgame_value`、根の葉）
  * `BatchedValue.from_encoded`（port が符号化した葉: `port._encoded`、`beliefnode`、`selfplay` の自分交代）
  * `RemoteValue`（推論サーバ。生成と対戦評価の本番の道）
* `search._subgame_value` のコメント（「どの評価軸も決着後は正確に 1 か 0 を返す」）は、value の葉には当てはまっていなかった

## 2. 直したもの

* **`Encoded.decided`**（(B,) の float64。決着した行は 1.0/0.0/0.5、続行中は NaN）。ネットの入力ではない（特徴量は変えていない）
  * Python の符号化（`Encoder.encode_positions`）: `pos.ended` の行に `payoff._decided` の値を入れる。JSON の道（`encode`）も同じところを通る
  * port の符号化（`fill_encoded`・`alternativesEncoded`）: 見出しに `"decided": [[葉の番号, 値], …]`（決着した葉だけ）を足した
    （`objective::decided_leaves`）。`EncodedNode.unpack` がそれを `Encoded.decided` にする。見出しにこの鍵が無い古い exe では止まる
    （黙ってネットの値に戻らないように）
  * 裏を隠すノードの組み立て（`beliefnode._subset`・`_stacked`・`_patched`）、自分交代の行の切り出し（`selfplay._rows`）、
    サーバへ送る塊の切り出し（`inference._slice`）、`mirror`（1−値）・`slice` も `decided` を運ぶ。
    `_patched` は参照の行の `decided` をそのまま使う（裏の決定化で差し替えるのは見えていない裏の行だけで、見えていないポケモンが
    いる側はまだ負けていない。だから決着は参照の局面と同じ）
  * 学習データ（`load_dataset`・`encode_dataset`・サーバ側の `Encoded`）は `decided=None`（分からない、置き換えない）
* **`encode.settle(values, encoded, rules)`**: 順伝播の**後で**、決着した行の値を結果で上書きする。決着した行もバッチに残す
  （CUDA の答えは行数で変わるので、行を抜くと他の行の末尾の桁が動く）。だから続行中の葉の値はビット単位で前と同じ。
  `BatchedValue.__call__`・`from_encoded` と `RemoteValue.from_encoded`（サーバの返事を受けた側）が呼ぶ
* **計器**: `timing.count("leaves.ended")`、葉ごとの数え `BatchedValue.ended`・`RemoteValue.ended`
* **測るための口**（IKA-141 の `EncodingRules` と同じ形。生成や学習に使うものではない）:
  `EncodingRules(net_scores_ends=True)`（ラベル `old-ends`）は直す前の葉（決着局面もネットが採点する）。数えは同じにする。
  `tools/pool_match.py --net-scores-ends / --baseline-net-scores-ends`。腕ごとに符号化器を分け（同じ重みでも別の葉のオブジェクト）、
  タグ `@enc:old-ends`、ワーカーの echo に腕ごとの「ends by the net / as the result」と、葉が自分で数えた決着局面の数を出す
* `search._subgame_value` のコメントを直し、`tools/endgame_exact.with_ends_decided` に「学習した葉では今は何もしない（asis = fixed）」と書いた

## 7. 判断

* **入れる**。正しさの修正（hp-share・faints と同じ定義にそろえた）で、対戦評価で弱くならず（H0）、生成は遅くならない

  比較で、直す前と後の局を混ぜて読むときは注意
* 決着局面の大外れ（0.1 超）は決着局面の 1% 前後、1 局あたりにすると数個で、効くのは「倒しきれるか」の読み合いの局面。
  IKA-254 §4b の「17〜64 のメニューでは 1/0 の直しと深さ 2 が組で効く」は、この直しの上でしか成り立たない
