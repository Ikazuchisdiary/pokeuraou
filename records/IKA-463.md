# IKA-463 段 5: 残る Python の探索と play_game を撤去する

始点は origin/master の 3b07b74（2026-11-27）。

## 方針（ユーザー 2026-11-26〜27）

* 既定はすべて Rust にし、Python は撤去していく。多少の犠牲はよい。ビット一致は求めない。
* 人と打つ道具は CUDA と Rust の推論サーバが要る。1 手の予算は 30〜45 秒で、検討は長くてよい。
* 対戦評価は全コアで 30 秒の手を打たない。単一コアで 4 秒以下の点から外挿する。

## 1. 棚卸し: 人と打つ道具・検討が使う Python の探索

読んだ道具は `tools/play_human.py`・`tools/analyze.py`・`tools/time_match.py` と、それが読む `humanplay`・`analysis`・`timematch`・`selection_deep`・`ladder`・`deepen` である。`play_human.py` の既定の読みは次のとおり。

* 深掘り（`deepen` の m の読み）で読む。根の差し替えの oracle は `sall`、深さの上限は 16、壁時計で 1 手 45 秒、4 スレッドで読む。
* `--ladder` を名指ししたときだけ、梯子の読み（`ladder.read`）で読む。
* 選出は `selection_deep` で読む。既定の読みは `stage=L6@0,rects=8-11,confirm=2,shift=add` で、各セルを梯子の L6 で読む。

### 1.2 Python の LP を使う所

`equilibrium.solve`・`solve_bayesian`（scipy の HiGHS）は、次の所でだけ使う。生成と対戦評価は使わない。

* 開いた局面の深さ 1 のノード（`search.search`）
* 深掘りの再解き（`deepen`）
* 梯子の読み（`ladder`）と選出の深い読み（`selection_deep`）
* 交代の局面（`humanplay._replacement_mixture`）
* 選出の解き（`selection.solve_selection`）

## 2. 設計

### 2.1 段の分け方

| 段 | 中身 | 規模の見積もり | 局が変わるか |
|---|---|---|---|
| A | 深掘りを port の要求（`deepenMove`）にする。木・優先度・oracle と差し替え・子の候補集合・再解き・壁時計の予算・途中の答え（画面の `step`）を Rust で持つ | `deepen.py` 3,542 行と `narrow` の子の候補集合。Rust で数千行。何日かかかる | 変わる。同じ時間の対戦評価で判定する |
| B | 梯子の読みを port の要求にする（選出のセルと `--ladder`）| `ladder.py` 3,288 行。A と子の読みを共有できる | 変わる |
| C | 交代の局面を `replacementNode` にする。選出の葉の 1 回の解きを `selection.rs` の要求にする | 小さい。要求はある | 葉の採点と LP の足し順だけ変わる |
| D | 開いた局面の深さ 1 のノードを `moveNode` の開いた形にする | 中くらい | LP の足し順だけ変わる |
| E | 研究用の読みと knob を消す（`Agent` の `depth`・`restricted`・`depth2_auto`・`root_all`・`widen`・`knockouts`・`sub_limit`・`sub_branches`・`refine`・`passes`、`search` の深さ 2、`eq_select`）| 消すだけ | 既定の手は変わらない |

* A と B が終わるまで、`equilibrium`・`deepen`・`ladder`・`search` の本体は消せない。人と打つ道具と検討が使うからである。
* `play_game` と `playgame.py` は本番の呼び手が無い。テストを置き換えれば、A を待たずに消せる（段 3）。
* `play_game` だけが使う研究用の機能（`eq_select` の打ち方、line 1、Baton の保留、`force_mega`、ally targets）も、`play_game` と一緒に消せる。

### 2.2 この課題で行う順

1. `play_game`・`playgame.py` と、そのテストの撤去（段 3）。Rust のワーカーで確かめられることは、Rust のワーカーのテストに残す。
2. 呼び手の無くなった探索の撤去と、研究用の knob の撤去（E）。
3. C と D。
4. A と B は別の課題に分けるのがよいと考える。理由は規模で、どちらも Python で 3,000 行を超える。同じ時間の対戦評価も段ごとに要る。
