# IKA-442: 選出の値は対ごとの勝率を当てるか

2026-11-23 起票。枝 `claude/wonderful-feynman-cykckd`。課題: https://app.notion.com/p/4214b8acaa6c813da312f341315f8029 。

## 要点

判定は「0.9 以上」で、選出の値を構築の探索の第一段に使う。gen-6 の局（387,760 局、65 構築、2,080 対）で、構築の段の補正後の相関は 0.944 だった。gen-6 の局は value-mc5 で打ち、記録の選出の値も value-mc5 で解いた値なので、評価モデルが学んでいない局での数字である。

| 問い | 答え | 出どころ |
|---|---|---|
| 対ごとの平均の得点と選出の値の相関（補正後） | 0.915（補正前 0.886、得点の信頼度 0.938） | §4.1 |
| 構築ごとの強さの順位の一致（補正後の相関、上位 5・10 の一致） | 0.944、Spearman 0.930、上位 5 のうち 4・上位 10 のうち 9 | §4.1 |
| 選出の値の較正（傾き） | 全局で 0.912。両席が均衡の台の選出を選んだ局だけでは 0.992 | §4.3 |

* 傾きが 1 より小さい理由は、生成の選出の探索（ε 0.25）で説明できる。片方の席だけが台の外を選んだ局では、その席の得点が値より 0.128 低かった（§4.3）。
* 世代が進むほど当たりがよくなった。構築の段の補正後の相関は gen-0 で 0.280、gen-3 で 0.863、gen-6 で 0.944 だった（§4.2）。
* 同じ gen-6 の局を古い評価モデルの store で比べると、value-mc4bindaux x2 は 0.879 だった。value-mc6 x2 は 0.978 だったが、value-mc6 は gen-6 の局を学んでいるので、学んでいない局での数字ではない（§4.4）。

## 1. 何を測るか

強い構築を効率よく探す方法の第一歩として、安い見積もりが当たるかを確かめる。

* 構築の強さは、環境のプールに対する平均の得点と定める。
* 選出の値は、選出の 90×90 の均衡の値である（`selection.solve_selection`）。評価モデルが 1 ターン目の局面を見積もるだけで出る。
* 局の記録は、両席の構築（`pool.teams`）・席 0 の得点（`outcome`）・選出の値（`selectionValue`、席 0 の勝率）を持つ。新しい局を打たずに比べられる。

## 2. 判定の目安（測る前に決めた）

| 構築の段の補正後の相関 | 次にすること |
|---|---|
| 0.9 以上 | 選出の値を構築の探索の第一段に使う |
| 0.7〜0.9 | 第一段に使い、上位を本物の局で確かめる段を厚くする |
| 0.7 未満 | 選出の値では足りない。安い探索の局を第一段にする |

## 3. 道具

`tools/matchup_proxy.py`（テストは `tests/test_matchup_proxy.py`）。

```bash
uv run python tools/matchup_proxy.py extract --games-dir data/selfplay-mc6 --out <出力>/rows-mc6.npz --jobs 8
```

```bash
uv run python tools/matchup_proxy.py report --rows <出力>/rows-mc6.npz --out <出力>/report-mc6.json
```

* `extract` は、決着した局を 1 行ずつ抜く。同じ構築どうし（ミラー）・未決着・選出の値の無い局は数えて捨てる。
* `report` は、各局を対の向き（id の順で先の構築を行の席）に揃えて、対の段・局の段・構築の段を出す。
* `--store` を付けると、記録の値の代わりに選出の store（`<lo>-<hi>.json`）の値を使う。別の評価モデルで解いた store を同じ局で比べられる。

### 4.3 傾きと選出の探索

生成の選出は、均衡の混合に探索の混合を ε 0.25 で混ぜて引く。局の記録には、均衡の混合（`ownSelectionPolicy`・`foeSelectionPolicy`）と実際の選出（`ownPick`・`foePick`）が残る。gen-6 の局を、両席の選出が均衡の台（確率が正の選出）に入る局と、少なくとも片方が台の外を選んだ局に分け、対の段の傾きを別々に出した（`C:/tmp/ika442/explore_split.py`、選出の番号は value-mc5 の store の `selections` の順）。

| 局の組 | 局 | 対 | 傾き | 相関（補正前）| 得点 − 値の平均 |
|---|---|---|---|---|---|
| 全局 | 387,760 | 2,080 | 0.912 | 0.886 | −0.0007 |
| 両席が台の中 | 225,802 | 2,080 | **0.992** | 0.834 | −0.0016 |
| 少なくとも片方が台の外 | 161,958 | 2,080 | 0.803 | 0.848 | +0.0005 |
| 席 0 だけが台の外 | 69,858 | 2,080 | 0.826 | 0.767 | −0.1276 |
| 席 1 だけが台の外 | 70,510 | 2,080 | 0.825 | 0.771 | +0.1285 |

* 両席が台の中の局では傾きが 0.992 で、選出の値は較正されている。
* 台の外を選んだ席は、値より平均 0.128 低い得点を取った。両席の探索が同じ割合で起きるので、全局の平均のずれは −0.0007 に収まる。探索は対の得点を 0.5 の側に寄せるので、全局の傾きが 0.912 に下がる。
* 対の段・構築の段の相関を探索の無い局だけで出し直す手もある。ただ局が 58% に減って得点の揺れが増えるので、この課題では全局の数字で判定した。

* value-mc5 の store は、記録の値と小数 3 桁まで同じ数字を出した。store の経路が記録と同じ値を読むことの確認になる。
* 課題の起票では gen-6 の局を value-mc6 にとって未知の局としていたが、value-mc6 は gen-0〜6 の局で学んだ（保留は 15%）。value-mc6 の行は学んだ局での数字で、value-mc5 の行と同じ条件では比べられない。value-mc6 x2 の Brier 0.23259 が、もう半分の対の平均 0.23332 を下回るのも、学んだ局の得点を覚えた分を含む。
* value-mc4 の 3 本は gen-6 の局を学んでいない。それでも gen-6 の局は value-mc5 の探索で打っているので、value-mc5 の値は打ち手と同じ評価モデルの値になる。value-mc4 と value-mc5 の差 0.877 と 0.944 には、評価モデルの強さの差と、打ち手との一致の差の両方が入る。
* 学んでいない局で value-mc6 を確かめるには、value-mc6 が打つ gen-7 の局が要る。

### 4.5 判定

§2 の目安で、構築の段の補正後の相関 0.944 は「0.9 以上」に入る。選出の値を構築の探索の第一段に使う。gen-4・gen-5 も 0.927・0.933 で同じ区分に入るので、判定は世代を 1 つ替えても変わらない。

IKA-419（`tools/selection_diag.py`）は value-mc4 の選出の値を、学んでいない対戦評価の局 2.2 万局と比べ、構築ごとの Spearman +0.907 を得ていた。この課題の gen-6 の Spearman 0.930（value-mc5、学んでいない局）は、それと同じ向きで少し高い。

## 5. 確かめていないこと

* 生成の選出は均衡に探索を混ぜている（ε 0.25）。対の平均の得点は、標本の揺れが無くても均衡の値と一致しない。
* 評価モデルはプールの 390 体だけを学んでいる。プールの外の構築で当たるかは、この測りでは分からない。
* 強さは「ソルバが操る構築が、ソルバが操るプールに勝つ」ことである。人が使って強いかは別に確かめる。
