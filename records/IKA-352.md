## 2. 入れたもの

### 2.1 3 体以上の同速（`resolve::tie_permutations`）

2 体の同速だけを (そのまま, 入れ替え) の半分ずつに分け、3 体以上は決まった順のままだった（注記も無し）。群の大きさ k によらず k! の順を 1/k! ずつにした（`arrangements`、恒等の順が先、以下辞書順）。
2 体の群は今までと同じ順・同じ重み（`weight / 2.0`）で、バイト一致。Showdown はターンの途中の並べ直し（第 8 世代以降）で残りの同速を引き直すが、群の各順が等確率なことは変わらない。
読み筋の札（IKA-345 の `tie <先> <後>`）は、群の中のすべての 2 体の組に付ける。

### 2.2 同時に場に出る体の同速（先発・交代・途中交代の同時）

`runSwitch`（sim/battle-actions.ts）は場の全員を `speedSort(allActive)` で 1 回並べ（同速は `prng.shuffle`）、その順の小数の素早さを登場の処理の各ハンドラに与える。
port は (−素早さ, 側, 枠) で並べていたので、同速はいつも側 0 が先だった。

* `resolve::switch_in_orders`（新）: 同速の群の全順を作り、各順で登場の処理をコピーの上で走らせ（draw なし・記録なし）、最初の順と違う状態に行き着く順が 1 つでもあれば全順を返す。全部同じなら最初の順だけ（生成の乱数を無駄に使わない）。
* 交代・先発（`phase_command` の中の `phase_position`）: 順が複数なら **draw**（重み全部 1）。生成（rng あり）は Python がその rng で引く（今までの draw と同じ口）。rng の無い呼び出しは 1 つ目の順で注記 `switch-in speed tie (the first; not branched)`。
* 途中交代の同時（両側が同時に交代する再開）: 計算予算が同速を列挙するなら各順を 1/k! で分岐。
* 口は変えていない（phase_command の引数と戻り、presets と draw の約束はそのまま）。

### 2.3 探索でも分岐として読む（調整役の指示）

rng の無い呼び出し（探索の交代の行列、選出の解きの先発局面）は、今までの presets の口で draw の全選択肢をたどり、重み付きの平均を取る:

* `RustNode.replacement_branches` / `lead_branches` と `_phase_branches`（新）: presets を幅優先で全部たどる。draw の無い相は 1 回の問い合わせで、今までと同じ位置。
* `port.replacement_branches`・`port.lead_branches_many`（新）: 後者は今まで通り 1 回の往復でまとめて問い、注記 `… (the first; not branched)` の付いた局面だけ問い直す。
* `selfplay.replacement_matrix`（新、humanplay も使う）: セルは各結果の重み付き平均。draw の無い行列は今までと同じ値。
* 学習した評価モデルの道（IKA-350 の `replacementsEncoded`）: draw のあった組だけ結果ごとに 1 行を返し、ヘッダーの `branches`（行 → 組・重み）で平均する。draw が 1 つも無ければヘッダーは今まで通り。
* 選出の解き（`selection.analyse` の先発局面）: `selfplay.lead_branches_from_sets`（新）で、draw のある先発は各結果の平均。`positions_from_sets` は 1 つ目の結果で、今までと同じ。
* 副作用: draw はトレース（相手 2 体のどちらを写すか）にもあるので、探索のトレースも両方を読むようになった。
* 注: 生成の選出は先に解いた store を読むので、store を解き直すまでは今までの選出のまま（状態が変わる先発の同速は局の 0.2〜0.6%）。

### 2.4 ターン終わりの処理の同速（`resolve::residual_forks`）

`residual_order` が同速の範囲を返すようにし、計算予算が同速を列挙するなら、ターン終わりの処理を各順で走らせて、同じ状態に行き着いた順を 1 つにまとめる（最初の順の状態・記録を残す）。
全部同じなら今までと同じ 1 分岐（注記だけ消える）。列挙しない計算予算（`Budget.deterministic`）は今まで通り決まった順で注記する。

* 近似: Showdown は `fieldEvent('Residual')` の同速をハンドラの種類ごとに別々に引く（たべのこしの組とやけどの組は別の硬貨）。ここでは 1 つの順をターン終わり全体に使う。違いが出るのは、2 つの処理の順が両方効く時（同じターン終わりに 2 つの処理で両方ひんしになる、など）だけで、それは残した。

### 2.5 オラクル（sim-bridge）

`RandomnessPolicy.shuffle_script`（`shuffleScript`）: 各段の、同じ長さの群の shuffle に順を与える（`[2, 0, 1]`: 最後の体が先）。`keep` / `reverse` では 3 体の群の 6 順に届かないため。

## 7. 残したもの・別課題の候補

* **ほかの同速の注記**: `redirection speed tie`（このゆび・ひらいしんの同速、`moves.rs` の `by_speed_noting`）と `item speed tie`（持ち物の処理の順）は、今も決まった順で注記するだけ。記録の局での頻度は数えていない
* **ターンの途中で生まれる同速**: 並べ直し（第 8 世代以降）で途中から同速になった行動は、Showdown は引き直すが port は並べ直しの決まった順のまま（ターンの始めに同速だった群だけを分岐にしている）
* **ターン終わりの同速の近似**: 1 つの順をターン終わり全体に使う（§2.4）。Showdown は処理の種類ごとに別々に引く
* **選出の store**: 先発の同速を平均にした選出の解きは、store を解き直すまで生成に入らない
* **ミラーの側 0 の得点の記録**: mc1 の 52.44% は同じ設定の 2,400 局で 49.67% に戻った。これより大きな偏りを探すなら、ミラーだけの生成（§5 (a) の差し替え）は 2,400 局 2.5 分で回る
