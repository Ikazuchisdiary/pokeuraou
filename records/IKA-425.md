|---|---|---|
| r ≦ 0.7（幅 2 の 1 本） | 速くなるか同じ | §5.1。ただし本数が減るので 2 本平均の分散減（保留局の損失で 0.0018、IKA-415）を失う |
| r = 1.1〜1.3（幅 4 の 1 本のグラフ 64 行、幅 2 の 2 本のグラフ 64 行） | 数 % の低下で済む見込み | 生成の GPU 使用率が約 50%。IKA-390 のサーバ 1 つの窓口の稼働率は 71%（開いた局面）。待ちは ρ/(1−ρ) で伸びる |
| r = 1.4〜2.2 | 目に見える低下の見込み。eager の道（裏あり）の費用が先に響く | 同上。裏ありは eager の道が壁時計の 45% を占める |
| r ≧ 2.7（幅 4 の 2 本） | GPU が飽和し、生成と対戦評価が遅くなる | 使用率 50% の約 2 倍 |

* 推論時間を倍にすると、探索全体が倍になるわけではない。推論待ちはワーカー容量の 33〜45% で、その中の GPU の計算は一部。数字は上限の目安。
* 探索全体での実測は無い。実際の遅れは ABBA の生成窓か同じ実時間の対戦評価でしか言えない（段 3 の手順）。
* **構造を変えると Q も作り直しになる。** `qhead.py` の `QNet` は胴体を `build(encoder, ValueConfig())`（既定の設定）で組み、`load_trunk` で評価モデルの重みを写す。幅・層・注意・数値列の数を変える案は、この既定の設定も直さないと Q の学習が形違いで止まる。Q はもともと世代ごとに作り直す（約 2.3 時間、IKA-409 §8）。

## 8. 確かめていないこと

* §5.3 の探索全体への影響は推定で、実測は無い。
* §7 の「期待する改善」は私の推定で、学習していない。
* 候補 4 の「手番 3〜8 に集まる」は測っていない。
