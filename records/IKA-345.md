## 1. 入れたもの

### 1.1 port: 分岐ごとの偶然の札（`EventLog::chance`）

* 出来事の記録（IKA-215 の `events`、頼んだ時だけ）に、**偶然の札**の列 `chance` を足した。札は `<種類> <使った体> <技> <対象> [<引数>]`（例 `crit p1a flareblitz p2b`、`roll p1a flareblitz p2b 0 3 2`）。
  付けるのは、その引きに結果が 2 つ以上ある時だけ（確率 0 と 1 の引きには付けない）。種類と場所:
  ```
    hit / miss        命中の引き（単体・全体の技、変化技、複数回の技の 2 発目以降の外れ（引数に何発目か））   moves.rs
    crit / nocrit     急所の引き                                                                          moves.rs
    roll              乱数（引数: 残した乱数の何番目・残した数・Showdown の 16 段のどれか）                  moves.rs
    hits              複数回の技の回数                                                                   moves.rs
    sec / nosec       追加効果の発動・不発（引数: 状態異常・揮発状態・boosts）                              moves.rs spread_secondaries
    stopped / acted   まひ・こんらん等で動けたか（引数: 理由）                                              moves.rs can_act の後
    protect           まもるの連続の成否（ok / fail）                                                    moves.rs do_protect
    tie               同速の順（先の体・後の体）                                                          resolve.rs tie_permutations の後
  ```
* 引きの両側に札を付ける（`crit` と `nocrit`、`hit` と `miss`）ので、同じターンの 2 つの分岐は、引きが違う所で必ず札が違う。
* **まとめた分岐**: port は同じ局面に行き着いた分岐を 1 つにまとめる。`events` は最初の分岐の文を残す（IKA-215 のまま）が、`chance` は**まとめた分岐すべてに共通の札だけ**を残す（`EventLog::common_chance`）。
  急所でもそうでなくても相手がひんしなら、急所の札は消える。乱数の札だけは消さずに幅にする（`roll … 0-2 16 0-2`: 0〜2 段の乱数が同じ結果になった）。
* **生成の道は変えない**: 札は `log_event!` と同じく、記録を頼んでいない（`log` が None の）ターンでは書式を作らず、何も持たない（`chance_tag!` は `log.is_some()` の比較 1 回）。
  まとめる所の `merge_logs` も `Option` の比較だけ。§3 で生成の局がバイト一致することを確かめた。
* JSON の口: 分岐の `chance`（`log_json`・`with_log`）。一時停止の記録（`log_from`）は `chance` が無ければ空で読む（前の記録も読める）。
  Python: `rustnode.PortBranch.chance`、`port.turn(..., events=True)`（足した引数。既定は今まで通り）。

### 1.2 読み（`progress.Reader`）

* **札を名前に**: 深化で開いた組（セル）の分岐を画面に出す時、Reader がそのセルのターンを port にもう一度頼む（`events=True`、深化が使った計算予算そのもの = `deepen.Step.turn`）。
  答えを深化と同じ並べ方（確率の大きい順、残した数まで）で並べ、分岐の局面が 1 つずつ一致した時だけ札を使う（合わなければ札なしで、結果だけ出す）。セルごとに 1 回だけ頼み、木の分岐の列（リスト）の id で覚える。
  頼むのは画面に出る組だけ（根の 4 組、その下は 2 組ずつ、6 段まで）。探索の道からは呼ばれず、見ているだけの局はバイト一致（`test_a_listener_changes_no_game…`、数えの時計）。
* `Reader.causes`: 兄弟の分岐の間で**違う引きだけ**を名前にする（全部の分岐が同じに引いた引きは区別にならないので出さない）。珍しい側（外れ・急所・追加効果・動けず・まもる失敗・同速・乱数の上下）は `Cause`、
  普通の側（命中・急所なし・追加効果なし・行動・まもる成功・乱数の中）は `Cause(plain=True)`。頭の語は 急所 / 急所なし / 命中 / 乱数幅 / 追加効果 / 追加効果なし / 同速 / 行動できず / 行動 / まもる / 回数。
  乱数幅は 16 段を 下（0〜4）・中（5〜10）・上（11〜15）の 3 つで言い、何〜何 % は `title` に置く。技が 2 体以上に当たっていれば「→ 対象」を付ける。
* `Reader.changes`: 分岐が各側（AI の側が先）に何をしたか（`Change`: 名前・sprite id・HP% の前後・登場・ひんし・新しい状態異常）。前の `describe` の文（`what`）も残した。
* `Reader.field`: 分岐の先のノードの各側の場の体（`NodeMon`: 名前・sprite id・HP%・ひんし・この分岐で登場）。
* **手のラベル**: `progress.Label`（`str` の子）。文は今まで通り（枠ごとの部分を ` ／ ` でつないだもの）で、`parts` に `(枠の番号, 部分)`、`rich` に `progress.Part`
  （枠・文・技の名前・対象の側（0/1、無ければ −1）・対象の名前と sprite id・メガシンカするか）を持つ。`action_label`・`slot_part` がこれを作る。
  `humanplay` のターンの出来事に `agentParts`・`personParts`（`part_json` の 7 要素の配列）を足し（`agentSlots` は部分の文の配列のまま）、人への問い（`prompt`）の `slots` の各手にも 3 つ目の要素として同じ配列を足した。

### 1.4 画面（デザイン担当の案。§4）

* 分岐の見出し = 重み ＋ 原因の札の列（紫＝珍しい側、灰＝普通の側を 1 つにまとめて頭の語だけ）＋ 側ごとの結果の行（xs のアイコン＋登場・±HP%・状態異常・ひんし）＋ 値と親との差。
  「偶然」の語は見出しから外した。分岐が 1 つなら重みは地の色で「分岐なし」。決着の分岐も原因の札の後ろに「決着」。両側とも変化が無ければ 1 行の「変化なし」。
* 下の段のノード: 場の帯（各側の 2 体の xs アイコン＋細い HP の帯、この分岐で登場した体は紫の輪、ひんしは薄く、HP% はアイコンの title、最後の行に「次のターン 値」）、その下に各側の上位の手（体ごとのアイコン、手ごとに右端に確率）、下の段の組にも体ごとのアイコン。
* 手のラベル: 体ごとの配列をそのまま使い、各部分に使い手のアイコン。読み筋の中は「技」「→ 対象」「+ メガ」の塊の境目だけで折る。動けない枠の「行動なし」は薄く。経過の欄のターンの手にもアイコン。
* 技の対象: 名前でなく対象の xs のアイコンで出し、アイコンの縁（ライト 2 px・ダーク 1.5 px）と → をその体の側の色（AI 橙・あなた青）にする。title は「ゴリランダー（AI の側）」。
  画像が読めない時の名前の札は頭の 2 字（ガオガエンとガブリアスを分けるため）。全体技・場の技・交代・空きの枠は文字のまま。
* メガシンカ: 「+ メガ」の文字をやめ、使い手のアイコンの右下に印（CSS で描いた虹の輪、直径 10 px、title・aria-label「メガシンカ」）を重ねる。画面の資産にメガの絵は無く、外からは取っていない。本物のキーストーンの絵にするか、その出どころは、ユーザーの判断を待つ。
  適用した場所: AI の混合戦略・AI が読むあなたの手・読み筋（根・下の段・上位の手）・経過・あなたの手の入力の下の要約（入力のボタンは文字のまま）。
* 交代: 「交代 → 体」の文字をやめ、交代の印（⇄）＋ 出てくる体の xs のアイコン。title・aria-label は「交代: ＜体＞」。画像が出ない時は頭 2 字。途中交代・強制交代の問いの手も同じ（入力の下の要約）。
* あなたの手の入力: 技の選択肢を 1 つずつにし（「+ メガ」の付いた 2 つ目を並べない）、メガシンカできる体の段の見出しにメガシンカの切り替え（虹の輪の印つき）を置く。技を選んだ後でも切り替えられる。
  メガシンカは 1 対戦に 1 回なので、片方の体に入れるともう片方は押せない。送る直前に「技 × 切り替え」を問いの選択肢の 1 つに戻し（`web/choice.js` の `resolve`）、選択肢に無い組は送れない（要約に「この手ではメガシンカできない」）。要約ではメガシンカする体のアイコンに印。
* 検討モードのターンの選択: プルダウンの両脇に「◀」（1 ターン戻る）「▶」（1 ターン進める）。端のターンでは押せない。キーボードの ← → も同じ（入力欄・選択欄にフォーカスがある時は効かない）。押すとそのターンの局面で読み直す（プルダウンで選んだ時と同じ。読んでいる途中なら今の読みを止めて読み直す）。
* 数えの時計: 帯は `spent / budget`（計算予算を使った割合）、文字は「計算予算 62%」を主に、秒は薄く後ろに。100% を超えたら帯は満杯で警告の色。壁時計は今まで通り「4.4 / 5.0 秒」。
* 差が丸めて 0 の時は「±0.000」を薄く（色を付けない）。状態異常の札の地色を、白い文字との対比 4.5:1 以上に暗くした（場の札も同じ）。
  裏の決定化の札は、決定化が 2 通り以上で名前がある時だけ。PV の読んだ・葉の値・読めないの札のクラス名を `r-deep` などにした（`leaf` が `.pv .leaf` の字下げを拾って「葉の値」の前が空いていた）。
* 375 px: 読み筋の字下げを 6+8 px、重みの欄を 3em にした。確かめた画面ではどれも読み筋・ページとも横スクロール 0（`scrollWidth − clientWidth` を測った）。

## 4. デザインの決め（デザイン担当の文）

デザイン担当の文（3 往復のあと「デザインとして可」。そのまま入れた）:

画面の原則は IKA-332 のまま（主役は場と形勢、数は一段奥、側は色で分ける: AI 橙・あなた青・分岐 紫）。変更前・各回の画像は C:/tmp/ika345/shots/（before-*、r1-*、r2-*、r3-*、r4-*）、見本は C:/tmp/ika345/design/pv-proposal.html。

- **分岐の見出し**: 重み ＋ 原因の札 ＋ 側ごとの結果 ＋ 値と差。「偶然」の語は外した。
  - 原因の札は、兄弟の分岐の間で違う原因だけを出す。頭の語は 急所／急所なし／命中／乱数幅／追加効果／追加効果なし／同速／行動できず／行動／まもる／回数（用語集の見出しは 分岐・急所・命中・乱数幅・同速、残りはゲームの語）。珍しい側（急所・外れ・発動・失敗）は紫の札に技と対象、普通の側は灰の札 1 つに頭の語だけを並べ、詳細は title。
  - 乱数幅は 下／中／上（中は灰）。16 段のどれか・何〜何% は title に置く。
  - 決着の分岐は原因の札の後ろに「決着」の札（太字、地 --surface-2）。
  - 分岐が 1 つだけ（100%）なら重みは地の色、札は灰の「分岐なし」。
  - 結果は AI の行（橙の縦線）とあなたの行（青の縦線）に分け、体ごとに xs のアイコン＋登場・HP の増減・状態異常（場の札と同じ .st）・ひんし。片側だけ変化が無ければその側は「変化なし」（--faint）、両側とも無ければ縦線なしの 1 行。体の名前と HP% はアイコンの title。

### 4.1 同速を分岐として読んでいない所（調べた結果。直していない: 局が変わるので別課題）

人と打つ・検討・読み筋の経路（`humanplay`・`analysis` は行列も深化の子のゲームも `Budget.matrix()`、選択的延長も同じ計算予算、候補集合の順位付けの `-fast` は `Budget.fast()`、局を進める解決は `Budget.exact()`）は、どれも `enumerate_speed_ties=True`（Python の `Budget` の既定、`fast` も既定のまま）で、ターンの行動順の 2 体の同速は分岐になる。分けていない所は次の 3 つ:

1. **交代・先発の場に出る順（port の `phase_command`、`commands.rs`）**: ひんしの後の交代と先発の登場を `deterministic()`（`enumerate_speed_ties=false`・`pinned_policy=true`）で解き、素早さの同じ体は `(−素早さ, 側, 枠)` の順（側 0 が先）に並べる（`placed.sort_by_key`）。
   Showdown は同速を無作為に並べるので、先発の特性（いかく・天候・場）が同速で競る時（例: ミラーの先発の天候）に、いつも側 0 の後に側 1 が出て、後から出た方の天候が残る。分岐にも注記にもならない
2. **3 体以上の同速のまとまり**（`tie_permutations`）: 2 体の同速だけを分け、3 体以上は決まった順のまま（ダブルでは 4 体の同速がまれにある）
3. **ターンの終わりの処理（residual）の同速**: IKA-190 のとおり、並べ替えの同速は注記（unmodelled）にして分けない

`Budget.deterministic`（同速を分けない）は、Python では Showdown との照合（オラクルのテスト）だけが使い、探索・人と打つ・検討の経路は使っていない。
